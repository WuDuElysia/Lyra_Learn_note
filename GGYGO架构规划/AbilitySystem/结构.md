## Current 与 Base 数值接口

`UGGYGOAbilitySystemComponent::TryCalculateNumericAttributeBaseForCurrentValue(ExpectedAttributeSet, Attribute, ExpectedCurrent, DesiredCurrent)`提供通用的原生聚合逆算接缝。输入是原AttributeSet、原属性、实际预期Current和目标Current；仅游戏线程、权威端、实际注册的`FGameplayAttributeData`属性可用，不以Avatar Ready作为持久属性前置。

ASC使用GAS原生capture、资格规则与通道求值；权威资格参数与原生属性dirty求值一致，保留自定义资格的实际结果。原AttributeSet／ASC／Owner、Base、ExpectedCurrent及修饰项来源须仍匹配；快照和临时原生通道只存活于本次调用，不外泄或长期缓存。ASC不写属性、不选择生命/韧性边界、不维护第二聚合公式。

| 返回值 | 作用与调用边界 |
| --- | --- |
| `Ready` / `None` | `CalculatedBase`有限且候选正向求值匹配DesiredCurrent；调用方须立即经原GAS写入，并核实自己的Post结果。 |
| `Rejected` / 明确Reason | 输入、来源、捕获或数值依赖无效；有效Override、原生拒绝的倍率、零Compound/Gain、非法Divisor、非有限值或正向不匹配均明确拒绝，不采用原生float逆算回落。 |
| `Stale` / `SourceChanged`或`AggregationChanged` | 原宿主、当前值、Base或聚合资格／修饰项已改变；返回值不授权写入，不保留候选等待重试。 |

HealthSet持有业务目标及本次ExpectedAttributeChange来源。Health/Poise的有限Base是内部聚合输入，可低于0或高于Max；实际Current仍受0～Max及原MinimumHealth规则约束，Max属性保留自身边界。Buff移除引起Current归零仍进入原死亡流程。客户端Max依赖投影保留原Base并通过GAS重新求值，不消费权威逆算接口。

调用方接口见[[Messages/结构#HealthSet 的 Current 结算|Current结算]]及[[Messages/结构#客户端上限的 NetReceive 投影|客户端依赖投影]]；实际计算与提交分支见[[GGYGO_流程_AbilitySystem.canvas|数值流程]]。

## 精确Montage播放归属

UE的Local／Rep／GA字段和Animation的Guard仍分别是原权威。ASC持有的唯一`MontagePlaybackProvenance`仅认证一次完整原生Local写入：不透明Handle的私有不可变Proof记录原ASC、GA／Spec／PredictionKey、Montage及Guard生命周期／非复用CallId／CreatedInstanceId；ASC当前资源持有原ActorInfo allocation与实际来源快照。8位Local PlayInstanceId仅核对一致性，不作唯一播放身份。

| 调用方 → 实际接口 | 输入、作用与输出／边界 |
| --- | --- |
| Task::Activate → `TryPlayMontageWithOwnership(Ability, ActivationInfo, Montage, PlayRate, StartSection, StartTimeSeconds, IsOriginalCallerCurrent)` | 必需同步纯原调用方查询。复用完整限定Super／GuardScope，Scope封存并退出后，Accepted且原源／GA／Local一致才返回Succeeded及新Playback；失败保留Guard／Duration历史，无有效Handle，非Guard不走播放兜底。Task已消费单一栈Result；失败诊断并结束自身，不猜实例或改用旧Play。 |
| 原资源持有者 → `CheckMontagePlaybackOwnership(Original) const` | 纯核对原Proof／当前provenance、ActorInfo来源、GA激活来源、Guard生命周期及实际Local／GA字段；不依赖Montage仍活动或GA IsActive，停止不会凭空抹去原清理资格。无活动实例不是“可以清任意新播放”。 |
| GA 原终止捕获 → `CaptureMontagePlaybackOwnership(OriginalAbility, OriginalSpecHandle, OriginalActivationInfo) const` | 首次终止只取该原GA的既有认证播放。NoOwnedPlayback是正常无认证播放，其他失败明确拒绝，不签Handle或接管Task停止。Combo/Boss持有各自的原Task及Context清理资源。 |
| 混出／原GA收尾 → `TryClearMontageAnimatingAbility(Original)` | 先Check原Handle；成功仅限定基类GA setter写CurrentMontage=null并清Local AnimatingAbility，再退休原证明。避免virtual业务setter重入后误清后继；不Stop、不延迟到技能结束，调用时机仍归原消费者。 |

同GA同Montage接续A→B时，B证明替换A；B停止后仍只允许B的原清空，A晚回调不能借相同资产认领B。完整原生Init（含同端点）实际重置Local，写入前退休；Clear同理。Refresh前后仅按真实来源核对，无Local／来源改变则保持播放证明，不用发布Context修订强制延期。原生复制、模拟、动态Montage及旧Clear在实际可截获入口核对／退休；拒绝、无写入失败或Superseded外层不凭空清除已接受后继。

ASC只持一份当前MontagePlaybackProvenance；替换、真实ActorInfo写入、精确Clear及OnUnregister负责退休。Playback Handle不强持ActorInfo，不维持播放状态；限定基类绕行不在项目接口的认证范围内。

依赖为ASC→[[Animation/结构|Animation Guard]]，无反向GAS依赖；结构和关键调用见 [[GGYGO_结构_AbilitySystem.canvas|结构图]]、[[GGYGO_流程_AbilitySystem.canvas|精确播放支线]]。设计说明见 [[AbilitySystem/计划_AbilitySystem#当前精确Montage增量（K3）|设计说明]]。

## Task原实例与资源消费

`Activate`捕原ActorInfo allocation与Ability／ASC／Owner／Avatar／Mesh／Anim来源，固定 Montage 的真实唯一 Slot，先向原 Guard `AcquireActionPoseContract`。ExplicitNotRequired 明确走普通模式；RequiredReady 保存原不透明 Ticket 并启用引擎 Task Tick；拒绝/不可用或不一致的必需 Ticket 先失败，不播放。资格保持后才注册自身 Cancel/Event 并调用 ASC `TryPlayMontageWithOwnership`。ASC／Guard各自认证原生写入与实例；Task不维护第二播放身份、进度或帧调度。

| Task接口／资源 | 输入、作用、输出及清理责任 |
| --- | --- |
| `FNativeCallbacks` → `RegisterNativeCallbacks(Callbacks)`／`UnregisterNativeCallbacks(Token)` | 包含Completed、BlendOut、Interrupted、Cancelled、EventReceived五个原native单播，另有SectionReceived、NotifyReceived和OnFailed typed单播；原五个Tag/Data及BP签名保持。只在原native AwaitingActivation、Ready前接受非空且无既有注册的包；空包/重复/迟到明确拒绝并诊断，不替换原包。返回FDelegateHandle，解除只匹配原token，先脱包再释放；捕获构造/析构重入后不覆盖后继注册。调用方按值捕原Activation、弱GA/弱原Task；Task只持订阅资源，不签GA身份或授Ready/后继结束权。 |
| private `DispatchOriginalCallback` | 复制载荷并共享不可变原包快照→native执行→释放快照且捕获析构返回→重取弱原Task，核弱Ability/ASC及本路径资格→既有BP。Event核IsNotifyValid；BlendOut/Interrupted/Completed核原Guard、ActorInfo及Task资格，Completed不Check当前ASC归属或活动实例。Cancelled允许尚未安装ActorInfo/Guard的启动失败，仍核同原Task及ShouldBroadcast。无native注册时普通BP保持；BP外调返回后的旧收尾只重取弱原Task，不写后继。 |
| `PlayMontageAndWaitForEvent`／`ResolvePlayRate` | BP工厂／委托与速率语义保持；TaskRate只含一次全局缩放，EffectiveRate再乘Montage RateScale。窗口／组合仍归Montage和GA。 |
| `Activate` → 原Result | 成功且原Task／Ability／ActorInfo有效才保存Handle／Guard，按CreatedInstanceId重取原实例，直接绑定带原Guard载荷的委托，获取自身缩放lease。最后`SetWaitingOnAvatar`外调后无成员写。 |
| `TryGetOriginalSectionSnapshot(OutSnapshot)`／`SectionReceived(Fact)` | 只读确切原实例的 Montage/InstanceID/Section/Position/InstancePlayRate；Section Fact 含原 Montage/ID/Section/bLooped，由实例回调交付，不累加 dt 或模拟 Main/End。普通通知继续核原 Task/Guard/上下文；GA 另核原激活/段/资源。 |
| `AcquireActionPoseContract` → Ticket／`TickTask` → `PollActionPoseContract` | Animation 唯一声明和执行姿态契约，Task只持原 Ticket。RequiredReady 要求有效 Ticket/真实 Slot 与失败消费者；Ready 返回后引擎 GameplayTasks 才 Tick，GA 此时已固定实例 ID。Poll 前后核原上下文；Valid 继续，Failed/Invalidated 终止，不重领 Ticket。弱来源丢失不能因 IsValid=false 静默跳过。ExplicitNotRequired 不启 Tick。 |
| `FGGYGOMontageTaskFailureFact`／`OnFailed` | 固定 Montage、真实 Slot、Startup/Playback、原 InstanceID 和 Diagnostic；Startup 为 INDEX_NONE，Playback 为已签原 ID。只请求一次失败：关普通事实入口→精确 Stop 原实例/释放缩放→EndTask 退自身资源→native 历史 OnFailed。它不是 Cancelled、Completed 或后继工作许可。native EndTask 已清 Task.Ability 并正常垃圾标记；历史发送者用捕获的弱 Task.Get(true) 且拒绝销毁标志，GA 另核自己的 Original/段/强 Task/资源身份，不用已失效的 live-Task/Guard 工作资格。 |
| private `FInFlightMontagePlayCleanup` | 只是一份与调用栈共持的原停止义务；原生外调中Cancel／Destroy先记录，返回后凭Result.Guard清原实例。已结束Task不安装资源；不是播放状态、进度或GA生命周期权威。 |
| `IsNotifyValid` → EventReceived | 原ActorInfo及Task有效、未混出、精确实例播放且ASC Check原Handle成功才接事件；Montage／instance ID过滤保持。复制Payload后广播，监听随自身销毁清理。 |
| `OnMontageBlendingOutForInstance` | 匹配原Guard → 释放自身缩放 → `TryClearMontageAnimatingAbility(OriginalPlayback)`。A晚回调不能清B；保留原混出清空时机，不Stop／延期。有效原上下文才发布原BlendOut／Interrupted事实。 |
| `OnMontageEndedForInstance` → OnCompleted | 原Guard委托身份／生命周期、原ActorInfo及AbilityTask资格成立且非Interrupted，发布原自然结束事实。**不Check当前ASC播放，不要求原实例仍活动或存在**，正常混出已退休归属不会吞Completed。调用方须另证原GA生命周期，不能据此End后继。 |
| `ExternalCancel`／`OnAbilityCancelled`／`FailAndEndTask`／`OnDestroy` | 三取消入口在回调前标记bCancellationRequested，native/BP各至多一次；启动失败不硬核尚未建立的ActorInfo/Guard。OnDestroy先关闭Task、脱native包/token，向原ActivatedAnimInstance精确RemoveDynamic自身NotifyBegin函数，再撤自身Event/Cancel句柄及精确实例委托、释放原Character/token缩放；旧cleanup及Super返回后释放脱出的包，捕获析构后无Task访问。按明确Stop策略处理原实例，栈仍共持在途停止义务；普通EndTask不擅自改成AbilityEnded。 |

停止按原Guard生命周期＋CreatedInstanceId重取。只有ASC认证原Handle且资产当前活动实例正是原ID，才用`CurrentMontageStop`保留GAS复制更新；否则仅释放有效的**精确原本地实例**，不Clear新GA／ASC、不换Avatar找资源。Guard失效明确诊断，不猜后继；原实例已释放无需替代清理。外调返回时Task仍活但原ActorInfo失效，同样诊断并清原实例。

Combo/Boss持有Ready前注册的FNativeCallbacks与精确token，闭包固定Original、原Task和自身资源。Task只拥有自身播放、监听、缩放与Ticket；依赖ASC及[[Animation/结构|Guard]]，不持第二份能力或播放状态。

必需姿态失败与普通取消分开：普通 `FailAndEndTask`/取消入口保持 Cancelled 语义；Required 失败由独立 typed `OnFailed` 发布清理后的历史。Task在同次分发暂时观察原 GA 的真实 End，native 消费者若终止原激活（包括同 UObject 再激活），不再向旧 BP 广播；原 GA 未结束且资格仍成立才发 BP OnFailed。因此 native 消费者结束原 GA 时，BP OnFailed 不保证交付。原 Tick 标志保留到引擎正常注销，OnDestroy 重置 Ticket/脱包/自身句柄，不能提前清标志而漏掉 native Tick 登记退休。Animation 节点/epoch/worker 求值见 [[Animation/动作姿态修正|姿态能力契约]]；GA Main/End资源接口见 [[计划_玩家普攻连段]]。

### 原生 Montage 作者信号

原生单点 `UAnimNotify_PlayMontageNotify` 在原 Montage 的作者位置调用原 AnimInstance 的 `OnPlayMontageNotifyBegin`。Task 使用独立 `NotifyReceived`，不把作者信号编码为 GameplayEvent 的 float Magnitude。普通 `EventReceived` 仍遵守 `IsNotifyValid` 的播放、混出与 ASC 归属校验；该通路没有扩大为打断许可来源。

## 原请求终止

真实入口为受控Try→保存Original→RequestEnd/Cancel。GA唯一持首次原终止记录，ASC只持指向该记录的实际Try退出依赖与原Ended见证；GAS仍拥有Active/spec/count/tasks和执行。Process、OnSpawn、Boss BT已接受控入口，Combo/Boss/Admission已接Initialize/Body/Context Cleanup。

| 接口/步骤 | 输入、输出与停止条件 |
| --- | --- |
| `TryActivateAbilityWithTerminationBoundary(Handle, bAllowRemoteActivation)` | 一次native Try及完整尾部；返回Outcome/Reason、bNativeAccepted、OriginalActivation与可能同步完成的OriginalTerminationCompleted。Accepted不等于本地Active/Commit；remote-only可无本地原身份。 |
| `CaptureCurrentActivation() const` | 按 ResourceWork 核原完整 Context／LastActorInfoWrite 与完整实际来源；Busy／失配返回空，不签或续签原身份。raw原身份也不证明其具备受控Try外层返回见证。 |
| `RequestAbilityEnd(Original, ReplicateEnd, WasCancelled)` / `RequestAbilityCancel(Original, ReplicateCancel)` | 核原身份/可结束性，首次固定种类、参数与camera/Montage资源；Cancel另核可取消性，End不借取消资格。重复请求不重捕获或改参数。ScopeLock仅一次native continuation，无第二队列或无限重排。 |
| final End/Cancel → `CleanupAbilityResourcesForTermination(Context)` | 一次Cleanup后一次native End；默认清原camera，派生脱自己的原Task/token/Window/World timer/Mesh/prerequisite，Boss另持CMC原句柄。外调后重核原来源；Task仍执行自身原资源清理。 |
| 原Ended与实际调用退出 → `OnAbilityTerminationCompleted()` | GA早数据广播、ASC原生通知均只是必要时点。native End/final End/Cancel/实际Activate/相关Try全部退出，先封存原结果槽、退休原记录并释放Busy，再由ASC唯一广播原Notice，广播后无旧状态写。 |

私有 Termination 校验与 ResourceWork 使用同一不可变原激活 Proof。GA 仍核原实例／非复用 serial／Spec／PredictionKey／ActorInfo allocation；有已签 Context 时，ASC `CheckOriginalAbilityBindingForTermination` 先认证当前已提交的同 Binding 完整快照，再核原 allocation／ASC／Owner／Avatar 与缓存端点。因此合法 Refresh 可改变 Controller 等原生缓存而保留精确原 End 资格，不重签 Original、不续旧输入／相机／移动／Montage 工作权限。未签 Context 的既有模式仍走原严格校验；换 Binding／后继失配返回 Stale／ActivationChanged。相关接口约束见 [[AbilitySystem/计划_原请求终止#同 Binding Refresh：工作与终止校验目的|接口契约]]。

缺受控Try来源的raw非虚Try/CallActivate可以签原身份、清原资源；final调用返回仍不能证明外层raw Try尾部，终止结果明确UnsupportedEntry、不发布协议Completed。匹配Context仅清自己的原资源，不补见证。拒绝活动同实例自动Retrigger，Busy覆盖原全退出；不同PerExecution实例不能按同Spec一概禁止。业务消费原Notice后显式新请求，没有自动重启。

## 模块接缝

- [[Input/结构|Input]]持有原生输入来源；Hero持有ActionInstance观察、原ASC ID/deadline、有限Retry、Extension typed H订阅及自身移动Session/Binding。ASC唯一持有held/queued聚合，`PostProcessInput`是Process的唯一帧入口。
- [[Teams/结构|玩家Slot]]或[[BossAI/结构|BossState]]选择Owner/Avatar；[[Combatants/结构|Host]]持有请求及公布资源，调用ASC事务与发布接口。[[Character/结构|Extension]]持有本地H，Health/Base/Hero消费各自原H；ActorInfo写入仅归ASC。
- GA持有向[[Camera/结构|Camera]]请求的原接收者、模式Spec/generation及Offset token。Cleanup只归还原token；Camera持有模式求值与视图发布职责。
- PlayerCombo/BossMelee通过[[Combat/结构|Combat]] Owned Window/精确hit订阅接收同一HitResult，闭包捕Original/原窗口/token；GA调用Builder与GAS，Combat只查询并去重。共享Builder支持显式空GE，Combo已选正常Cue模式；Boss消费者要求有效GE。必需Spec失败false/空输出、不施加该hit的GE/Cue。Combo依赖/Builder故障直接RequestAbilityEnd(Original,true,true)，Boss只拒绝该hit；合法Spec应用免疫/拒绝的碰撞Cue政策保持。
- AI 经 `UGGYGOCombatActionAbility::ActionTag` 请求语义动作，BT 不直接执行伤害。具体竖切见 [[BossAI/结构|BossAI 结构]]。

| InitialPress | Receive的原资源进入有序边沿；首次Spec集合冻结，原Owner／Avatar／World和完整来源保留。Process在外调前按原边沿位置冻结InitialSourcesByEdge，不把未来B请求并入前一个A边沿。 |
| FiniteRetry | Queue仅接受原ID／Tag／deadline和真实Queued许可；本次Try沿用完整原请求，再次失败原载荷回传。Released后未过期tap可重试，held与retry资格不是同一个状态。 |
| Released／Invalidated | 前者仅释放原真实来源的held，最后来源才发Spec Released；后者精确退休且不伪发Released。deadline到期只失去retry，不代替物理释放。 |
| QueryOnly／raw | CanActivateAbilityByHandle只Query；嵌套raw Try仍有独立Can评估但无外层输入许可。正常失败反馈保留，不生成借来的Retry来源。 |

ASC唯一维护原输入请求及Spec的held／queued聚合，多个原来源以OR保持。真实边沿有序保存，同Spec一次Process最多尝试一次；剩余边沿由后续引擎输入帧消费。详见[[GGYGO_流程_AbilitySystem.canvas|输入消费流程]]。

每次Can评估与Try的输入许可独立关联；NotifyAbilityFailed只消费匹配的评估及完整原来源。GA/CDO不持输入来源，组准入sequence与输入请求身份分别归ASC对应资源。

Clear推进输入revision并退休原资源／证明；弱端点、真实World／Owner／Avatar、输入阻断、原deadline失效时不发布旧Retry。End的原资源清理不要求重新借当前Ready。操作Result是历史Accepted／AlreadyApplied／Rejected／Stale，不等于能力激活成功。

[[Input/结构|Input]]持有原生观察，Hero持有ActionInstance的首次deadline、原ASC请求及完整Retry。Extension的`RegisterLocalAbilitySystemNoticeAndCall`提供H订阅，`IsLocalAbilitySystemResourceReady`提供原资源工作资格。移动Source提供Session与receiver接口，CMC持有Binding并消费MovementInputFact；各调用方只归还自身Session/Binding，移动与输入帧执行权威保持唯一。

ASC只保留一份当前发布记录：Receipt、来源Context与None／Pending／Dispatching／Consumed／Closed阶段；Context是提交资源的派生元数据，不是第二绑定权威。成功Consumed释放强Proof引用，只留下去重／认证所需元数据；失败Closed不能被误认成成功Consumed。不建历史队列、第二Issuer或帧调度器。窗口退出只清原Operation；明确失败无成功发布Proof。完整native Init已返回但未commit的失败可保留另一份私有原写入清理证明，见下节；不自动回滚原生字段、不改成其它动作。匹配失效只释放自己的引用，旧栈副本仍保留历史bCommitted，但没有当前权限。

旧`InitAbilityActorInfo`／`ClearActorInfo`和项目类型`RefreshAbilityActorInfo`也覆盖自己的完整Super窗口：Busy时先拒绝，窗口外写入前撤销旧Context／Operation／待发布引用并退休已提交cleanup快照及失败Init证明，字段相同也不会恢复旧证据；被Busy或生命周期拒绝且未写入的调用不退休原来源。基类Refresh非虚，项目同名方法是遮蔽，不是override；任意基类指针或限定基类Refresh不在保障范围内。旧GA通知／OnSpawn目前保留在旧Init的原生窗口退出后；新Try不执行这些通知。

### 原已提交清理来源（Destroy）

ASC继续唯一拥有Context、身份序号与native执行。既有 `AvatarBindingActorInfoSnapshot` 在逻辑撤销时保留，唯一增加用途为清理来源认证；工作查询仍严格Current/live，不从cleanup查询结果开放Ready或新动作。私有WorkingBinding/CommittedCleanup目的分别校验工作与清理生命周期，后者允许仍合法分配、正在Destroy的原Owner/Avatar；无效／析构中的ASC、失效必需对象、allocation或完整字段改变均明确失败。

`CheckAvatarBindingCleanupContext`必须匹配Binding/LastActorInfoWrite的原Issuer、当前记录的精确Context、原ActorInfo allocation及全字段：ActorInfo ASC／Owner／Avatar／PC／Mesh／Movement／原AnimInstance／Tag、实际GetAnimInstance、ASC缓存Owner／Avatar／Tag。弱身份按index/serial比较，null不冒充expired；查询纯游戏线程，不执行或保存闭包。

Cancel／Cue remove／Clear使用同一私有 `MatchCommittedCleanupContext` 准入及原native Busy；清理作用域查询只证明原资源，不能要求新安装或Ready。真实typed写前以及准入legacy Init/Clear/Refresh退休旧提交快照，即使端点相同；逻辑撤销和拒绝调用不等于真实写入。新Init/Refresh/Bootstrap/Replace工作准入未放宽，关闭组件宿主不能由Clear重开。

PreserveOwner遇关闭Owner或组件宿主明确LifecycleClosed。Host在原Release及自己已提交的失败收尾显式选择ClearMode：关闭原Host/Owner使用ClearActorInfo，正常保留Owner使用PreserveOwner。Typed Clear保留事务提交／Released凭据契约，cleanup查询本身不产生提交或发布。

### 失败Init原写入清理（未提交证明）

common typed Init执行器涵盖普通／Bootstrap／Replace。完整qualified `Super::InitAbilityActorInfo`返回后、后续原caller query／Commit之前捕获候选：原pending Operation/Issuer与Kind Init、Busy、原allocation、原请求Owner/Avatar及缓存相符，保存完整WrittenActual。依赖字段非法可能正是提交失败原因，来源认证不作Ready验证。

私有不可变 `FFailedAvatarActorInfoInitCleanupProof`只含OriginalOperation、Before、WrittenActual；仅完整native返回后未commit失败且当前原场景仍精确匹配才保留，成功提交不保留。原allocation强引用仅防地址复用，Actor引用仍弱，不存查询闭包、第二Binding／序号／队列／计时器或执行器。缺认证证明保留真实失败，并单次诊断模块／ASC／Operation／目标／原因。

`TryCleanupFailedAvatarActorInfoInit`消费原失败结果Operation与必需同步pure原清理作用域查询；入口不重捕／猜来源。核对成员原Proof、Before元数据、allocation和完整实际字段，拒绝无效ASC、较新写入/提交或Busy；关闭原Owner不借工作Ready门槛拒绝合法自身清理。既有单native窗口内，query前后均重检原场景，再关闭匹配发布许可、消费Proof并退休旧Montage来源，唯一qualified `Super::ClearActorInfo`。

native返回及第二次原query前后核对精确后置条件：Owner／Avatar／PC／Mesh／Movement、cached Owner／Avatar和实际GetAnimInstance空；原ActorInfo::AnimInstance字段和Tag按GAS真实Clear行为保留，其余原字段/allocation不变。不能要求引擎未清字段空。Succeeded只描述原写入物理清理，原Operation/Before保留、bCommitted=false、CommittedContext空，无Receipt／Notice／Ready，原Init仍失败；native后检查失败也不重发已消费Proof，不回滚／自动重试。

后继真实typed/准入legacy ActorInfo写入退休旧失败Proof，拒绝／预写入失败不替换既有实际写入资源；消费或ASC销毁释放。已提交Context不能认证这个未提交写入，未知qualified native绕行或子类额外字段未作完整保障声明。

### 单次发布与回调资源归属

`Publish`先捕获原Receipt，校验真实Pending后以作用域管理自己的派发许可。每次调用必需纯谓词的前后，以及事件／每个GA回调的前后，均复核原ASC、Proof、完整Context、实际字段和生命周期；谓词不保存到成员。事件前切换Dispatching，派发不占用原生Busy窗口，因此普通回调可合法接续B。

事件之后，只有原Kind为Init、After是有效Pawn且不可变BeforeAvatar身份不同，才按原新Pawn规则通知GA。同Pawn Init、Refresh和Clear不冒充首次出生。OnPawn候选是局部原SpecHandle＋弱实例：调用前以`FindAbilitySpecFromHandle(Handle, EConsiderPending::None)`重取原Spec，并核对原实例仍在实际成员列表。已移除／PendingRemove／脱离原Spec或弱对象失效的资源跳过，不替换为另一实例。OnSpawn在OnPawn之后重新收集Handle，每项同样排除PendingRemove、复制原Spec后调用`TryActivateAbilityOnSpawn`，不跨回调保留容器引用。

发布凭据由ASC唯一持有并消费。后继接管时，原调用返回自身历史结果及Stale，只可清理匹配的原Proof／Context。派发中重入为Busy／PublicationInProgress，成功消费后再发为Rejected／PublicationAlreadyConsumed；缺谓词、调用方失效或实际字段不符不授Ready权限。

[[Combatants/结构|宿主]]持有Avatar选择、公布及原请求／销毁订阅；[[Character/结构|Extension]]持有本地H，ASC负责发布凭据及派发认证。消费者只归还自己的原H与资源。

### 原归属限定取消（C1a）

`TryCancelAvatarBindingAbilities(Expected, WithTags, WithoutTags, IsOriginalCallerCurrent)`无默认参数：调用方提交捕获的原完整Context、显式标签筛选和必需同步纯查询。查询证明原清理资源／作用域仍有效，不能借正在关闭的Ready资格或临时读取的后继Context续权。ASC在任何外调前复制标签值及null模式：null With不筛选，非null空With匹配零；业务Tag仍由调用方选择。

复用同一ASC的原Operation槽与原生Busy作用域；查询前后、原生返回后按原已提交cleanup来源重检Operation／Context／实际ActorInfo／清理生命周期；逻辑撤销可清理，不借工作Ready。入场成功只关闭匹配原Context发布许可，再一次限定`Super::CancelAbilities`，Busy覆盖完整遍历、原生列表锁析构、返回重检与Complete。窗口内新绑定／取消返回Busy，不自动排队；完整返回后才允许合法后继。

Succeeded只证明原生调用同步返回且原归属仍有效；`bCommitted=false`、CommittedContext为空，不改Binding／LastWrite／ActorInfo，不签Receipt／Notice。不可取消或WaitingToExecute的技能不被证明已End；失效返回Stale只清原操作，不追加输入／Clear／Cue／Montage或回滚已经发生的取消。没有第二取消执行器或持久状态。

### 原归属限定Cue清理（C1b）

`TryRemoveAvatarBindingGameplayCues(Expected, IsOriginalCallerCurrent)`消费原Context和必需的同步pure Query，查询仅证明原清理资源作用域。原Closing资源的清理资格独立于工作Ready和已撤销的Extension缓存。

复用既有Operation `RemoveGameplayCues` Kind、Reserve／Complete与同一native Busy，不新增Cue状态或执行器。入场仅检查Query存在性；Busy内Query前后、原生返回后重检原weak ASC、Operation、Context、完整实际ActorInfo与CommittedCleanup目的，不要求工作Ready。只关闭匹配发布许可、不撤Binding；一次限定`Super::RemoveAllGameplayCues()`完整返回及Complete之后释放Busy。Succeeded不Commit、不签Receipt／Notice，只证明原归属有效时同步返回；失效明确失败，RAII仅退出自己的Operation，不回滚Cue或清后继。

该接口的执行范围是原生Active Cue容器，不包括Minimal容器、延期Notify或异步表现的完成屏障。Removed使用原Avatar来源；Clear后的owner-only Context不授予旧Avatar资源清理资格。

## 玩家普攻原生实现

`UGGYGOPlayerComboAbility` 管理段序及原资源的作者信号许可，三段同优先级。`FGGYGOComboStep` 定义每段 Montage 的 Main→End、作者通知名和下一段索引；`WaitComboInput` 发送来源段与请求号。Task的`NotifyReceived`与原实例快照只提供事实，GA核原资源后决定打断；Main/End与旧窗口不代替这个许可。服务器通过 ASC `ClientCorrectAbilityState` 传递 `FGGYGOComboCorrectionData`，由 Combo 的 `ReceiveAbilityCorrection` 验证类型、范围和 Revision。ASC 不依赖 PlayerCombo 具体类型。

当前由Initialize固定Original并初始化自己的原批次，Body校验配置/Commit并创建原Task资源；native回调按Original、原Task/段token/Owned窗口核验。Context Cleanup先脱成员/原订阅和StepMotionResources，再退原CMC observer/Action句柄、结束原Task/停止原播放/恢复Mesh和原World timer；final基类统一执行native End并发布完成。旧回调不能借当前资源清后继，段token只区分原激活内资源，不与GA权威状态竞争。详见[[计划_玩家普攻连段]]。

正式GA_Pyrios_Attack_Combo使用三段Main/End、FullBody及MotionTranslationScale=1；ABP_Pyrios的RequiredPoseCorrectionSlot=FullBody与ActionPoseSlot对应。段与资源关系见[[GGYGO_结构_玩家普攻连段.canvas|连段结构]]，执行链见[[GGYGO_流程_玩家普攻连段.canvas|连段流程]]。
