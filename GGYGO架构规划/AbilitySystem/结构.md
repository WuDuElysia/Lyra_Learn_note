## Current 与 Base 数值接口

`GGYGOAttributeBase::CalculateBaseForCurrent(ASC, ExpectedAttributeSet, Attribute, ExpectedCurrent, DesiredCurrent)`（`Attributes/GGYGOAttributeBaseCalculation.h`）提供GAS原生聚合的Current→Base计算。输入为ASC、原Set、注册的`FGameplayAttributeData`属性、实际预期Current和目标Current；仅游戏线程、权威端可用，不要求持久属性的Avatar Ready。

该函数通过ASC公开接口做实时capture、默认/CustomQualifies资格外调、重新capture与来源认证。`GGYGOAttributeCalculation`只处理已认证的栈内聚合快照和原生临时通道；不访问当前ASC/Set，不持GE、依赖登记或业务缓存。

| 无状态计算接口 | 输入与产物 |
| --- | --- |
| `HasSameAttributeAggregation(First, Second)` | 两个冻结聚合快照；返回修饰项和资格是否一致。 |
| `PrepareNativeAttributeCalculationChannels(Snapshot, Parameters, OutChannels, OutOrder)` | 已通过资格的快照和求值参数；输出原生临时通道/顺序或明确Reason。 |
| `IsAttributeForwardValueConfirmed(Actual, Desired)` | 有限正向结果与目标；返回是否匹配。 |

快照和临时通道仅在调用栈内存活；原Set/ASC/Owner、Base、Current及修饰项资格构成来源。计算不写属性、不选择生命/韧性边界。

| `FGGYGOAttributeBaseCalculationResult` | 含义与消费边界 |
| --- | --- |
| `Ready / None`与有限`CalculatedBase` | 正向求值匹配目标；候选供调用方立即提交，结果不证明属性已写入或结算。 |
| `Rejected`与明确Reason | 无效依赖、不可逆通道、有效Override、非法Divisor、零或原生拒绝的倍率、非有限值或正向不匹配。 |
| `Stale / SourceChanged / AggregationChanged` | 原来源、数值或聚合项已变化；不提供可提交候选。 |

HealthSet唯一拥有目标Current、MinimumHealth/0～Max边界、Base提交及自身Post结果标记。Health/Poise的有限Base是内部聚合输入，可低于0或高于Max；客户端Max投影保留原Base，使用GAS重求值。

消费者见[[Messages/结构#HealthSet 的 Current 结算|Current结算接口]]、[[Messages/结构#客户端上限的 NetReceive 投影|客户端依赖接口]]；计算与提交时序见[[GGYGO_流程_AbilitySystem.canvas|数值流程]]。

## 精确Montage播放归属

ASC只留一个能力Montage播放入口，原生`PlayMontage`覆盖转到它；只支持`UGGYGOMontageGuardAnimInstance`，Guard识别本次调用创建的实例并处理播放期间的重入。

| 接口 | 输入 → 作用 → 输出 |
| --- | --- |
| `PlayAbilityMontage(Ability, ActivationInfo, Montage, Rate, Section, Start, IsCallerContextCurrent)` | 处于当前激活的项目GA与播放参数 → 经Guard播放 → `FGGYGOAbilityMontagePlaybackResult`（Playback、Guard结果、Duration）。非Guard、参数无效或Guard拒绝时Playback为空，不回退原生播放。 |
| `IsPlaybackCurrent(Playback)` | 原播放身份 → Local当前播放仍是同一能力、Montage与PlayInstanceId，且在同一AnimInstance上、能力仍处于记录的激活 → bool。 |
| `ClearPlayback(Playback)` | 原播放身份 → 仍为当前播放时清除AnimatingAbility与能力CurrentMontage，不停止Montage → bool。 |

播放身份为Guard实例＋Local PlayInstanceId＋所属激活；Avatar更换后PlayInstanceId会从头计数，所以另核AnimInstance。依赖方向为ASC→[[Animation/结构|Animation Guard]]；实际播放、混出、结束和停止分支见[[GGYGO_流程_AbilitySystem.canvas|播放流程]]。

## Task原实例与资源消费

Montage Task持有原Ability/ASC/Owner/Avatar/Mesh/Anim、ActorInfo allocation、唯一Slot、原Playback/Guard及整数实例ID。Animation拥有姿态契约；GA拥有原激活和招式资源；CMC唯一执行胶囊位移。

| Task接口 / 资源 | 输入、产物与归属 |
| --- | --- |
| `PlayMontageAndWaitForEvent` / `ResolvePlayRate` / `GetEffectivePlayRate` | 工厂参数配置原Task；TaskRate包含一次全局缩放，EffectiveRate包含Montage RateScale。 |
| `FNativeCallbacks` / `RegisterNativeCallbacks` / `UnregisterNativeCallbacks(Token)` | Ready前一次非空native包；含Completed、BlendOut、Interrupted、Cancelled、EventReceived、SectionReceived、NotifyReceived、OnFailed。返回精确订阅token；调用方持token及固定原Activation的闭包，Task持不可变注册包。 |
| `TryGetOriginalSectionSnapshot` / `SectionReceived` | 原实例的Montage、ID、Section、Position、Rate；Section Fact另含bLooped。只提供原实例事实。 |
| `AcquireActionPoseContract` / `PollActionPoseContract` | Animation返回ExplicitNotRequired或RequiredReady及原Ticket。Task持Ticket，Required模式由引擎GameplayTasks Tick只读Poll。 |
| `FGGYGOMontageTaskFailureFact` / `OnFailed` | 原Montage、真实Slot、Startup/Playback、InstanceID、Diagnostic。Startup ID为INDEX_NONE；事实描述已清理Task的必需姿态失败，不授予当前工作权限。 |
| Cancel/Event订阅、实例委托、scale lease、Ticket | Task独占自身资源；`OnDestroy`按原来源精确解绑、释放，停止范围由原Guard/ID及Stop策略限定。 |
| 私有`FInFlightMontagePlayCleanup` | 与调用栈共持的原停止义务，覆盖播放外调期间Task结束；不持播放进度或GA状态。 |

普通Event使用`IsNotifyValid`的原播放工作资格；自然Completed是原实例事实，原ASC播放归属已退休也不等于事实失效。Task Completed与GA终止Completed分别描述实例和能力生命周期。Required失败使用typed OnFailed，普通取消使用Cancelled；native消费者结束原GA时，旧BP通知可被拒绝。

native/BP派发、外调后校验、Required失败、缩放和实例清理时序见[[GGYGO_流程_AbilitySystem.canvas|Task流程]]。姿态Ticket/epoch/worker接口见[[Animation/动作姿态修正|姿态能力契约]]。

## 原事件桶与输入Task订阅

| 接口 / 数据 | 输入、产物与所有权 |
| --- | --- |
| `WaitComboInput(OwningAbility)` / `SetSourceStep(InStep)` | 工厂返回未Ready Task；GA提供来源段，Task不拥有段序。 |
| `FGGYGOComboInputNativeDelegate` / `RegisterNativeCallback` / `UnregisterNativeCallback(Token)` | Ready前一次可选非空native单播；返回精确FDelegateHandle。Task持注册包，调用方持token及原Activation闭包。 |
| BP `OnPress(SourceStep, RequestId)` | 两个整数事实；remote载荷X为[0,65535]段序、Y为[1,65535]请求号。 |
| 私有原输入订阅 | 弱ASC/Ability、Spec、PredictionKey、remote/predict模式、自身事件handle。零key合法；Spec/key只定位GAS桶，不是GA激活身份。 |
| `OnDestroy` | 归还原桶中的自身handle及native包，不消费后继事件或换ASC补来源。 |

ASC/GAS拥有InputPressed事件桶和预测机制。Task使用原订阅读、发、消费事件，GA校验原激活及资源；native/BP派发和remote回放时序见[[GGYGO_流程_AbilitySystem.canvas|输入Task流程]]。

## 激活薄hook与OnSpawn受控入口

| GA接口 | 输入、产物与职责 |
| --- | --- |
| final `CanActivateAbility` / `CanActivateAbilityAdditional` | 原生Can参数与失败Tags输出；基类拥有GAS/BP/成本/冷却/Tag/组检查，派生仅追加业务条件。 |
| `InitializeAbilityActivation(Original)` | 原不可变激活身份；派生初始化该原激活的业务资源。 |
| `ActivateAbilityBody(Original, Handle, ActorInfo, ActivationInfo, TriggerData)` | 同一原激活和原生参数；派生承接招式业务，默认Body调用native Super/BP。 |
| `CleanupAbilityResourcesForTermination(Context)` | 本次正式结束的原激活与bWasCancelled；位于原生EndAbility之前，派生归还自己拥有的Task、窗口、timer、Mesh与CMC等资源，覆盖须调Super归还相机接管。 |
| `TryActivateAbilityOnSpawn(ActorInfo, Spec)` | OnSpawn策略、Spec/Avatar和网络端条件；按网络执行策略由应激活的一端调用一次`TryActivateAbility`。 |

Can/Activate/End为final；取消走原生CancelAbility，最终都经EndAbility覆盖。扩展点不拥有另一生命周期执行器。激活顺序及停止分支见[[GGYGO_流程_原请求终止.canvas|激活与终止流程]]。

## 原请求终止

| 接口 / 数据 | 输入 → 作用 → 输出 |
| --- | --- |
| `FGGYGOAbilityActivationHandle` | GA在原生PreActivate（`ASC::NotifyAbilityActivated`）签发，在`ASC::NotifyAbilityEnded`的原生广播之前退役；共享不可变记录，相等只说明同一次激活，广播内重激活得到新身份。 |
| `CaptureCurrentActivation()` / `IsActivationCurrent(Handle)` | → 当前身份（未激活或正在结束为空）/ 是否同一身份、仍Active、未进入结束清理。 |
| `RequestAbilityEnd(Original, Replicate, Cancelled)` / `RequestAbilityCancel(Original, Replicate)` | 原激活 → 结束或取消 → `Accepted` / `NotCurrent` / `NotCancelable`。原生ScopeLock期间延后执行，执行时重核原激活，不作用于后继；结果只用于诊断。 |
| final `EndAbility` | 正式结束时先调`CleanupAbilityResourcesForTermination`，再原生End；清理期间对本实例的重复结束不执行。 |
| `OnAvatarSwitchOut(Context)` / `NotifyOwnerControlLost／Regained()` | 换人时由Squad调用，见[[Teams/结构#换人：留场、退场与进场|Teams 换人]]。 |

GAS拥有实际Active/Spec/count/Task和原生终止执行；GA只持当前激活身份与自己的资源。外部等待（Boss BT、Editor观察）订阅原生`OnAbilityEnded`并按Spec匹配，并处理Try内同步结束。完整调用见[[GGYGO_流程_原请求终止.canvas|激活与结束流程]]。

## 模块接缝

- [[Input/结构|Input]]拥有物理来源；Hero拥有原生输入会话、Action首次观察、原ID/deadline及会话关联的ASC资源；ASC唯一拥有held/queued聚合、有限重试许可与等待集合。PlayerController的PostProcessInput提供唯一Process帧入口。
- [[Teams/结构|玩家Slot]]或[[BossAI/结构|BossState]]持久拥有ASC；[[Combatants/结构|Host]]选择Avatar并调用原生`InitAbilityActorInfo`；[[Character/结构|PawnExtension]]以本地订阅（`FGGYGOLocalASCSubscription`）发布Ready/Released，Hero、CMC、Health、LocomotionFX各自订阅。Hero会话退役时按来源一次结束其签发的全部输入请求。
- [[Camera/结构|Camera]]拥有模式求值和视图；GA持原接收者、模式Spec/generation和Offset token，仅归还自身资源。
- [[Animation/结构|Animation]]拥有Guard和姿态窗口语义；Task消费原实例事实，[[Movement/结构|CMC]]唯一执行胶囊XYZ。
- [[Combat/结构|Combat]]拥有Owned Window、命中查询及去重；GA消费原HitResult，GE/Execution/AttributeSet拥有数值执行。Cue拥有表现配置与播放职责。
- Boss BT通过ActionTag请求能力并订阅原生`OnAbilityEnded`等待，不直接执行伤害，也不凭旧Spec/key终止后继。
- [[Teams/结构|Squad]]换人时调用GA的换出决定与`RequestAbilityCancel`、ASC的`ReleaseHeldInputForControlLoss`，并以`State.SwitchReturnPending`拦截输入发起的新激活。

## 关键接口契约（按调用边界）

| 调用方 → 接口 | 关键输入 | 产物与责任 |
| --- | --- | --- |
| Hero → `ReceiveAbilityInputRequest(Tag, PreviousID, Deadline)` | 原Tag、可空ID、原World有限绝对截止 | ASC签原请求或复核已有资源；结果不代表能力已激活。 |
| PlayerController → `ProcessAbilityInput(dt, bPaused)` | 本帧原输入边沿 | 输入缓冲按边沿顺序消费，每帧每Spec至多一次`TryActivateAbility`；唯一帧入口，不拥有第二Tick。 |
| Boss BT → `CanActivateAbilityByHandle` / `TryActivateAbility` | 已授予Spec Handle | Can为QueryOnly；BT订阅`OnAbilityEnded`按Spec等待，处理Try内同步结束。 |
| GAS → final `NotifyAbilityFailed(Handle, Ability, Tags)` | 本层Can评估及完整原输入来源 | ASC保存真实Queued许可/等待；原GAS/GA失败反馈与`OnAbilityInputRetryable`仅观察该原失败。 |
| 组释放／ReturnPending移除 → 输入缓冲`WakeQueuedAbilityInputRequests` | 原ID/Tag/deadline及真实Queued许可 | 加入既有PendingRetries，交唯一Process消费；ReturnPending可能经复制移除，由Process入口发现后唤醒一次。Hero不保存等待。 |
| GA final `CanActivateAbility` → ASC `IsAbilityInputActivationAttempt(Handle)` | ASC有`State.SwitchReturnPending` | 只拒绝输入缓冲发起的这次Try，失败Tag为`Ability.ActivateFail.SwitchReturnPending`；事件触发与能力内部激活不受影响。 |
| Squad → `ReleaseHeldInputForControlLoss()` | 旧队员失去控制 | 对仍按住的活动Spec派发一次真实释放（WaitInputRelease会收到），再`ClearAbilityInput`。 |
| Hero → `EndAbilityInputRequest(ID, Kind)` | 原ID、Released或Invalidated | 归还原来源；最后held来源Released才发布释放，Invalidated不伪造释放。 |
| ASC/Host → `ClearAbilityInput` | 整ASC输入上下文失效 | 退休请求/revision/来源；局部Hero清理使用精确End。 |
| GA → `IsActivationBlockedByGroup` / `FinalizeAbilityGroupAdmission` | GroupTag/Priority/SelfPolicy / ASC分配的AdmissionSequence | ASC提供只读准入及最终裁决；ActiveAbilitiesByGroup为项目组登记。 |
| GA → `BuildHitEffectPayload(TargetASC, GE, Level, Hit, Origin)` | 原Owned命中、Source/Target/Origin及显式GE模式 | 成功返回Context/可选Spec/Cue载荷；必需Spec失败返回false/空输出。招式失败响应归具体GA。 |
| GE → DamageExecution::Execute_Implementation | Execution.PassedInTags、Source快照、SetByCaller及原EffectContext | 解析绝对／倍率模式，校验两项基础输入；经可选AbilitySource材质／距离衰减后写Damage／PoiseDamage。无HitResult距离为0，无AbilitySource接口时系数保持1。 |

输入消费、组准入、失败反馈和命中执行见[[GGYGO_流程_AbilitySystem.canvas|主流程]]、[[GGYGO_流程_能力仲裁.canvas|仲裁流程]]、[[GGYGO_流程_伤害结算.canvas|伤害流程]]。

## 单次 Can 评估与输入失败来源

| 数据 / 来源 | 归属与契约 |
| --- | --- |
| `FGGYGOAbilityInputRequestIdentity` | ASC签发的weak SourceASC、InputRevision、非零RequestSerial；revision=0合法，弱身份保留index/serial。 |
| `FGGYGOAbilityInputRetryRequest` | 原InputTag、完整Identity和原World绝对OriginalDeadline；默认-1无效。 |
| InitialPress / FiniteRetry | 输入缓冲保存首次Spec集合、原截止与来源会话，不存Owner/Avatar/World快照。Press与Retry是来源类型，不是另一输入权威。 |
| Released / Invalidated | 真实物理释放与来源失效分别表达；deadline只限定Retry，不替代松键。 |
| QueryOnly / raw Can | 各自独立评估，没有外层输入许可，不产生借来的Retry来源。 |
| Can评估与失败证明 | ASC关联本层Try/Can及完整原来源；GA/CDO不持输入来源，NotifyAbilityFailed只消费匹配证明。 |

ASC拥有原输入请求、真实有序边沿、Spec held/queued聚合及有限重试。多个held来源按OR保持；deadline只限制有限Retry，不决定held或真实Released。Hero只持原Action观察、ID/deadline与自己的H关联。

| ASC内部资源 | 唯一归属与寿命 |
| --- | --- |
| `RetryableSpecHandles` | RequestRecord内保存本次真实Queued（组排队或SwitchReturnPending）的Spec许可；原有限重试消费、过期或请求退休使其失效。 |
| `QueuedWaitOrder` / `LastAbilityInputWaitOrder` | 本次等待集合的派生顺序，按首次真实Queued排列；不是请求身份，不从残留Spec许可生成等待。 |
| `PendingAbilityInputRetries` | 已通过原ID/Tag/deadline验证的有限重试；由既有Process消费，不持另一激活队列。 |
| `OnAbilityInputRetryable` / `OnAbilityGroupFreed` | ASC外部观察接口；不把许可、等待或调度委托给Hero。 |

输入许可只靠revision与记录存在判断有效（ActorInfo端点变化、ClearActorInfo与输入阻断都清空并递增revision），另受阻断约束；有限Retry另受原绝对deadline及激活Policy约束。GroupFreed的消费顺序见[[GGYGO_流程_能力仲裁.canvas|仲裁流程]]。

## Avatar 绑定

绑定按Lyra做法由[[Combatants/结构|Host]]编排：释放旧Avatar（取消能力，保留`Ability.Behavior.SurvivesDeath`；清输入；移除全部Cue；ActorInfo回到Owner-only，宿主关闭时`ClearActorInfo`；旧Pawn广播Released），再`InitAbilityActorInfo(宿主, 新Pawn)`，由新Pawn的PawnExtension广播Ready。ASC不保存绑定事务、身份或发布记录；`InitAbilityActorInfo`覆盖在Owner或Avatar变化时清输入，检测到新Pawn Avatar时通知能力实例并尝试OnSpawn激活。Controller变化只走`RefreshAbilityActorInfo`。

## 伤害输入、Spec与属性边界

| 所有者／输入 | 作用与产物 |
| --- | --- |
| FGGYGOComboStep | Damage为绝对模式数值；DamageMultiplier为独立倍率，-1表示未配置且仅用于绝对模式；PoiseDamage独立配置。模式来自所选GE的Execution配置。 |
| GE的Execution.PassedInTags | 精确Tag DamageCalculation.AttackPowerMultiplier选择倍率模式；该模式必须使用DamageExecution。Combo拒绝同GE混合绝对与倍率Execution。 |
| GA → BuildHitEffectPayload | 每次服务器Owned命中创建新Spec；先AddHitResult后写显式Origin。Source的BaseDamage／BasePoiseDamage以bSnapshot=true捕获本次Spec创建时的聚合值，包含当时生效的Buff。 |
| Combo → 实际返回的Spec | 复核GE模式及段配置。倍率模式写SetByCaller.DamageMultiplier，绝对模式写SetByCaller.Damage；削韧独立写SetByCaller.PoiseDamage，随后通过ASC Apply。Builder扩展后的冲突键或倍率不一致使本次命中失败。 |
| DamageExecution绝对输入 | 没有倍率模式及倍率键时，伤害／削韧分别优先读取存在的对应SetByCaller键；缺键才用对应原生捕获。明确覆盖须有限非负，非法覆盖拒绝。 |
| DamageExecution倍率输入 | 必须同时有模式Tag及有限非负倍率，不能有绝对伤害键；攻击力快照×倍率为基础伤害。缺捕获、非有限捕获／乘积明确拒绝；有限负捕获仍由最终非负公式处理。削韧独立解析。 |
| Execution → HealthSet | 两项基础输入合法才新增Damage／PoiseDamage Modifier。可用AbilitySource接口提供材质与Origin→ImpactPoint距离衰减；HealthSet消费元属性并结算Current／Base。原生Execution拒绝只是不新增本次输出，不提供整个GE应用失败结果。 |

实际顺序见[[GGYGO_流程_伤害结算.canvas|伤害流程]]；命中查询资源归[[Combat/结构|Combat]]，数值结算归GE／Execution／AttributeSet，Cue消费表现载荷。

## 玩家普攻原生实现

PlayerCombo拥有段序、原Step资源及独立AttackGate／MovementGate。ComboStep分别配置攻击接续和移动打断模式／异名Notify；Disabled显式关闭对应门。攻击点只允许真实新攻击接续；移动点作者位置等于Main实际末端，原生offset提前触发仍须等原实例实际位置到达末端。WaitComboInput提供段／请求号，Montage Task提供按名认证的原实例事实与快照。

Combo拥有Montage／输入／FX Task与各自token、Owned窗口、原World timer、Mesh/prerequisite及StepMotionResources；CMC拥有实际位移执行。强类型`FGGYGOComboCorrectionData`由ASC路由，Combo验证类型、范围和Revision；ASC不依赖具体Combo类型。

正式GA_Pyrios_Attack_Combo配置三段Main/End、FullBody及MotionTranslationScale=1；ABP_Pyrios的RequiredPoseCorrectionSlot与ActionPoseSlot对应FullBody。详细资源关系见[[GGYGO_结构_玩家普攻连段.canvas|连段结构]]，招式执行见[[GGYGO_流程_玩家普攻连段.canvas|连段流程]]。
