## 精确Montage播放归属（K3：ASC与Task源码冻结，GA未迁移）

UE的Local／Rep／GA字段和Animation的Guard仍分别是原权威。ASC新增的唯一`MontagePlaybackProvenance`仅认证一次完整原生Local写入：不透明Handle的私有不可变Proof记录原ASC、GA／Spec／PredictionKey、Montage及Guard生命周期／非复用CallId／CreatedInstanceId；ASC当前资源持有原ActorInfo allocation与实际来源快照。8位Local PlayInstanceId仅核对一致性，不作唯一播放身份。

| 调用方 → 实际接口 | 输入、作用与输出／边界 |
| --- | --- |
| Task::Activate → `TryPlayMontageWithOwnership(Ability, ActivationInfo, Montage, PlayRate, StartSection, StartTimeSeconds, IsOriginalCallerCurrent)` | 必需同步纯原调用方查询。复用完整限定Super／GuardScope，Scope封存并退出后，Accepted且原源／GA／Local一致才返回Succeeded及新Playback；失败保留Guard／Duration历史，无有效Handle，非Guard不走播放兜底。Task已消费单一栈Result；失败诊断并结束自身，不猜实例或改用旧Play。 |
| 原资源持有者 → `CheckMontagePlaybackOwnership(Original) const` | 纯核对原Proof／当前provenance、ActorInfo来源、GA激活来源、Guard生命周期及实际Local／GA字段；不依赖Montage仍活动或GA IsActive，停止不会凭空抹去原清理资格。无活动实例不是“可以清任意新播放”。 |
| 目标GA收尾 → `CaptureMontagePlaybackOwnership(OriginalAbility, OriginalSpecHandle, OriginalActivationInfo) const` | 只捕获这份原GA来源已有的认证资源；缺对应记录明确NoOwnedPlayback，失败不返回另一来源Handle。不是“GA＋资产推导身份”，不签发新播放或授业务执行权限。GA统一收尾尚未迁移。 |
| 混出／原GA收尾 → `TryClearMontageAnimatingAbility(Original)` | 先Check原Handle；成功仅限定基类GA setter写CurrentMontage=null并清Local AnimatingAbility，再退休原证明。避免virtual业务setter重入后误清后继；不Stop、不延迟到技能结束，调用时机仍归原消费者。 |

同GA同Montage接续A→B时，B证明替换A；B停止后仍只允许B的原清空，A晚回调不能借相同资产认领B。完整原生Init（含同端点）实际重置Local，写入前退休；Clear同理。Refresh前后仅按真实来源核对，无Local／来源改变则保持播放证明，不用发布Context修订强制延期。原生复制、模拟、动态Montage及旧Clear在实际可截获入口核对／退休；拒绝、无写入失败或Superseded外层不凭空清除已接受后继。

组件只持一份当前provenance，替换／实际生命周期写入／精确Clear／OnUnregister释放自己的资源；调用方Handle不强持ActorInfo，也不维持播放。未观察的Owner ABA、限定基类绕行写入不能冒称已隔离；不改UE／GAS库。接口源码四文件已冻结并有限静态接受，未成功整链编译／UE，原严格失败保留；Task两源已消费Result及原资源并冻结；GA统一终止／Busy／业务薄扩展点未实施，受控激活政策待用户决定。正式AnimClass、资产与网络未验。

依赖为ASC→[[Animation/结构|Animation Guard]]，无反向GAS依赖；结构和关键调用见 [[GGYGO_结构_AbilitySystem.canvas|结构图]]、[[GGYGO_流程_AbilitySystem.canvas|精确播放支线]]。阶段顺序见 [[AbilitySystem/计划_AbilitySystem#当前精确Montage增量（K3）|迁移计划]]。

## Task原实例与资源消费（源码已接，未编译）

`Activate`捕原ActorInfo allocation与Ability／ASC／Owner／Avatar／Mesh／Anim来源，先注册自身取消及事件订阅，再调用ASC `TryPlayMontageWithOwnership`。同步纯查询只读原关联和Task存活；ASC／Guard各自认证原生写入与实例。Task不再维护全局播放尝试表、token或“唯一新实例”扫描，也不签Handle。

| Task接口／资源 | 输入、作用、输出及清理责任 |
| --- | --- |
| `PlayMontageAndWaitForEvent`／`ResolvePlayRate` | BP工厂／委托与速率语义保持；TaskRate只含一次全局缩放，EffectiveRate再乘Montage RateScale。窗口／组合仍归Montage和GA。 |
| `Activate` → 原Result | 成功且原Task／Ability／ActorInfo有效才保存Handle／Guard，按CreatedInstanceId重取原实例，直接绑定带原Guard载荷的委托，获取自身缩放lease。最后`SetWaitingOnAvatar`外调后无成员写。 |
| private `FInFlightMontagePlayCleanup` | 只是一份与调用栈共持的原停止义务；原生外调中Cancel／Destroy先记录，返回后凭Result.Guard清原实例。已结束Task不安装资源；不是播放状态、进度或GA生命周期权威。 |
| `IsNotifyValid` → EventReceived | 原ActorInfo及Task有效、未混出、精确实例播放且ASC Check原Handle成功才接事件；Montage／instance ID过滤保持。复制Payload后广播，监听随自身销毁清理。 |
| `OnMontageBlendingOutForInstance` | 匹配原Guard → 释放自身缩放 → `TryClearMontageAnimatingAbility(OriginalPlayback)`。A晚回调不能清B；保留原混出清空时机，不Stop／延期。有效原上下文才发布原BlendOut／Interrupted事实。 |
| `OnMontageEndedForInstance` → OnCompleted | 原Guard委托身份／生命周期、原ActorInfo及AbilityTask资格成立且非Interrupted，发布原自然结束事实。**不Check当前ASC播放，不要求原实例仍活动或存在**，正常混出已退休归属不会吞Completed。调用方须另证原GA生命周期，不能据此End后继。 |
| `ExternalCancel`／`OnAbilityCancelled`／`OnDestroy` | 取消通知幂等；撤自己的Event／Cancel句柄及仍属自己的实例委托，释放原Character/token缩放。按明确Stop策略处理原实例；普通EndTask不擅自改成AbilityEnded。 |

停止按原Guard生命周期＋CreatedInstanceId重取。只有ASC认证原Handle且资产当前活动实例正是原ID，才用`CurrentMontageStop`保留GAS复制更新；否则仅释放有效的**精确原本地实例**，不Clear新GA／ASC、不换Avatar找资源。Guard失效明确诊断，不猜后继；原实例已释放无需替代清理。外调返回时Task仍活但原ActorInfo失效，同样诊断并清原实例。

两源已作者明确冻结、统筹全文／哈希有限接受，八只读依赖保持；Build55已通过UHT但整链编译失败，未UE／资产验收。旧nonGuard／after-Super／手工ID夹具保留未适配，历史严格失败未复测。GA统一终止、Combo／Boss原生命周期认证、正式AnimClass与联机仍独立未完成；不能称K3闭环。Task依赖ASC原协议与[[Animation/结构|Guard]]只读身份，无反向依赖／第二播放器／帧调度。

## 模块接缝

- [[Input/结构|Input]]负责原生物理观察，Hero负责自身Action观测资源与有限意图；ASC负责唯一原请求和Spec held／queued聚合。ASC三个native输入入口及完整Retry载荷已编码冻结、未成功整链编译；当前Hero仍是旧Tag消费者，A迁移未实施。目标Hero捕获首个真实请求的原deadline→`ReceiveAbilityInputRequest`，只凭返回原ID及完整Retry载荷缓冲／结束；不能按Tag猜ID或从`-1`补截止。`AGGYGOPlayerController::PostProcessInput`仍为唯一`ProcessAbilityInput`引擎入口。能力Action物理来源已获原则授权，原观察端口及纯查询技术接缝仍未实现，不能把准备接口当正式生产已接。
- Owner/Avatar由[[Teams/结构|玩家Slot]]或[[BossAI/结构|BossState]]选择。共同Host的`RequestAvatarBinding`及[[Character/结构|Extension]]生产路由已编码冻结，原生ActorInfo写入只由ASC执行；本次未成功整链编译。Health／Base原资源消费已源码接入，Hero未迁移。两项ASC清理来源契约已有限静态接受／冻结、未成功整链编译；Host H1已消费原提交cleanup及显式Clear模式，H2已有限静态接受冻结。共用GAS契约不等于共用编队业务，整链仍未闭合。
- `UGGYGOGameplayAbility` 可请求 [[Camera/结构|Camera]] 的模式覆盖和微调；拥有者是 Ability SpecHandle，结束时清自己的覆盖。
- PlayerCombo 与 BossMelee 都通过 `BuildHitEffectPayload` 消费 [[Combat/结构|MeleeTrace]] 的同一个 HitResult：先加入 HitResult，再写入命中回调时 Avatar 位置作为显式 Origin；`FGGYGOGameplayEffectContext::Duplicate` 保留该 Origin。碰撞一旦成立就可发布 Cue，目标免疫或 GE 被拒绝不吞掉命中表现。
- AI 经 `UGGYGOCombatActionAbility::ActionTag` 请求语义动作，BT 不直接执行伤害。具体竖切见 [[BossAI/结构|BossAI 结构]]。

Boss阶段A–C及组仲裁有历史实现证据；当前原请求输入运行与Host生产迁移属于其后的未成功整链编译接力，不以历史测试通过宣称新消费者或资产已接。具体GA、正式配置、联机与剩余停点分别见[[计划_实施状态]]。

## 关键接口契约（按调用边界）

| 调用方 → 接口 | 输入 / 前提 | 作用与输出 / 副作用 |
| --- | --- | --- |
| 目标Hero → `ReceiveAbilityInputRequest(Tag, PreviousIdentity, OriginalDeadline)` | 空完整ID仅新请求；非空只复核原请求；真实来源及原World有限绝对截止 | 签发或复核ASC原ID，冻结首次匹配Spec集合和Owner／Avatar／World；返回操作历史，不立即Try，不代表能力激活。Hero旧调用尚未迁移。 |
| PlayerController → `ProcessAbilityInput(dt, bPaused)` | 引擎本帧输入处理后，唯一执行入口 | 捕有序原边沿，按边沿位置冻结InitialSources；同边沿来源OR、同Spec本批至多一次Try。保留真实后续DeferredEdge；Held不被deadline过期伪释放，无第二Tick。 |
| Boss BT → `ASC::CanActivateAbilityByHandle(Handle, OutFailureTags)` | ActionTag 映射出的已授予 Spec | QueryOnly 选招预检，复位输出并返回 Can/FailureTags，不签发输入重试证明；真正激活仍须 `TryActivateAbility` 再准入一次。 |
| GAS → `GA::CanActivateAbility(...)`（final） | Handle、当前 ActorInfo、Source/Target Tags、可选失败 Tags 输出 | 在核心外调前开启独立评估并认领匹配输入许可；依次保留 ActorInfo、`Super::CanActivateAbility` 的原生/BP/冷却/成本/Tag 检查、组检查，全部通过后调用 `CanActivateAbilityAdditional`。返回前封闭本层结果。业务只能追加条件，不替代核心检查。 |
| GAS → `NotifyAbilityFailed(Handle, Ability, FailureReason)`（final） | 原失败来自本层已封闭Can评估、仍有效的完整原来源数组 | 外调前复制Tags并一次消费证明，再Super；真实Queued且来源有效，才逐原来源发`OnAbilityInputRetryable(const FGGYGOAbilityInputRetryRequest&)`。raw／Query不借外层来源，原Native→Script反馈保留。 |
| 目标Hero → `QueueAbilityInputRetry(const FGGYGOAbilityInputRetryRequest&)` | 原ID／InputTag／OriginalDeadline全部匹配、真实B0 Queued许可、未过期 | 精确原请求入队，下一Process作为FiniteRetry；不是新请求、不替held或延长窗口。结果Accepted／AlreadyApplied／Rejected／Stale只描述操作。 |
| 目标Hero → `EndAbilityInputRequest(ID, Released/Invalidated)` | 原ASC签发ID；Released需真实原来源释放，失效不是释放 | Released清该来源held，最后来源才发Released，并保留未过期tap；Invalidated精确退休、不伪发Released。已失效Context仍可还自身原义务，不清同Tag后继。 |
