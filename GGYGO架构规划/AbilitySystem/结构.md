## Current 与 Base 数值接口

`UGGYGOAbilitySystemComponent::TryCalculateNumericAttributeBaseForCurrentValue(ExpectedAttributeSet, Attribute, ExpectedCurrent, DesiredCurrent)`提供GAS原生聚合的Current→Base计算。输入为原Set、注册的`FGameplayAttributeData`属性、实际预期Current和目标Current；仅游戏线程、权威端可用，不要求持久属性的Avatar Ready。

ASC拥有实时GAS capture、默认/CustomQualifies资格外调、重新capture与来源认证。`GGYGOAttributeCalculation`只处理已认证的栈内聚合快照和原生临时通道；不访问当前ASC/Set，不持GE、依赖登记或业务缓存。

| 无状态计算接口 | 输入与产物 |
| --- | --- |
| `HasSameAttributeAggregation(First, Second)` | 两个冻结聚合快照；返回修饰项和资格是否一致。 |
| `PrepareNativeAttributeCalculationChannels(Snapshot, Parameters, OutChannels, OutOrder)` | 已通过资格的快照和求值参数；输出原生临时通道/顺序或明确Reason。 |
| `IsAttributeForwardValueConfirmed(Actual, Desired)` | 有限正向结果与目标；返回是否匹配。 |

快照和临时通道仅在调用栈内存活；原Set/ASC/Owner、Base、Current及修饰项资格构成来源。ASC不写属性、不选择生命/韧性边界。

| `FGGYGOAttributeBaseCalculationResult` | 含义与消费边界 |
| --- | --- |
| `Ready / None`与有限`CalculatedBase` | 正向求值匹配目标；候选供调用方立即提交，结果不证明属性已写入或结算。 |
| `Rejected`与明确Reason | 无效依赖、不可逆通道、有效Override、非法Divisor、零或原生拒绝的倍率、非有限值或正向不匹配。 |
| `Stale / SourceChanged / AggregationChanged` | 原来源、数值或聚合项已变化；不提供可提交候选。 |

HealthSet唯一拥有目标Current、MinimumHealth/0～Max边界、Base提交及自身Post结果标记。Health/Poise的有限Base是内部聚合输入，可低于0或高于Max；客户端Max投影保留原Base，使用GAS重求值。

消费者见[[Messages/结构#HealthSet 的 Current 结算|Current结算接口]]、[[Messages/结构#客户端上限的 NetReceive 投影|客户端依赖接口]]；计算与提交时序见[[GGYGO_流程_AbilitySystem.canvas|数值流程]]。

## 精确Montage播放归属

UE的Local/Rep/GA字段与Animation Guard各自拥有原生权威。ASC的唯一`MontagePlaybackProvenance`认证原生Local写入，持有原ActorInfo allocation与实际来源快照，不维护播放进度或第二播放器。

| 接口 / 数据 | 输入与输出 | 责任与有效期 |
| --- | --- | --- |
| `FGGYGOAbilityMontagePlaybackHandle` | 私有const Proof；`HasPlayback / HasSamePlayback` | 仅ASC签发。Proof含弱ASC/GA、Spec/PredictionKey、Montage、Guard生命周期、非复用CallId和CreatedInstanceId；8位Local计数只用于一致性核对。 |
| `TryPlayMontageWithOwnership(Ability, ActivationInfo, Montage, Rate, Section, Time, Query)` | 原播放参数和必需同步纯调用方查询；返回Outcome、Reason、Guard、Duration、Playback | ASC认证完整原生返回与Local写入，成功才签Handle；失败只提供真实结果。 |
| `CheckMontagePlaybackOwnership(Original)` | 原Handle；返回归属结果与原因 | 只读校验Proof、当前provenance、ActorInfo、GA来源、Guard和Local字段。无活动实例仍可具有原清理资格。 |
| `CaptureMontagePlaybackOwnership(Ability, Spec, ActivationInfo)` | 原GA激活来源；返回已有播放证明或明确`NoOwnedPlayback` | 供GA终止Context捕获原资源；不创建新身份或接管Task停止。 |
| `TryClearMontageAnimatingAbility(Original)` | 原Handle；返回清空结果 | 只清匹配的GA CurrentMontage/Local AnimatingAbility并退休证明，不停止Montage。 |
| PlaybackResult / OwnershipCheck / ClearResult | Outcome、Reason、Guard历史和原Handle | 按值结果不拥有播放器、进度、停止策略或网络调度。 |

原证明由替换、真实ActorInfo写入、精确Clear和ASC注销退休。同GA/同资产后继具有不同Proof，旧回调不能借资产相等清后继。Refresh按真实来源核对；原Local与来源仍匹配才保留证明，归属核对失败即退休。限定基类绕行不在项目接口认证范围内。

依赖方向为ASC→[[Animation/结构|Animation Guard]]；实际播放、混出、结束和停止分支见[[GGYGO_流程_AbilitySystem.canvas|播放流程]]。

## Task原实例与资源消费

Montage Task持有原Ability/ASC/Owner/Avatar/Mesh/Anim、ActorInfo allocation、唯一Slot、原Playback/Guard及整数实例ID。Animation拥有姿态契约；GA拥有原激活和招式资源；CMC唯一执行胶囊位移。

| Task接口 / 资源 | 输入、产物与归属 |
| --- | --- |
| `PlayMontageAndWaitForEvent` / `ResolvePlayRate` / `GetEffectivePlayRate` | 工厂参数配置原Task；TaskRate包含一次全局缩放，EffectiveRate包含Montage RateScale。 |
| `FNativeCallbacks` / `RegisterNativeCallbacks` / `UnregisterNativeCallbacks(Token)` | Ready前一次非空native包；含Completed、BlendOut、Interrupted、Cancelled、EventReceived、SectionReceived、NotifyReceived、OnFailed。返回精确订阅token；调用方持token及固定原Activation的闭包，Task持不可变注册包。 |
| `TryGetOriginalSectionSnapshot` / `SectionReceived` | 原实例的Montage、ID、Section、Position、Rate；Section Fact另含bLooped。只提供原实例事实。 |
| `AcquireActionPoseContract` / `PollActionPoseContract` | Animation返回ExplicitNotRequired或RequiredReady及原Ticket。Task持Ticket，Required模式由引擎GameplayTasks Tick只读Poll。 |
| `FGGYGOMontageTaskFailureFact` / `OnFailed` | 原Montage、真实Slot、Startup/Playback、InstanceID、Diagnostic。Startup ID为INDEX_NONE；事实描述已清理Task的必需姿态失败，不授予当前工作权限。 |
| Cancel/Event订阅、实例委托、scale lease、Ticket | Task独占自身资源；`OnDestroy`按原来源精确解绑、释放，停止范围由原Guard/ID及Stop策略限定。 |
| 私有`FInFlightMontagePlayCleanup` | 与调用栈共持的原停止义务，覆盖播放外调期间Task结束；不持播放进度或GA状态。 |

普通Event使用`IsNotifyValid`的原播放工作资格；自然Completed是原实例事实，原ASC播放归属已退休也不等于事实失效。Task Completed与GA终止Completed分别描述实例和能力生命周期。Required失败使用typed OnFailed，普通取消使用Cancelled；native消费者结束原GA时，旧BP通知可被拒绝。

native/BP派发、外调后校验、Required失败、缩放和实例清理时序见[[GGYGO_流程_AbilitySystem.canvas|Task流程]]。姿态Ticket/epoch/worker接口见[[Animation/动作姿态修正|姿态能力契约]]。

## 原请求终止

| 接口 / 数据 | 输入、产物与所有权 |
| --- | --- |
| `FGGYGOAbilityActivationHandle` | GA私有不可变Proof；弱原ASC/实例、Spec、ActorInfo和非复用serial。PredictionKey不是唯一激活身份。 |
| `FGGYGOAbilityTerminationHandle / Context` | 首次原Activation、种类、复制/取消参数、camera与Montage资源；GA拥有唯一原记录。 |
| `TryActivateAbilityWithTerminationBoundary(Handle, AllowRemote)` | 返回Outcome/Reason、bNativeAccepted、OriginalActivation及可能同步完成的Notice。Accepted不证明本地Active或Commit。 |
| `CaptureCurrentActivation` | 按ResourceWork校验原完整Context/LastWrite/来源；返回已有Original，不签或续签身份。 |
| `RequestAbilityEnd(Original, ReplicateEnd, WasCancelled)` / `RequestAbilityCancel(Original, ReplicateCancel)` | 精确原激活请求；首次参数不可变，Cancel另要求可取消性。原生ScopeLock continuation属于同一原记录。 |
| `TerminationResult / TerminationCompletedNotice` | 原结果、Reason及只读Context；描述原完成历史，不授予后继End或当前idle权限。 |
| ASC `OnAbilityTerminationCompleted` | 原GA记录全部必要实际调用退出后的完成事实；ASC是唯一发布者。 |

GAS拥有实际Active/Spec/count/Task和原生终止执行；GA拥有原终止记录与清理义务；ASC只持匹配记录的Try退出依赖和原Ended见证。

Termination与ResourceWork共享原激活Proof，校验目的不同。同Binding合法Refresh可保留精确原End资格；旧输入、镜头、移动和播放工作权仍受其原来源限制。raw非虚Try/CallActivate缺受控外层返回来源时，结果为UnsupportedEntry，不生成协议Completed。

完整调用及完成门见[[GGYGO_流程_原请求终止.canvas|终止流程]]。

## ActorInfo来源值

`FGGYGOActorInfoSource`统一表达实际ASC、Owner/Avatar、Controller、Mesh、Movement、ActorInfo/实际AnimInstance、cached Owner/Avatar及两个AffectedAnimInstanceTag。端点为弱引用，字段按只读来源证据使用；它不执行capture、不拥有绑定、Ready或播放身份。

ASC的实际快照持强ActorInfo allocation和Source；GA激活Proof持弱allocation和同一Source。allocation所有权由外层Proof/快照承担。ResourceWork要求原完整Context/LastWrite和实际来源；Termination仍只按原终止目的消费ASC认证，来源值不改变两者权限。

## 模块接缝

- [[Input/结构|Input]]拥有物理来源；Hero拥有原生输入会话、Action首次观察、原ID/deadline及原H关联；ASC唯一拥有held/queued聚合、有限重试许可与等待集合。PlayerController的PostProcessInput提供唯一Process帧入口。
- [[Teams/结构|玩家Slot]]或[[BossAI/结构|BossState]]持久拥有ASC；[[Combatants/结构|Host]]拥有Avatar选择及原请求/公布资源；[[Character/结构|Extension]]拥有本地H及Ready/Refreshed/Closing/Released通知。Closing只退休原H消费者关联，Hero据此精确End自身ID；原生输入绑定/IMC与Action首次观察仍归输入会话。ActorInfo写入归ASC。
- [[Camera/结构|Camera]]拥有模式求值和视图；GA持原接收者、模式Spec/generation和Offset token，仅归还自身资源。
- [[Animation/结构|Animation]]拥有Guard和姿态窗口语义；Task消费原实例事实，[[Movement/结构|CMC]]唯一执行胶囊XYZ。
- [[Combat/结构|Combat]]拥有Owned Window、命中查询及去重；GA消费原HitResult，GE/Execution/AttributeSet拥有数值执行。Cue拥有表现配置与播放职责。
- Boss BT通过ActionTag请求能力并持原完成等待，不直接执行伤害，也不凭旧Spec/key终止后继。

## 关键接口契约（按调用边界）

| 调用方 → 接口 | 关键输入 | 产物与责任 |
| --- | --- | --- |
| Hero → `ReceiveAbilityInputRequest(Tag, PreviousID, Deadline)` | 原Tag、可空ID、原World有限绝对截止 | ASC签原请求或复核已有资源；结果不代表能力已激活。 |
| PlayerController → `ProcessAbilityInput(dt, bPaused)` | 本帧原输入边沿 | ASC消费输入并发起受控Try；唯一帧入口，不拥有第二Tick。 |
| Boss BT → `CanActivateAbilityByHandle` / 受控Try | 已授予Spec Handle | Can为QueryOnly；Try返回原激活及同步/异步完成关联，BT持自己的等待。 |
| GAS → final `NotifyAbilityFailed(Handle, Ability, Tags)` | 本层Can评估及完整原输入来源 | ASC保存真实Queued许可/等待；原GAS/GA失败反馈与`OnAbilityInputRetryable`仅观察该原失败。 |
| ASC内部唤醒 → `QueueAbilityInputRetryInternal(OriginalRetry)` | 原ID/Tag/deadline及真实Queued许可 | 加入既有PendingRetries，交唯一Process消费。公开`QueueAbilityInputRetry`保留同一精确验证及失败诊断；Hero生产链不调用或保存等待。 |
| Hero → `EndAbilityInputRequest(ID, Kind)` | 原ID、Released或Invalidated | 归还原来源；最后held来源Released才发布释放，Invalidated不伪造释放。 |
| ASC/Host → `ClearAbilityInput` | 整ASC输入上下文失效 | 退休请求/revision/来源；局部Hero清理使用精确End。 |
| GA → `IsActivationBlockedByGroup` / `FinalizeAbilityGroupAdmission` | GroupTag/Priority/SelfPolicy / ASC分配的AdmissionSequence | ASC提供只读准入及最终裁决；ActiveAbilitiesByGroup为项目组登记。 |
| GA → `BuildHitEffectPayload(TargetASC, GE, Level, Hit, Origin)` | 原Owned命中、Source/Target/Origin及显式GE模式 | 成功返回Context/可选Spec/Cue载荷；必需Spec失败返回false/空输出。招式失败响应归具体GA。 |
| GE → `DamageExecution::Execute_Implementation` | CombatSet捕获、SetByCaller、原EffectContext | Origin到ImpactPoint距离衰减及目标元属性输出；无HitResult的距离为0。 |

输入消费、组准入、失败反馈和命中执行见[[GGYGO_流程_AbilitySystem.canvas|主流程]]、[[GGYGO_流程_能力仲裁.canvas|仲裁流程]]、[[GGYGO_流程_伤害结算.canvas|伤害流程]]。

## ActorInfo事务底层与历史凭据

| ASC接口 / 数据 | 输入、产物与所有权 |
| --- | --- |
| `FGGYGOAvatarBindingIdentity / OperationIdentity / Context` | Issuer弱身份与单调serial；Context含Binding和LastActorInfoWrite。ASC唯一签发，同Pawn指针不证明同一次绑定。 |
| `GetAvatarBindingContext / CheckAvatarBindingIdentity / CheckAvatarBindingContext` | 读取或核对原ASC身份；工作资格要求Current/live。 |
| `TryExecuteAvatarActorInfoTransaction(Request, OutPublication)` | 精确Context、明确Kind/ClearMode和同步纯谓词；返回事务Result，实际提交才有Receipt。 |
| `TryBootstrapAvatarActorInfoTransaction` | Unissued且完整空Context的显式首次准入。 |
| `TryReplaceRevokedAvatarActorInfoTransaction` | 精确Revoked Context的显式替换；不与普通或Bootstrap入口互作错误兜底。 |
| `IsAvatarBindingNativeWriteBusy` | ASC原生调用栈窗口的只读状态；窗口内新请求返回Busy。 |
| `InvalidateAvatarBinding` | 原Context；撤销工作及匹配发布许可，保留已提交清理来源。 |
| `FGGYGOAvatarBindingRequest / Result / Notice` | 请求、提交结果和通知语义分别表达；bCommitted不等于Host公布或全局Ready。 |
| `FGGYGOAvatarBindingPublicationReceipt` | ASC私有const Proof；`TryGetCommittedEvidence`只复制原Result/Notice历史，弱端点不延长生命周期。 |
| `PublishAvatarBindingNotice(Receipt, Query)` | 原Receipt与必需同步纯谓词；只派发当前匹配凭据，不回滚提交或补发失败。 |
| `IsAvatarBindingNoticeDispatching` / `IsAvatarBindingPublicationContextCurrent` | 精确原Receipt / Context；分别认证Dispatching与当前Dispatching/成功Consumed，不提供全局Ready。 |
| `FGGYGOAvatarBindingNoticeEvent` / `OnAvatarBindingNotice` | ASC独占广播；外部借用Add/Remove订阅入口，持有自己的handle；参数为const Receipt/Notice引用。 |

ASC以单个`TUniquePtr<FGGYGOAvatarBindingProtocol>`独占绑定元数据。协议对象唯一保存LastIssuedSerial、Context、IdentityState、CommittedSource、PendingOperation、FailedInitCleanup、native Busy及PublicationRecord；ASC没有竞争副本。私有头依赖ASC内部类型，ASC公开头仅前置声明，外部调用方仍只使用ASC端口。

| 私有协议职责 | 输入与产物 |
| --- | --- |
| `ReserveValidatedOperation` / `CheckCommitOperation` / `CommitValidatedSource` | ASC认证的原操作和实际快照；签发单调serial、核操作并保存唯一提交来源/Context。 |
| `InvalidateBinding` / `InvalidateOperation` / `DiscardOperation` | 精确原身份与明确Reason；撤销匹配许可或退休原操作。 |
| `TryEnterNativeWrite` / `LeaveNativeWrite` | 原ASC调用栈的唯一native Busy窗口；不执行ActorInfo写入。 |
| 提交/失败Init来源的保留与退休 | ASC已认证来源值；保存或释放自己的原Proof/allocation资源，不执行capture。 |
| 发布记录迁移与消费 | 原Receipt/Context及ASC已重检的阶段；保存唯一记录并消费原发布义务。 |

ASC保留原生Super调用、实际ActorInfo捕获、纯谓词外调前后认证与公开发布桥；协议对象不调用外部代码、不保存谓词、不建Tick/Timer或第二执行器。

唯一发布记录含Receipt、来源Context及None/Pending/Dispatching/Consumed/Closed阶段。Context是来源元数据，不是第二绑定权威；历史Receipt副本不授予当前权限。

旧Init/Clear和项目Refresh也拥有原生Busy边界。真实写入退休旧证明，拒绝且未写入的调用不退休来源。基类Refresh非虚，基类指针或限定基类绕行不在项目同名接口保障范围内。事务与发布时序见[[GGYGO_流程_AbilitySystem.canvas|ActorInfo流程]]。

### 原已提交清理来源（Destroy）

私有协议的唯一`CommittedSource`持ASC认证的ActorInfo allocation与完整`FGGYGOActorInfoSource`；外层Context提供原Issuer/LastWrite。WorkingBinding要求Current/live；CommittedCleanup允许匹配Current或Revoked及仍合法分配、Destroy中的原Owner/Avatar。

`CheckAvatarBindingCleanupContext(Expected, OutReason)`纯GT认证原提交来源，不执行动作或签发Ready。Cancel/Cue/Clear共同消费`MatchCommittedCleanupContext`与原native Busy。逻辑撤销保留cleanup来源，真实typed或legacy写入退休来源。

ClearMode由调用方显式选择：正常保Owner为PreserveOwner，关闭Host/Owner为ClearActorInfo。关闭来源的PreserveOwner返回LifecycleClosed，不自动换模式。

### 失败Init原写入清理（未提交证明）

私有const `FFailedAvatarActorInfoInitCleanupProof`含OriginalOperation、Before和WrittenActual。它认证完整native Init返回但未提交的实际写入；ActorInfo allocation强引用防地址复用，Actor端点仍为弱引用。它不认证工作Ready，不存调用方闭包或另一Binding。

`TryCleanupFailedAvatarActorInfoInit(OriginalOperation, Query)`消费原失败Operation及必需同步纯清理查询，限定原证明的物理Clear。Succeeded仍为bCommitted=false、CommittedContext空，无Receipt/Notice/Ready，原Init结果不变。

证明由真实后继写入、消费或ASC销毁释放。已提交Context不替代未提交写入证明；入口不重捕当前来源。认证和Clear后置分支见[[GGYGO_流程_AbilitySystem.canvas|失败Init清理流程]]。

### 清理调用方

| 调用方 | 持有资源及接口 |
| --- | --- |
| CombatantState Host | Avatar选择、原H、初始化与清理scope；使用原提交Context或失败Operation，显式选择ClearMode。 |
| Character Extension | 本地H及Ready/Refreshed/Closing/Released通知资源；Closing只说明原H关联关闭。 |
| Health/Base/Hero | 自己的H订阅与模块资源，只归还匹配资源。 |

### 单次发布与回调资源归属

ASC拥有发布Proof及派发认证；Host拥有Avatar选择和公布；Extension拥有本地H；接收者拥有自身订阅/资源。纯谓词只存活于调用栈，不被ASC保存。

OnPawn/OnSpawn候选为原SpecHandle和弱实例，来源必须仍属于原Spec。原Init对不同新Pawn提供出生通知；同Pawn Init、Refresh和Clear不具有该语义。后继接管使旧发布返回自身历史和Stale，旧记录仅可释放自己的资源。

### 原归属限定取消

`TryCancelAvatarBindingAbilities(Expected, WithTags, WithoutTags, Query)`消费原完整Context、显式筛选与必需同步纯清理查询。null With不筛选，非null空With匹配零；业务Tag选择归调用方。

接口共用ASC原Operation和native Busy，不改变Binding/LastWrite/ActorInfo。Succeeded表示原生调用同步返回且归属仍匹配；bCommitted=false，无Receipt/Notice，不证明不可取消或WaitingToExecute能力已结束。

### 原归属限定Cue清理

`TryRemoveAvatarBindingGameplayCues(Expected, Query)`消费原Context与同步纯清理查询，共用ASC原Operation/native Busy。结果不提交Binding，不签Receipt/Notice。

执行范围为原生Active Cue容器；不提供Minimal容器、延期Notify或异步表现完成屏障。Removed使用原Avatar来源，owner-only Context不授予旧Avatar清理权限。

## 玩家普攻原生实现

`UGGYGOPlayerComboAbility`拥有段序、原Step资源和作者信号打断许可。`FGGYGOComboStep`配置每段Montage的Main/End、作者通知名和下一段；WaitComboInput提供段/请求号，Montage Task提供原实例事实与快照。

Combo拥有Task/token、Owned窗口、原World timer、Mesh/prerequisite及StepMotionResources；CMC拥有实际位移执行。强类型`FGGYGOComboCorrectionData`由ASC路由，Combo验证类型、范围和Revision；ASC不依赖具体Combo类型。

正式GA_Pyrios_Attack_Combo配置三段Main/End、FullBody及MotionTranslationScale=1；ABP_Pyrios的RequiredPoseCorrectionSlot与ActionPoseSlot对应FullBody。详细资源关系见[[GGYGO_结构_玩家普攻连段.canvas|连段结构]]，招式执行见[[GGYGO_流程_玩家普攻连段.canvas|连段流程]]。
