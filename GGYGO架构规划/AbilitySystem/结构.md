# AbilitySystem：结构与接口

> 结构图：[[GGYGO_结构_AbilitySystem.canvas]] · 激活流程：[[GGYGO_流程_AbilitySystem.canvas]] · 子图：[[GGYGO_流程_能力仲裁.canvas]]、[[GGYGO_流程_伤害结算.canvas]]

## 当前类关系

| 类 / 数据 | 跨模块关键接口 | 责任 |
| --- | --- | --- |
| `UGGYGOAbilitySystemComponent` | `AbilityInputTagPressed/Released`、`ProcessAbilityInput`、`CanActivateAbilityByHandle`、`IsActivationBlockedByGroup`、`SetAbilityGroupConfig`、`SetTagRelationshipMapping` | 缓存输入、统一激活、组仲裁和 Tag 关系；持有 GA、GE 与 AttributeSet 的 GAS 状态。 |
| `UGGYGOGameplayAbility` | `CanActivateAbility`、`ActivateAbility`、`EndAbility`、`SetCameraMode`、`ClearCameraMode`、`ApplyCameraOffset` | 能力基类，声明组身份/优先级/消耗，统一能力生命周期与相机清理。 |
| `UGGYGOAbilityGroupConfig` / `UGGYGOAbilityTagRelationshipMapping` | 配置给 ASC | 前者决定组内并发规则；后者决定 Tag 需求、阻断与取消。两种规则正交。 |
| `UGGYGOAbilitySet` | `GiveToAbilitySystem`、`FGGYGOAbilitySet_GrantedHandles::TakeFromAbilitySystem` | 由宿主授予或收回属性集、能力、效果；基础 HealthSet/CombatSet 在宿主默认子对象上。 |
| `UGGYGOHealthSet` / `UGGYGOCombatSet` | 属性读取与变更委托 | 分别承接承受侧生命/韧性与输出侧伤害/治疗属性。 |
| `UGGYGODamageExecution` / `UGGYGOGameplayCueManager` | GE 执行 / Cue 路由 | 前者结算伤害并写入目标元属性，后者控制 Cue 加载。 |
| `UGGYGOAbilityTask_PlayMontageAndWaitForEvent` | Montage 与 GameplayEvent 回调 | 让 GA 等待表现事件；命中窗口由具体能力解释。 |

## 模块接缝

- 玩家输入由 [[Input/结构|输入模块]] 的 HeroComponent 转成 InputTag，`AGGYGOPlayerController::PostProcessInput` 调 `ProcessAbilityInput`。ASC 拒绝且可重试时，HeroComponent 缓冲意图，等组释放再申请。
- Owner/Avatar 由 [[Teams/结构|玩家 Slot]] 或 [[BossAI/结构|BossState]] 装配；PawnExtension 只消费注入的 ASC。两种宿主共用 GAS 契约，不共用编队业务。
- `UGGYGOGameplayAbility` 可请求 [[Camera/结构|Camera]] 的模式覆盖和微调；拥有者是 Ability SpecHandle，结束时清自己的覆盖。
- AI 经 `UGGYGOCombatActionAbility::ActionTag` 请求语义动作，BT 不直接执行伤害。具体竖切见 [[BossAI/结构|BossAI 结构]]。

当前阶段 A–C 的 Boss GAS 竖切已实现；通用玩家输入/仲裁已实现。把计划中的具体 GA、资产配置或联机验收当作独立状态，详见 [[计划_实施状态]]。

## 关键接口契约（按调用边界）

| 调用方 → 接口 | 输入 / 前提 | 作用与输出 / 副作用 |
| --- | --- | --- |
| HeroComponent → `ASC::AbilityInputTagPressed/Released(Tag)` | 已绑定的 InputTag，ASC 已有相应 Spec | 按 DynamicSpecSourceTags 找句柄，只写 Pressed/Held/Released 集；此处不立即激活。 |
| PlayerController → `ASC::ProcessAbilityInput(dt, bPaused)` | 本帧输入回调已结束 | 先收集激活候选再 `TryActivateAbility(Handle)`，最后清 Pressed/Released，Held 保留至松手。 |
| Boss BT → `ASC::CanActivateAbilityByHandle(Handle, OutFailureTags)` | ActionTag 映射出的已授予 Spec | 只做选招预检；真正激活仍须 `TryActivateAbility` 再准入一次。 |
| GA → `ASC::IsActivationBlockedByGroup(Ability, OutReason)` | GA 的 GroupTag / Priority / SelfPolicy，已激活组状态 | 决定可共存、压制或排队；失败原因用于玩家缓冲，不等于自动排队。 |
| 宿主 → `AbilitySet::GiveToAbilitySystem(ASC, Handles, Source)` | 权威宿主、PawnData 中的 AbilitySet | 授予属性/GA/GE 并记句柄；撤装用 `TakeFromAbilitySystem` 精确移除。 |
| GE → `DamageExecution::Execute_Implementation` | Source CombatSet、SetByCaller、EffectContext | 计算伤害/韧性伤害写 HealthSet 元属性；HealthSet 再做免疫、钳制、消息和死亡边沿。 |

输入与 AI 只提出能力请求，ASC 负责准入，GA 负责动作，GE/AttributeSet 负责数值。三段不能互相替代。详见 [[GGYGO_流程_能力仲裁.canvas|仲裁]] 与 [[GGYGO_流程_伤害结算.canvas|结算]]。

## 玩家普攻原生实现（完整构建通过，待运行验收）

`UGGYGOPlayerComboAbility` 已编码：管理段序、窗口与活跃期单请求缓存，三段同优先级。`FGGYGOComboStep` 定义每段 Montage 的 Main→End 和下一段索引；`WaitComboInput` 发送来源段与请求号，服务器验窗并通过 ASC `ClientCorrectComboStep` 纠正分歧。Montage Task 按动画资产、播放实例及 ASC 所有权过滤通知，换段解绑旧回调，结束恢复 Trace/任务/Mesh Tick。

当前 `GA_Attack_Light` 仍为空壳，尚未切换父类和配置段数组。IA_Attack 的 Pressed 已保存回读；HeroComponent 现有缓冲仅用于激活失败重试。UHT/C++/DLL 完整构建、新类加载和窗口/缓存自动化 1/1 通过；Montage、Trace、完整 GA 和联机运行验收尚未完成。见 [[计划_玩家普攻连段]]、[[GGYGO_结构_玩家普攻连段.canvas]]、[[GGYGO_流程_玩家普攻连段.canvas]]。
