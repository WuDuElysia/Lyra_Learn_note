## 唯一责任与数据寿命

| 所属者 | 持有或执行的内容 | 边界与清理责任 |
| --- | --- | --- |
| GAS 原生机制 | Active、spec/count、能力与 Task 的原生执行及网络语义 | GA/ASC 新记录不复制这些权威，不建第二个能力状态机。 |
| `UGGYGOGameplayAbility` | 签发原 Activation/Termination；唯一 `FOriginalTerminationRecord`；首次参数、原 camera 资源和 K3 capture；实际调用跨度与退出义务 | 原记录只属于一次原激活。重复请求不改首次参数、不重捕获。原记录及身份的对象来源为弱引用；失败或完成仅退休自己的记录。 |
| `UGGYGOAbilitySystemComponent` | 受控 native Try 栈；原 Ended 见证；指向 GA 原记录的 Try 退出依赖；原完成事件 | 退出依赖不是第二份终止状态。结果槽封存、依赖解除和原 Busy 释放均先于事件广播。 |
| `UGGYGOAbilityTask_PlayMontageAndWaitForEvent` | 自身监听、精确实例委托、RootMotionScale lease 与原停止义务 | Task 仍执行播放/停止和自身资源清理；GA 的 Montage capture 不接管播放器或再造停止执行器。 |
| 派生 GA 与业务调用方 | 招式资源、动作失败响应、对原结果的消费 | 迁移尚未完成。不得借旧回调、Spec 或 PredictionKey 猜原激活，也不得用原通知结束后继。 |

Activation 的私有 Proof 由 GA 签发，区分原 ASC、实例、Spec、ActorInfo 来源及非复用身份。PredictionKey 只参与原生一致性核对，零键不构成激活身份。`HasActivation`、`HasTermination` 和复制/相等查询只描述历史值，不证明当前存活。

## 真实接口

| 调用方 → 接口 | 输入、输出与语义 |
| --- | --- |
| 受控调用方 → `ASC::TryActivateAbilityWithTerminationBoundary(Handle, bAllowRemoteActivation)` | 只进入一次 native Try。返回原生接受结果、认证的本地原 Activation 历史及可能同步完成的原 Notice。Accepted 不等于本地激活、Commit 成功或当前 Active；remote-only 接受可以没有本地 Activation。 |
| 原 GA 调用方 → `CaptureCurrentActivation() const` | 只复制当前可认证的受控原激活。未跟踪、Busy、失效或不活动时返回空；不能从空值补造身份。Try 结果中的历史 handle 也不能作为当前活动证明。 |
| 原持有者 → `RequestAbilityEnd(Original, bReplicateEndAbility, bWasCancelled)` | 校验原身份与原生可结束性；第一份有效请求固定参数、资源和 Termination。经虚 End 调用保留派生行为，外层 dispatcher 见证完整返回。 |
| 原持有者 → `RequestAbilityCancel(Original, bReplicateCancelAbility)` | 另核原生取消资格；先捕获原资源，再进入 native Cancel 广播。Cancel 固定 `WasCancelled=true`，不重广播重复请求。 |
| GA 原 dispatcher → `CleanupAbilityResourcesForTermination(Context)` | protected 虚扩展点，原清理只执行一次。当前默认实现仅释放原 camera 接收者/token；现有派生 End 清理仍待迁移。 |
| ASC → `OnAbilityTerminationCompleted()` | ASC 唯一发布原来源 Notice，外部只能订阅/移除。Notice 是完成历史，不是当前 idle、后继 End 权限或自动重开的许可。 |

PreActivate 的 NotifyActivated 早于 native ActiveCount 递增。此时即使能观察原 Activation，仍可能不可结束；请求必须通过原生可结束性检查，不另造等待“可结束”的调度器。

## 原记录的运行链

### 1. 受控激活与首次终止捕获

`TryActivateAbilityWithTerminationBoundary` 包围真实 native Try。现有 Can 评估桥只认证匹配的原请求；真正 NotifyActivated 由 GA 签发原身份，raw/QueryOnly 不借外层来源。

持有者在原激活仍可认证时使用 `CaptureCurrentActivation`，或保留本次受控 Try 返回的原历史。`BeginOriginalTermination` 验证它仍对应可结束的原来源；Cancel 另核可取消性。首次有效请求安装唯一记录，固定请求种类、复制参数、取消语义、原 camera 接收者/token，并调用既有 `CaptureMontagePlaybackOwnership`。

K3 `Succeeded` 保存原播放历史；明确 `NoOwnedPlayback` 是正常无认证播放模式。其他捕获失败返回真实失败，不替换为无播放、当前播放或成功结果。重复请求返回首次上下文，不启动第二次执行。

### 2. 原生 ScopeLock 单次继续

`ResumeOriginalTermination` 遇原生 ScopeLock 时，由 `DeferOriginalTermination` 向 native `WaitingToExecute` 添加一个绑定原记录的 continuation；不增加 Tick、timer、自动激活或第二队列。

continuation 不重捕获资源、不改首次参数，恢复前重核原来源。若 native 解锁发生在原虚调用内，只记录原继续已就绪，等该调用返回再消费。已使用的继续再次遭锁时明确失败，不无限重排。

Cancel 已广播后若 End 必须延后，继续执行该原 End，不能再次广播 Cancel。原作用域、原请求及尚未退出的相关 Try 继续持有 Busy。

### 3. 清理、原 Ended 与完整返回

dispatcher 调用虚 End/Cancel；基类原 End 在 native End 前调用一次 Cleanup。默认 camera 清理只向快照中的原接收者归还 token，只脱离仍匹配的自身成员；原终止期间新 camera 请求明确拒绝。Task 按已有原资源策略执行自己的取消或 TaskOwnerEnded 清理。

`ASC::NotifyAbilityEnded` 提供原 Ended 见证；native 此时已经清掉 IsActive，但尚有返回尾部，所以不能凭 inactive 或该通知发布 Completed。见证比较原身份和实际来源，不从当前资源重建原身份。

GA 外层 dispatcher 必须等完整虚 End 返回；Cancel 还须等其原 native Cancel/外层调用返回。ASC 的相关原 Try 必须完成 native Try 全部尾部，先解除栈链接，再释放指向该原记录的退出依赖。未退出的依赖阻止完成通知。

### 4. 封存后发布

原 Ended、native End 返回、完整虚返回、Cancel 返回以及相关 Try 退出条件全部满足后，ASC 才能 `TryPublishOriginalTerminationCompleted`：

1. 复制原 Context，封存原 Completed 结果及同步 Try 结果槽。
2. 清除原退出依赖，退休该原记录并释放其 Busy；只退休仍匹配的原 provenance。
3. 发布原 Notice。广播后不再写原状态，回调中的后继激活不能覆盖原结果。

Completed 不承诺任意异步资源已全部 idle，不承诺网络确认，也不将 Task 的独立停止义务变成 GA 权威。

## 结果与未闭合入口

| 场景 | 当前结果或后果 |
| --- | --- |
| 初次原请求执行中，尚有退出依赖 | Accepted；Completed 尚不可用。 |
| 原生锁内接受原请求 | Deferred/ScopeLocked；只保留该原继续。 |
| 同一原激活重复请求 | AlreadyPending，保留首次上下文；不能改参数或再广播。 |
| 失效、异源、不可结束/取消或 K3 capture 失败 | 明确 Rejected/Stale/Failed/Reason；不发布 Completed，不清后继。 |
| 同步 raw Cancel，且无相关原 Try 退出见证 | 可以发生原生取消/结束，但入口自身完整虚返回没有外部证明；报告 UnsupportedEntry，不制造 Completed。入口返回后的原生继续由外层 dispatcher 另见证。 |
| 原记录等待期间原实例被锁中移除 | 仅释放可认证的原 camera 资源并明确失败；native Task teardown/full-return 未闭合，不加第二 continuation，不发布 Completed。 |
| 旧 direct End 或尚未迁移派生 End override | 可能在进入基类前已经清理；没有首次快照与完整返回保障，不能称原终止协议闭合。 |
| Task `OnCompleted` | 原 Montage 实例的自然结束事实，**不是** `OnAbilityTerminationCompleted`；不授予 End 当前/后继 GA 的权限。 |

## E14-B：相邻的构造失败响应

`BuildHitEffectPayload` 的 bool 签名保持。显式空 `DamageEffectClass` 是正常无 GE 碰撞 Cue 模式；非空 GE 必须构造有效 Spec，能力扩展（包括 `BP_EditSpecValues`）返回后失效仍按该契约失败。失败返回 false、清空输出，并诊断 Ability/Source/Target/GE/原因，不继续无 Spec Cue 初始化或伤害。

有效 Spec 的真实应用遭免疫或拒绝，是调用方结算结果；既有碰撞 Cue 政策保留。Builder 不加载替代 GE、不重试，也不代替 Combo 中止动作。**E14-B 已随 Gate66 编译；原动作失败响应待派生与生产取消契约冻结后实施，运行失败传播未验证。**

## 后续阶段与验收边界

| 阶段 | 唯一目标与停止点 |
| --- | --- |
| 剩余原取消/移除接缝 | 在所属原生调用边界取得真实返回或明确的失败契约；不得以当前 idle、延时通知或兼容路径生成 Completed。 |
| 派生清理迁移 | Combo/Boss/Admission 将自身清理按原来源与生命周期接入既有 Cleanup 扩展点。原资源快照与输入先冻结，不能仅移动 End 函数体就称来源认证完成。 |
| 生产消费者迁移 | T3-I Process已在原InputScope内调用一次受控Try并按bNativeAccepted消费，随Gate67编译；原Origin/Can失败关联、Retryable清除和成功消费保持，不raw重试，remote接受非本地Activation证明。OnSpawn/Boss BT/客户端RPC仍待迁入受控入口并保留自身网络与等待/Abort语义；派生/Task及新Completed动态边界开放。 |
| E14 动作失败传播 | Builder false 后阻断该次伤害/Cue，并只响应原动作；不取消同步重入后的后继。此调用方步骤尚未实施。 |
| final 与验收 | 派生迁移前不 final End/Cancel。源码冻结后由统筹统一编译及必要原问题冒烟；原失败复现与断言保留，专项、资产和网络未运行时保持可见。 |
