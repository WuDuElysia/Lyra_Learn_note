## 唯一责任与数据寿命

| 所属者 | 持有或执行的内容 | 边界与清理责任 |
| --- | --- | --- |
| GAS原生机制 | Active、Spec/count、Task登记、执行与网络语义 | 不迁入项目镜像状态或第二执行器。 |
| `UGGYGOGameplayAbility` | 原Activation/Termination、唯一`FOriginalTerminationRecord`、首次参数、camera/K3资源与实际调用跨度 | 实际NotifyActivated时签原身份。Initialize/Body/Context Cleanup各管原批次；完成/失败仅退休自己的记录，重复请求不改首次参数。 |
| `UGGYGOAbilitySystemComponent` | 受控Try栈、指向GA原记录的退出依赖、原Ended认证与完成事件 | 栈依赖不是第二终止状态。封存原结果、释放原Busy后唯一发布Notice，广播后不写旧状态。 |
| Montage/Input Task | 原播放/Guard/scale/事件桶/自身监听及native注册token | Task执行自身清理，原Activation由调用方闭包捕获；Task Completed只是原实例自然结束事实。 |
| Combo/Boss派生GA | 原任务、Owned Trace窗口/token、原World timer、Mesh/prerequisite；Boss另持CMC原动作句柄 | Context匹配原批次后先脱成员，再精确归还旧资源。Combat查询去重、CMC位移与Animation窗口职责保持唯一。 |
| Boss BT / 其他请求者 | 自身原等待订阅、Result与固定Original历史 | BT先订阅、再Try，核同步完成历史或异步原Notice，先解绑再Finish；Abort只撤自己的等待。 |

Activation的私有不可变Proof含原弱对象来源、Spec/ActorInfo和非复用serial；PredictionKey仅作原生一致性核对，零键合法。`HasActivation/HasTermination`及相等查询只描述历史，不证明当前Active、idle或结束后继的权限。

## 真实接口

| 调用方 → 接口 | 输入、输出与语义 |
| --- | --- |
| 请求者 → `TryActivateAbilityWithTerminationBoundary(Handle, bAllowRemoteActivation)` | 一次native Try及完整尾部，返回Outcome/Reason、bNativeAccepted、OriginalActivation和可能同步完成的OriginalTerminationCompleted。Accepted不等于本地Active/Commit，remote-only接受可无本地原身份。 |
| 原GA持有者 → `CaptureCurrentActivation() const` | 只复制已有可认证原身份，Busy/失效/不活动返回空，不签新Proof。raw原生激活可有Original，但不因此取得受控Try外层见证。 |
| 持有者 → `RequestAbilityEnd(Original, ReplicateEnd, WasCancelled)` | 核原身份及可结束性，固定首次End参数；不要求CanBeCanceled，也不先Cancel再End。 |
| 持有者 → `RequestAbilityCancel(Original, ReplicateCancel)` | 另核原生可取消性，固定取消语义，至多一次原Cancel广播。拒绝取消不能解释为另一种业务结束成功。 |
| final入口 → `InitializeAbilityActivation / ActivateAbilityBody` | Initialize在组终检/相机/Body前一次调用；默认Body一次native Super→BP。任何外调结束/延期/改变原来源，停止旧业务尾部。 |
| final原End → `CleanupAbilityResourcesForTermination(Context)` | protected虚扩展点，一次原清理后一次native End；默认归还原camera，派生归还自己原批次。 |
| ASC → `OnAbilityTerminationCompleted()` | 只能订阅/移除的原Notice事件，完成历史不等于网络确认、当前idle或自动重开许可。 |

原生NotifyActivated发生于PreActivate，早于ActiveCount++。原身份发行与Can准入sequence、玩家输入来源、Task/Trace资源身份分别有自己的唯一归属，不能互相代替。

## 原记录的运行链

### 1. 原生身份与受控来源

实际`ASC::NotifyAbilityActivated`先让GA签Original，再登记组sequence/预留并进入native通知。raw/受控激活均由这一真实接缝签身份；只有本次受控Can已准入、原参数/来源精确匹配的Try才取得不可变外层返回来源，不给QueryOnly/嵌套raw借权。

ActiveCount++后，final Activate持实际调用跨度并调用Initialize；原来源仍有效才Finalize组准入→相机/offset→Body。Initialize中结束/延期或外调改变原来源，不执行该原Body。

### 2. 首次终止与原生单次继续

`BeginOriginalTermination`核固定Original与原生前置，保存首次种类/参数、原camera接收者/token及`CaptureMontagePlaybackOwnership`的既有原资源。Succeeded保存原播放；明确NoOwnedPlayback是正常无认证播放，其余失败不改为当前播放或成功。重复请求保留首次Context。

`ResumeOriginalTermination`遇ScopeLock时，只向native WaitingToExecute登记一个绑定原记录的continuation。原调用内解锁只标ready，实际调用返回后消费；继续不改参数/重捕资源，不重复Cancel广播，再次遭锁明确失败，不无限重排或增加Tick/timer。

### 3. 一次原清理与两个原生通知

final End调用一次Context Cleanup，再一次Super::EndAbility。派生先脱原成员/委托/窗口/timer/Mesh恢复义务，再TaskOwnerEnded处理原Task；Task拥有播放、事件与scale清理，GA的K3 capture不接管播放器。

| 时点 | 当前事实 | 可消费含义 |
| --- | --- | --- |
| 项目Cleanup完成 | 原项目资源已经归还，原Task可已Finished/OwnerFinished | 尚不代表UE native ActiveTasks数组已Reset或End全返回。 |
| GA `OnGameplayAbilityEndedWithData` | native End早期广播，保留实际ReplicateEnd/WasCancelled参数；随后才清Active并处理/Reset native Task登记 | 不能据它在同实例立即启动后继。 |
| ASC `OnAbilityEnded` / 原Ended认证 | native数组已Reset；UE NotifyAbilityEnded没有replicate输入，构造的ReplicateEnd固定false；仍有End返回尾部 | 是必要原Ended见证，false不表示GA请求参数被改写。 |
| 项目Completed及调用返回 | 所有原调用/相关Try退出义务齐备；先封存/退休/退Busy，再发布首次Context | 消费者核原身份后可显式新请求，旧栈不修改后继。 |

Gate79 Combo夹具精确读回：触发前两原Task为Active/OwnerFinished=false；GA早通知时仍登记这两原引用，但已Finished/OwnerFinished=true且业务资源恢复；ASC、Completed与返回后登记为0、资源检查通过。此数量是该夹具观察，不是新增生产账本或所有GA的固定要求。

### 4. 全退出后封存与发布

GA记录关联实际Activate/final End/Cancel/dispatcher调用跨度，ASC关联本次原Try。原Ended、native End返回、完整final调用返回、Cancel返回与相关Try尾部退出全部满足后，才允许`TryPublishOriginalTerminationCompleted`：

1. 复制原Context，封存原Notice和同步Try完成结果槽。
2. 清除原依赖，退休匹配原Activation/终止记录并释放Busy。
3. ASC广播原Notice；回调返回后无旧状态写，不覆盖已启动后继。

Completed不保证任意异步资源全idle，不保证网络确认；Task自然结束与GA原请求完成是两种事实。

## 结果与未闭合入口

| 场景 | 当前结果或边界 |
| --- | --- |
| 首次原请求已受理但仍有调用/退出义务 | Accepted，未提供Completed。 |
| 原生锁内受理 | Deferred/ScopeLocked，仅一个原continuation。 |
| 同一原激活重复请求 | AlreadyPending，保留首次Context，不再广播/改参数。 |
| 失效/异源、不可结束/取消或必需K3捕获失败 | 明确Rejected/Stale/Failed与Reason，不清后继或补成功资源。 |
| 原激活来自raw非虚Try/CallActivate，缺受控Try外层来源 | 真实Original/清理可发生；final调用返回不能证明raw外层尾部，UnsupportedEntry、无协议Completed。 |
| PendingRemove/锁内native teardown | 匹配Context只释放原资源，无法认证必要native/完整返回时失败，不增加第二继续或生成Completed。 |
| 活动同实例/原Busy中再次受控Try | Busy/明确原因，拒绝自动Retrigger；不同PerExecution实例不能仅因同Spec一概拒绝。 |
| Task `OnCompleted` / 组空通知 | 不等于项目原Notice，不授权结束后继或自动重开。 |

final入口已替代旧派生End overrides；尚未闭合的是明确列出的来源/移除/极端重入等验证边界，不能再以“派生未迁移”表示当前源码。

## E14-B/C：构造与消费者失败响应

共享Builder保留bool接口。显式空DamageEffectClass是正常无GE Cue模式；非空必需GE/Spec/Def/Context与原来源必须有效，能力扩展返回后也重检。失败false/空输出并定位模块/Ability/Source/Target/GE/原因，不降级Cue、加载替代资源或重试。

Combo命中期间必需GE依赖失效或真实Builder失败，停止该hit的Apply/Cue并直接`RequestAbilityEnd(Original,true,true)`；CanBeCanceled=false场景仍正式End，没有Cancel→End兜底。Boss要求有效GE，保留自身“拒绝该hit的damage/Cue、继续当前动作”的政策，不能从共享Builder推导两者响应相同。有效Spec应用免疫/拒绝后的碰撞Cue语义保持。

Gate79验证显式无GE、有效GE、启动后RequiredGE失效、native Spec扩展使真实Builder失败四Case的行为；故障先保留前一次正常hit，之后不增加Apply/Cue，原Cleanup→GA/ASC/Completed身份/次数/顺序及资源阶段全部通过。未覆盖Shared预载资产失效、底层MakeOutgoingSpec创建失败、正式Execution数值与CueNotify表现。
