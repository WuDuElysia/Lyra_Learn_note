## 已确认的动作规则

- 一个玩家普攻 GA 持有整套连段；每段一个 Montage，默认 `Main → End → 停止`。
- 每段配置一个唯一原生作者点。原播放过点后，真实移动与新的攻击按下均可打断；Main/End 和旧 ComboWindow 不隐式授门。
- 信号前的新攻击明确拒绝，不缓冲、不在过点后重播。信号后的新攻击按唯一 `NextStepIndex` 立即换段；新播放独立关门，`INDEX_NONE` 显式关闭攻击接续。
- 长按不自动连段，首次激活按键不同时充当第二段请求。
- 三段共用 Attack 组、Priority 100；段内推进不重新做能力组准入。独立攻击 GA 的同级窗口取消仍不在首版范围。
- 已持有的真实合格移动可在作者点开放时立即接管；原输入/CMC 继续认证资格和执行胶囊位移。
- 无新请求完整自然收尾，不自动换段或循环。正式目标为 01→02→03→01；自然结束或移动结束后的新受控激活从 01 起手。
- 自然混出起点与时长由 Montage 分别配置；完整 End、原动画与窗口保留。作者点可编辑至 Main 或自然混出期间，不以段名锁定业务时机。

### 必需姿态失败的历史事实

Animation Guard是能力声明与节点状态唯一来源：`AcquireActionPoseContract(Montage,Ticket,Diagnostic)`返回ExplicitNotRequired/RequiredReady/Rejected/Unavailable。显式不需要才走普通Task；RequiredReady须真实唯一Slot、有效原Ticket和失败消费者。缺声明、节点/骨骼/来源不可用、Ticket不一致明确Startup失败，尚无播放InstanceID（INDEX_NONE）。原Ticket不等于播放证明或GA身份。

Required-only `TickTask`由引擎GameplayTasks正常调度，Ready返回并固定GA资源实例ID后才只读Poll。Valid继续；Failed/Invalidated发Playback失败，携原Montage/Slot/实例ID/Diagnostic。Poll前后核原Task/Ability/ActorInfo/ASC/Guard；不靠无效弱Ticket静默跳过、不重领Ticket、不执行姿态或累计播放时间。

失败顺序是**关普通事件/Section/完成入口→精确停止原实例/释放缩放→EndTask注销自身句柄与Ticket→native typed OnFailed**。UE OnDestroy此时已清Task.Ability并正常MarkAsGarbage；GA用捕获WeakTask.Get(true)拒RF_BeginDestroyed/RF_FinishDestroyed，再核自身Original、段token、强MontageTask、原FStepMotionResources、固定Montage/Slot和Startup NONE或Playback原ID。不能要求已清理Task仍Active/有Ability/有效Guard工作权，从而吞掉应当发生的失败通知。

GA必需依赖失败直接 `RequestAbilityEnd(Original,true,true)`，即使原能力CanBeCanceled=false也正式结束；Task不直接执行GA终止或清CMC。Task临时观察同次分发中原GA真实End，native消费者结束原激活或同UObject接续后，旧BP OnFailed不再交付；只有原激活未结束且历史发送资格仍成立才发BP。该事实不是普通Cancelled或Completed，也不授予后继工作许可。OnDestroy保留Tick标志至引擎原登记正常退休，Ticket/注册包/句柄均精确清理。完整接口见 [[AbilitySystem/结构#Task原实例与资源消费|Task契约]]。

### 命中 GE 模式与两条故障链

`ValidateDamageEffectDependency` 在准入、启动和运行命中处校验依赖。每次 hit 只解析一次已选 GE，并把同一次成功结果传给 Builder。

| 模式或失败 | 实际链路与可见结果 | Gate79 覆盖 |
| --- | --- | --- |
| 显式无 GE：DamageEffect 空且 `bUseSharedDamageEffectWhenUnset=false` | 正常模式；Builder 生成 Cue 数据但无必需 Spec，跳过 Apply，合法 Cue 继续 | Case0：Apply0 / Cue1 / SpecExtension0；能力继续到正式手动正常 End |
| 有效必需 GE：显式 Override；或明确选择且预载可用的 Shared | Builder → SetByCaller → ASC Apply → 合法 Cue；应用免疫/拒绝不吞掉已成立命中的 Cue | Case1 只验显式有效 GE：Apply1 / Cue1 / SpecExtension1 |
| 命中期间已选必需 GE 无效/缺失 | 记录模块、GA、Source/Target、段、Montage、配置与原因 → `RequestAbilityEnd(Original,true,true)` → 立即返回，不发送该故障 hit 的 Apply/Cue | Case2 在成功 hit 后选入抽象 Override；故障 Apply/Cue 增量0，原 End/Completed精确一次 |
| 必需 Spec 的 Builder 构造链失败 | 保留 Builder 原诊断及 Combo 故障诊断 → 同一固定 Original 的正式 End(true,true) → 立即返回 | Case3 在真实 Spec 的 ApplyAbilityTags 扩展中使 Def 无效；Exclusive 原能力已明确不可取消，仍通过正式 End 清理；故障 Apply/Cue 增量0 |

非法 Override 不改用 Shared 或无 GE；已选 Shared 缺失也明确失败。E14-C 内部依赖失败直接使用 End，不先 Cancel 再兜底 End。Accepted/Deferred/AlreadyPending 是原请求历史，仍需原生命周期完成，不能当作已清理成功。

这条整动作中止策略属于 PlayerCombo，显式无GE正常模式也只在Combo中验证。BossMelee要求解析出的必需GE与有效必需Spec；生命周期/动作资源失败走原终止，命中期间GE解析或Builder失败只拒绝该次hit的伤害与Cue，详见 [[BossAI/计划_Kevin_DemonBattle战斗接入|Kevin 计划]]。

### Cleanup 与原生结束阶段

`CleanupAbilityResourcesForTermination(Context)` 只处理 `Context.GetOriginalActivation()` 匹配的资源。Combo 先摘下原成员/身份、Pending、段 token、Timer 和订阅句柄，再退原CMC QualifiedMovementIntent observer与Action handle，用捕获的原 World/Trace/Mesh/Task 清 Timer、关原窗口、恢复 Tick/URO/prerequisite、注销原 callbacks，最后对仍需结束的原 Task `TaskOwnerEnded()` 和父类清理。RequiredPose的发送Task已先EndTask，不要求该历史Task重新Active；Gate79普通夹具两Task阶段证据保持，不能外推这条失败路径。后续协议门禁归基类；派生不从“当前激活”猜旧来源。

| 真实时点 | 资源与通知契约 | Gate79 RuntimeHit 实际观察 |
| --- | --- | --- |
| 触发前 | 两个原 Task 必须真实有效/Active/OwnerFinished=false，原生登记恰为两原身份 | Count2，State3(Active)，OwnerFinished0 |
| Cleanup 返回、GA `OnGameplayAbilityEndedWithData` 早广播 | 业务成员/订阅/Window/Timer/Mesh/Montage 已恢复，两原 Task 已 Finished/OwnerFinished；UE 的 ActiveTasks 登记尚未退休 | 业务分项全部通过；仍 Count2 且身份精确，State4(Finished)，OwnerFinished1 |
| UE native End 后续阶段 → ASC `OnAbilityEnded` | native End 遍历任务并 `ActiveTasks.Reset()` 后才通知 ASC | Count0；原任务仍 Finished，所有检查资源恢复 |
| 项目 Completed / 原请求或命中调用返回后 | 原协议完成门禁、固定 Original/Kind/参数及回调退出；资源终态与账本空须分别成立 | Completed一次，顺序 GA→ASC→Completed；返回后能力 inactive、受控激活空、Count0和资源恢复 |

本机 UE5.8 `TaskOwnerEnded` 先置 OwnerFinished，再 OnDestroy；TasksComponent 在 OwnerFinished 时不调用 Owner 的 OnGameplayTaskDeactivated，因此已结束任务仍留在 GA 登记直到 native Reset。Task 的正常垃圾标记不能用来跳过实际 Finished/OwnerFinished 校验；也不能直接清 UE 数组使测试成功。该阶段说明不把任意结束路径的任务数量固定为2。

GA 数据事件保留传入 native Super End 的复制/取消参数；ASC 本地 `OnAbilityEnded` 的复制字段固定为 false，取消字段仍来自该次 End。Gate79 普通夹具的手动 End 使用 `(false,false)`，故障 End 使用 `(true,true)`；生产 Montage 正常完成的复制参数由 Authority 决定。Completed Context 不能替代实际 GA 数据观察，复制参数也不证明网络送达。

raw 的非虚 Try/CallActivate 也可能通过真实 NotifyActivated 签发原身份并清理原资源；缺少原激活外层受控 Try 见证时，最终返回 UnsupportedEntry 且不发布协议 Completed。不能把所有直接 End/Cancel 都归为 Unsupported；判断关键是 Original 的受控 Try 来源，详细证明归核心计划。

新的 B 从 A 原请求与观察回调均返回后的受控调用方继续启动；不能在原生 `OnAbilityEnded` 内 raw Try 重新激活并宣称边界已完成。原终止共享机制见 [[GGYGO_流程_原请求终止.canvas|原请求流程]]。
