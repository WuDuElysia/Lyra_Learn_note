## 已确认的动作规则

- 一个玩家普攻 GA 持有整套连段的状态；每段一个 Montage，默认 `Main → End → 停止`。
- 请求在窗口内立即推进下一段；窗口可以延伸到 End 前部，具体由资产标记。第三段完成后重新从第一段起手。
- 同时最多保存一个带有效期的下一段请求；每次成功推进只消费一次。窗口关闭、取消、结束清除缓存。
- 输入必须是实际按下边沿；长按不自动产生后续段。首次激活按键不能同时充当第二段请求。
- 三段同 Priority 100；GA 内换段不重新进行组激活。独立 GA 间的同级窗口取消不在首版实现范围，D4 与组仲裁保持现状。

## 原生接口与职责（第04批 Combo 代码已冻结，第二轮完整构建及第五次统一自动化 3/3、0 warning 通过）

`UGGYGOPlayerComboAbility : UGGYGOGameplayAbility` 管理段序、窗口、单请求缓存、输入任务、Montage 任务、命中和统一清理。`FGGYGOComboStep` 配 Montage、Main/End Section、NextStepIndex、播放率、伤害及 Socket/Radius；首版为 GA 默认值数组，不额外创建通用连招图编辑器或 Intent UObject。

`FGGYGOComboWindowState` 分开保存 `bOpen`、`bClosed` 和唯一 `PendingRequestId/ExpiresAt`；开窗前允许预输入，关窗后不再接受本段请求。`UGGYGOAbilityTask_WaitComboInput` 在整个激活期间监听 GAS `InputPressed`，不测试激活键的已按下状态；`SetSourceStep` 随换段更新请求来源。`AGGYGOHeroCharacter` 已创建 `MeleeTraceComponent` 默认子对象。

```text
ActivateAbility:
  新本地激活代次、清初始状态 → Super → 核对代次
  验证配置与 Avatar → CommitAbility → 核对代次 → StartStep(0)
  等待新的 InputPressed（忽略激活时已按下状态）
HandleInputPressed:
  若本段已关窗/没有下一段 → 丢弃
  否则 Pending = 本次请求，记录到期时间
  TryAdvanceCombo()
HandleMontageEvent:
  校验事件来自当前 Montage
  ComboWindowBegin → 开窗 → TryAdvanceCombo()
  ComboWindowEnd → 关窗且清缓存
  HitWindowBegin/End → 服务器 BeginTraceWindow/EndTraceWindow
TryAdvanceCombo:
  若未开窗、请求过期或下一段无效 → 不切换
  消费请求 → 关闭旧判定 → 解绑旧任务 → StartStep(next)
OnCompleted → EndAbility
OnInterrupted/OnCancelled/Avatar失效 → 统一取消并清理
```

默认 Main→End 由 Montage Section 链接承担；即使缺少连段通知也能自然收尾。主动切段要先解绑旧播放的业务回调，防止旧 OnInterrupted 取消新段。Notify 对象不能保存角色级可变状态；GA 必须校验来源并自行兜底清理，不能依赖 NotifyEnd 一定到达。

Montage NotifyState 配 `Event.Montage.ComboWindowBegin/End` 和独立命中窗口。播放率传入 ASC 的 Montage 播放路径，窗口跟随动画时间；不用固定 Delay 代替窗口。AnimBP 仅负责匹配的 Slot、与移动状态的表现混合。素材裁剪、接缝、混合时长在资产中调校，不能把原始长 End 全部等同于不可操作硬直。

## 网络与异常契约

- 玩家 LocalPredicted，输入使用 GAS 复制事件任务；服务器验证段序和窗口，服务器独占伤害结算。
- 客户端与服务器都运行连段状态；拒绝/取消必须恢复窗口、缓存、Trace 和动画。预测段分歧须有显式纠正，不能把普通 GameplayEvent 当作网络消息。
- 服务器依赖 Notify 与 Socket 时确保 Mesh 动画 Tick/骨骼刷新；跨段主动切换后旧事件不得重新打开判定。
- 缺少下一段时保留当前 Main→End；当前 Montage 无效、播放失败、Avatar 丢失时结束能力，释放占用。
- 位移按 D3 归 CMC；检查攻击动画现有根轨迹与 locomotion 曲线驱动的冲突。首版不自动引入 MotionWarping、时间回溯或另一套位移权威。

### 已编码的输入复制与纠正

`WaitComboInput` 用 `ServerSetReplicatedEventWithPayload` 发送 `VectorPayload.X=SourceStep`、`Y=RequestId`。服务器先消费事件，再回调 GA；只接受有限整数、匹配当前段且递增的请求号，防止同一次请求重复推进。请求号范围为 1–65535，每次能力激活重置。

服务器接受换段或拒绝请求时，由 `UGGYGOAbilitySystemComponent::ClientCorrectAbilityState` 可靠 RPC 传输 SpecHandle、原始激活预测键和 GAS `FGameplayAbilityTargetDataHandle`。载荷 `FGGYGOComboCorrectionData` 归 Combo 所有，包含递增 Revision、请求号、服务器段序、播放位置及窗口状态；使用 GAS TargetData 序列化机制。

ASC 只筛选活动 Spec、活动实例及匹配的预测键，调用基类 `ReceiveAbilityCorrection` 虚接口；不引用或转换为 PlayerCombo。Combo 验证载荷恰为一项、确切结构类型、有限数值/有效段/窗口组合，再由 `CorrectPredictedStep` 忽略旧 Revision，拒绝时回到服务器段，接受旧请求不会撤销更新的本地预测。当前没有客户端时间戳宽限或回溯；本批新增传输的构建、序列化回归及联机延迟边界尚未实测。

### 来源过滤与生命周期

`GameplayEventWindow` 在 payload 的 `OptionalObject` 传动画资产、`OptionalObject2` 传 Mesh，有 Montage 上下文时用 `EventMagnitude=MontageInstanceID+1` 标记实例。Montage Task 拒绝其他 Montage/实例、已混出或失去 ASC 动画所有权的通知；GA 再验证当前段 Montage 与主 Mesh。

发送入口先查询 Owner 的 ASC：没有 ASC 的 Persona/非游戏世界预览静默返回；PIE 或游戏世界缺少 ASC 则记录带 Actor、Tag、动画路径的警告后返回。有 ASC 时保持原 GameplayEvent 发送路径及 payload，不按世界类型屏蔽有效事件。守卫已完整构建并在重启后的 Persona 第一段预览中逐帧跨越命中/连段窗口，日志无 Invalid ability system component，也未产生游戏世界缺 ASC 警告；真实 GA 事件与缺 ASC 游戏场景尚未运行验收。

换段先关 Trace、解除旧任务全部业务回调，再结束旧任务并播放下一段，避免旧中断事件取消新段。服务器激活期间强制 Mesh Tick/骨骼刷新、关闭 URO，并让 Trace Tick 依赖 Mesh；`EndAbility` 关闭 Trace、解除输入/命中/动画监听、清理兜底计时器并恢复 Mesh 原设置。兜底计时器仅处理完成回调丢失，不模拟动作窗口。

第04批增加本地激活代次，独立于可为零的预测键。Super、Commit、Montage/Input Task Ready 的同步返回点核对代次；段启动及 watchdog 还绑定段 token/任务身份。旧调用发现能力已结束、重激活或换段后退出，不清理后继资源。

End 先检查引擎 `IsEndAbilityValid` 与 ScopeLock；需要延期时保留代次，不能让旧延期结束新激活。真正清理先摘实例字段，使用捕获的旧 Trace/Mesh/Task 关闭窗口、恢复 Tick/URO、解绑全部业务委托并 `TaskOwnerEnded`，最后调用 Super；Super 的结束广播后不再写实例状态。

已定位的引擎限制：UE 5.8 `ASC::PlayMontageInternal` 在 `AnimInstance::Montage_Play` 同步回调之后才写 ASC 动画记录并跳转 Section。若回调嵌套启动后继播放，外层仍可能覆盖后继记录或位置。Task 生命周期保护不能阻止该引擎内部写回；任意不同 Montage/Section 的启动重入及相应预测拒绝路径尚未解决，不能用本批代次保护或历史构建宣称通过。
