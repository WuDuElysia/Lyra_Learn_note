>
> 当前检查点（2026-10-06）：实现、ABP 单包接线及约定必要测试完成。最终姿态证据仅覆盖 Normal01 Main；故障行为断言和 Automation 的真实 Fail 分开记录。本文说明当前最低能力契约，不把任意骨架、混合模式或网络列为已验收。

## 1. 根因与选择

原主图的 `ModifyBone(Bip001)` 在 FullBody Slot 后，以组件空间 Replace 固定整个 Translation 为 `(0,0,50.801998138427734)`。它保持网格对齐，同时抹去攻击 Body 的垂直姿态。只把 Slot 移到修正之后会重新带入原素材的绝对平移，不能可靠区分身体姿势和胶囊运动。

当前把组件对齐与动作 Body Z 分离放入继承原生 `FAnimNode_Slot` 的 `FGGYGOAnimNode_ActionPoseSlot`：借用原生同次实际参与的 Source，利用当前 Mesh 的固定参考祖先基底分离 Body／轨迹骨 Z，再输出对齐后的 Body translation。原生 Slot 继续管理播放、姿态混合和通知；GA／CMC 继续管理动作位移及其资源。没有第二 pose mixer、源时钟或按角色招式写死的 C++ 分支。

## 3. 最低能力与原参考基底

`BuildReferenceCache/CheckCapability` 只接受当前主 Mesh 的真实 `RequiredBones` 与参考姿态：

- Body、Trajectory 不同且分属独立分支，实际 CompactPose／当前 LOD 都必须保留，祖先索引也必须有效。
- 参考 TQS 有限、旋转归一、Scale 非奇异；祖先必须满足固定当前 Mesh 参考基底。节点在实际 Source／混合 pose 中核对祖先；压缩容差只用于校验，不钳制或替换 Body Z。
- 当前支持非 Additive、均匀混合；拒绝资产 BlendProfileIn/Out 和实际 instance 的 ActiveBlendProfile。
- Slot track 非空且每段为普通 `UAnimSequence`，不得启用 native RootMotion。Editor 显式检查 DataModel 的 Body／Trajectory 轨道；非 Editor 路径检查压缩数据及轨道映射，不能据 Editor 测试宣布 Cook 分支已验。

Pyrios 的两条分支为 `Bip001 → Bone_Root → 模型根` 与 `Root → 模型根`。Gate95 在当前 Mesh 读得参考根 Scale=1；独立 Skeleton 参考根 Scale=100，两者不能混用。节点的参考量只来自当前 Mesh，缺 Root CompactPose 不采用 helper reference 替代。

正常 CacheBones／LOD 索引重建更新索引；逻辑配置与参考值未变时不因索引变化自动换 epoch。失去必需骨是能力失败；角色骨／Slot／对齐值、AlwaysUpdate、模型或有效参考值改变才按配置变化处理。epoch／failureSerial 不回绕；耗尽明确不可用。

## 4. 同次原生 Slot 的 Z 分离

原生 `FAnimNode_Slot::Update_AnyThread` 负责真实权重与 Source 更新；派生节点不再次 Update/Evaluate Source。`Evaluate_AnyThread` 先清临时量，调用 `Super::Evaluate_AnyThread(Output)`，通过原生受保护的 `PostEvaluateSourcePose` 借用**同次已求值且参与**的 Source 残差，退出时再次清理。

原生在 SourceWeight≤阈值时不求值 Source，却仍可能调用 hook。节点此时不读 SourceContext；AlwaysUpdateSourcePose 只保证 Update，并不改变这个 Evaluate 门槛。无有效动作贡献时仅采用角色原组件对齐值。

设 `Bp/Rp` 为当前 Mesh 参考姿态中 Body／Trajectory 的父链基底；它们包含参考旋转与缩放。定义：

```text
Q(P) = Bp.TransformVector(P[Body].Translation).Z
     - Rp.TransformVector(P[Trajectory].Translation).Z

u = SourceWeight > ZERO_ANIMWEIGHT_THRESH ? clamp(SourceWeight,0,1) : 0
d = TotalNodeWeight > 1 + ZERO_ANIMWEIGHT_THRESH ? TotalNodeWeight : 1
v = TotalNodeWeight / d

Target.XY = ComponentAlignment.XY
Target.Z  = ComponentAlignment.Z + Q(native slot output) - u*Q(actual source) - v*Q(mesh reference)
```

这里的 native slot output 是 `Super` 已混合完成的局部 pose，不是某一 clip 单独求值；`v` 来自原生 TotalNodeWeight 的有效除数，不能机械替换成 SlotNodeWeight。节点核对公开 `GetSlotWeight` 与本轮继承 WeightData 完全一致、SourceWeight+SlotNodeWeight 为纯 nonadditive 关系；祖先平移／Scale 按 `u+v` 核对，旋转按参考核对。

最终用**实际输出 pose 的 Body 父链** `InverseTransformPosition(Target)` 转成 local translation，只写 `Output.Pose[Body].SetTranslation`；Body Rotation/Scale、Trajectory pose 与其他骨保持原生输出。此公式去除 Source 和动作参考高度贡献，保留动作相对轨迹骨的 authored Z；负 Z 合法，不做地面钳制、clip 首帧归零或按招式兜底。

GT 的 Guard 在原引擎 `NativeUpdateAnimation` 中检查已参与的实际 Montage 输入；只向节点发布 bool／诊断、原 provider 弱身份和已有 native UpdateCounter。worker 用 `WasSynchronizedCounter` 验证同轮／原生一次 Update 前后允许的边界，不读 MontageInstances 或 proxy 受保护的 evaluation array，也不复制权重作为另一权威状态。原生 `OnInitializeAnimInstance` 清 publication；延迟 worker Initialize 只清 pose/cache/scratch，保留该轮 GT publication，仍受原 provider/counter 限制。

任何条件失败均 `RecordFailure`：锁存明确原因并推进 failureSerial，按原因变化节流 Error；输出引擎合法的诊断 reference pose，并由契约终止原动作。这不是动作成功、默认姿态替换或继续运行的业务兜底。

## 5. Acquire、Poll 与原失败清理

| 阶段／接口 | 条件与结果 |
| --- | --- |
| `AcquireActionPoseContract(OriginalMontage, OutTicket, OutDiagnostic) const` | GT 原并行评估完成屏障前后重验 lifecycle／Owner／主 Mesh／模型／角色声明；用原编译 `IAnimClassInterface` properties 唯一找到同 Slot producer，核对 current cache、真实轨道与能力。成功返回 RequiredReady 及一次原票据；不强制 pose 求值。 |
| `ExplicitNotRequired` | 原 Montage 不用 correction producer 且角色未要求该 Slot 时，是明确普通 native Slot 模式，无票据／轮询。 |
| `Rejected/Unavailable` | correction producer 未匹配角色声明、重复 producer、非法 Montage → Rejected；原上下文或必需骨/cache/capability 不可用 → Unavailable。失败清 OutTicket，Task Startup 失败，禁止先播后等。无隐式等待／默认资源。 |
| `PollActionPoseContract(OriginalTicket, OutDiagnostic) const` | 原 lifecycle／Owner／Mesh／模型／角色或节点配置换代 → Invalidated；故障序号超过 acquire 基线或当前必需能力失败 → Failed；其余 Valid。旧票据不升级，RequiredReady 不承诺未来 Evaluate 成功。 |

Task 在 Ready 前必须登记 OnFailed 消费者。只有 RequiredReady 开启自身原生 GameplayTasks `TickTask`，不累计 DeltaTime；invalid ticket 也进入 Poll，不能因 `IsValid=false` 静默跳过。

失败顺序为：捕原失败事实 → 封闭自身失败入口并保存原回调 → 精确原 Guard/Handle 停止、归还 scale lease → EndTask/OnDestroy 释放自身监听、委托与票据 → 同步历史 OnFailed → 原 GA 验证并 `RequestAbilityEnd(Original,true,true)`。Startup 事实的 instance 为 INDEX_NONE；Playback 事实须匹配原 instance。正常用户 Cancelled／Interrupted 路径保持独立语义。

引擎 EndTask 会清 Task.Ability 并标记 Garbage；历史失败发送者仍须读取剩余原对象，使用 `WeakTask.Get(true)` 且拒绝 RF_BeginDestroyed/RF_FinishDestroyed。Task 验证原 ActivatedAbility/ASC，并在当前清理／派发栈观察原 GA 是否已经 End，防止同 UObject 再激活吞入旧事实。GA 专用接收者不要求已退休 Montage 活动或 Task Active，而核对自身原 Activation、step token、Task 和资源；强制 End 不受 CanBeCanceled=false 阻止。停止旧对象不取得后继资源权。

## 6. 已保存接线与 CMC 胶囊边界

`/Game/BP/Anim/ABP_Pyrios` 实际主图：

```text
MainStateMachine → GGYGO Action Pose Slot (FullBody)
                 → 原 LocalToComponentSpace → 原 ComponentToLocalSpace
                 → 原 Inertialization → Output Pose
```

旧普通 FullBody Slot 和旧 Bip001 ModifyBone 均删除，避免双重修正。新节点配置 `Bip001/Root`、`AlwaysUpdateSourcePose=true`、完整 `ComponentAlignment=(0,0,50.801998138427734)`；角色 CDO `RequiredPoseCorrectionSlot=FullBody`。原父类 UZZZAnimInstance、AnimSet／Tuning、RootMotionMode=IgnoreRootMotion 和其余 24 张图保持，未调整 Sequence／Montage／RootLock／PosXYZ。

GA 另用 `GGYGOActionMotionSource::BuildSourceBinding` 解析原 Montage/FullBody/Main，再按精确播放 snapshot 申请 CMC `BeginMontageActionMotion`。Animation source binding 只保资产配置与映射；Movement 在自身区间读取原 `RootMotion_PosX/Y/Z` 差值，原 ActionCurveRMS/CMC 执行胶囊。Section 变化、完成、替换或失败由 GA 释放自己的句柄；准入移动取消使用 `CancelMontageActionMotionForMovement`。姿态 Q/Body Z 不发送给这条 XYZ 链。

当前普攻源曲线 Y/Z 为零的采样不构成删除轴的理由；Z 仍是独立胶囊曲线轴，重力／碰撞／移动模式沿原生 CMC。RMS 退休不必清零已应用的物理 Velocity；无输入的原生动量与未准入驱动由 Movement 单独判断，不能要求姿态层清速度。接口与制动、FAILED、后继隔离见 [[Movement/结构]]、[[Movement/动作曲线执行]]；原 GA 资源见 [[AbilitySystem/结构]]。

## 8. 排查顺序

| 现象 | 优先核对 |
| --- | --- |
| 攻击 Body Z 又固定在50.802 | ABP是否仍串旧ModifyBone、是否有双Slot；实际最终buffer与Inertialization；角色节点与声明是否匹配。 |
| 启动被Required契约拒绝 | 原ABP CDO FullBody、唯一compiled producer、当前Mesh CacheBones/Body/Root CompactPose、实际源轨道和BlendProfile；按诊断修配置，不改成None绕过。 |
| Main中途Pose失败却资源不退 | Task原生Tick是否因RequiredReady登记，historical OnFailed是否Ready前订阅；原Activation/step/Task验证与GA强制End；各模块只清原资源。 |
| 网格动了但胶囊错误／失败后仍滑动 | 原Main source binding、CMC实际PosXYZ区间与原句柄／RMS；区分原生物理动量与未准入输入。节点不负责物理速度清零。 |
| Runtime测试Behavior PASS但报告Fail | 保留真实生产Error，检查行为断言及源诊断；不能滤Error、放宽断言或把局部PASS写成全报告Success。 |
