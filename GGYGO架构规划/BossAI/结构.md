## 14a：选招配置与短期请求（完整构建、三项专项自动化通过）

本批仅处理 E10/E11。`ValidateConfiguration(OutError)` 对所有行检查 Tag 唯一、能力类及其 ActionTag 一致、有限数值和有效范围；编辑器 `IsDataValid` 复用同一规则，无效集合整体拒绝并给出原因。空集及全基础权重为零是合法无动作配置；禁用行仍须通过配置校验。`MaxDistance=0` 表示不限远距，有效权重上限保持 `max(MaxWeight, BaseWeight)`。

`BaseWeight=0` 永远不进入候选。先按目标与 GAS 准入筛选，再由 `SelectAction` 使用 Encounter Seed 初始化的随机流抽签；所有合格候选惩罚权重耗尽时，仅恢复这些候选的基础权重并继续本次选择。因此 `RepeatPenalty=0` 是软避重，唯一合法动作仍可继续选择。无合法候选不消耗随机数。权重随 ActionSet 来源改变而失效，不建立冷却镜像或定时恢复器。

Controller 的短期记录包含 Set/Phase/ASC/Tag/Class/Spec/Avatar 身份，UObject 来源用弱引用。记录只服务一次请求，成功或失败消费后都失效；重选、重置随机种子、Possess/UnPossess 和 EndPlay 也清理。消费前重新验证全集和来源；原 Spec 已移除、同类重授、来源变化均拒绝，不按 Tag/Class 换成另一动作。Blackboard 的 `SelectedAction` 仅用于原有行为树的语义传递，未新增键或修改资产。

## 14b：Encounter创建责任与回收（完整构建、两项专项自动化通过）

Encounter独立保存三份类型化弱创建记录：`CreatedBossState`、`CreatedBossController`、`CreatedBossAvatar`，均由自己的真实Spawn返回值立即登记。公开`BossState/Controller/Avatar`在装配完成时发布，供调用方访问；创建记录决定回收责任，不从Actor Owner或State的当前Avatar推导。当前Avatar可以已换成外部Pawn；初始创建Avatar即使Owner改变，仍在回收范围内。

`SpawnBoss`仅Authority可启动。已有对象/创建记录、装配或清理中、Encounter正在销毁或EndPlay后均拒绝。当前实际装配为State Spawn/定义初始化 → Controller Spawn/决策Seed初始化 → Deferred Avatar Spawn/注入PawnData → State `AttachAvatar` → `FinishSpawningActor` → Controller `Possess` → 一致性核对并发布三引用。关键回调后复核Encounter、三创建记录与对象有效性，避免回调已清理/EndPlay后旧调用栈仍报告成功。

生成失败的`FailSpawn`与`EndPlay`共用protected `CleanupCreatedBoss`，顺序见[[GGYGO_流程_BossAI.canvas|主流程撤场分支]]：

1. 快照三创建对象，清空公开引用与创建记录，先进入同步清理守卫。
2. 有效Controller清短期请求，通过有效Brain调用`StopLogic`，随后对仍有效且有Pawn的Controller `UnPossess`。
3. 有效State若有当前Avatar，调用`DetachAvatar(CurrentAvatar)`；ASC/PawnExtension解绑唯一归宿主接口，Encounter不直接写ActorInfo或复制ExpectedASC清理。
4. 每步重新检查有效性，依次仅Destroy明确创建的Avatar、Controller、State；外部当前Avatar只解除关系，保留对象，即使Owner指向Encounter也不销毁。

`bSpawningBoss`、`bCleaningUpBoss`仅保护同步重入；`bEndingPlay`阻止EndPlay后再生成，不是Boss阶段/动作状态机。公开引用已空时，清理回调仍不能重入Spawn；重复清理及对象提前失效不会重复释放。失败回滚后可重试，EndPlay后不可重试。本次不实现创建责任转交、完整换形态事务、奖励或脱战重置。

两项测试已冻结并由统筹执行通过：`GGYGO.BossAI.Encounter.CleanupLifecycle`与`GGYGO.BossAI.Encounter.ExplicitCreationOwnership`，各自Success、errors/warnings均0。真实Spawn覆盖成功/重复拒绝、部分失败/重试、装配与清理重入、提前失效、Owner变化及外部Avatar保留；可观测Brain/Pawn/解绑通知/OnDestroyed记录实际调用顺序。夹具初始化Actor但不BeginPlay，显式调用真实Encounter EndPlay，不以无BeginPlay的Destroy冒充引擎EndPlay派发验收。

| 非空 | 任意 | 始终使用覆盖；其余配置与执行门禁仍须满足。 |

## 原激活与资源收尾（当前契约）

生命周期唯一归[[AbilitySystem/计划_原请求终止|GA/ASC原请求终止契约]]。公共 `CanActivateAbility` 及 `ActivateAbility/EndAbility/CancelAbility` 已为final；Boss不覆盖原生入口，也不另建Active/Ending/Completed状态或帧调度器。正常配置、蓝图业务与原资源职责仍在Boss派生。

1. `InitializeAbilityActivation(Original)` 接收原生发行的固定原身份，在组/Camera最终处理及Body之前建立唯一 `FOriginalMeleeResources`。原ASC/Avatar/World及接收者用弱引用保存；它是资源与来源记录，不发行生命周期权限。
2. `ActivateAbilityBody(Original,…)` 只调用一次父Body/BP；在外部回调后核对原身份与接收者，再校验/Commit。实际原Task在Ready前登记 `RegisterNativeCallbacks` 的N0包；闭包固定Original、弱原Task及资源批次，卸包只撤原token。原World watchdog在CMC/Ready外调前登记；可选Profile经共享`BeginOriginalMeleeMotion`启动并观察失败，原CMC执行，GA只持原MotionHandle。
3. Montage事件只消费原Montage/主Mesh与Task资格。Owned Trace开窗返回原Window，`SubscribeWindowHit`返回原命中token；窗口、原Trace和原Activation共同限定命中。资源失效或外调返回后属于旧批次时，只向原接收者释放迟到句柄，不能清后继资源。
4. `CleanupAbilityResourcesForTermination(Context)` 匹配批次的固定Original；先脱离整个成员批次，再恢复原Mesh Tick/URO与自有prerequisite，清原World timer、原N0包、原Window/hit token、原CMC句柄及原Task，最后调用父Context Cleanup。清理不捕获当前激活冒充来源，释放后不写后继成员。
5. 正常Montage完成用 `RequestAbilityEnd(Original,…,false)`；启动/配置/原Profile运行失败经`FailOriginalAction`用`RequestAbilityEnd(Original, true, true)`记录Cancelled；中断及watchdog用 `RequestAbilityCancel(Original,…)`。返回结果字段为 `Outcome/Reason`；拒绝明确诊断，不能换Original、重试另一能力或强制End。当前激活查询只用于原准入比对，不能替换来源。

### Profile动作接缝（M3）

原Profile配置/采样非法时，CMC先中性化原RMS贡献、标记退场，摘下原动作槽与失败观察，再至多一次同步回调原Handle/Reason。GA回调核对固定原资源批次、弱原CMC身份及句柄；`FailOriginalAction`只请求该Original结束，不以已经清空的`HasActiveActionMotion`或旧资源工作许可阻断失败传播。资源归属由`OwnsOriginalResources`检查，继续执行资源工作另须`CaptureCurrentActivation`；原End资格仍由GA/ASC判断。同Binding合法Refresh不续签旧工作，组合失败场景尚未动态验证。清理先摘批次，后续外调不写后继成员。

Profile保留明确的服务器地面水平模式：累计曲线经捕获的Mesh基准变换后由CMC执行XY，Z不参与胶囊动作位移；离地、合法零间隔与原生末帧沿正常规则，Profile不发布完成回调。未配置可选Profile为明确无动作位移模式；已配置但无效必须失败，不替换固定速度、Montage或另一资源。未迁移统一动作资产，详见[[Movement/动作曲线执行|动作模式与清理契约]]。

### 原完成等待与有限验收

BT自己的 `FAbilityWait` 只持弱原ASC/BT接收者、固定Original及Completed订阅token。订阅先于受控Try；早期通知尚无返回身份时不猜测匹配，同步完成只消费Result中封存的原历史。异步 `HandleTerminationCompleted` 只匹配原Original，先清订阅再 `FinishLatentTask`；正常为Succeeded，取消为Failed。Abort/销毁只释放本等待，不替GAS取消能力；`bNotifyTaskFinished=false`，无来源的原生OnTaskFinished不再负责清后继等待。

原Completed要求原native End、完整final End/Cancel及相关受控Try调用全部返回后由ASC发布；它是原历史，不等于当前Idle或重开许可，后继仍须走受控Try准入。原生raw Try/CallActivate仍可在实际NotifyActivated签原身份并Cleanup；缺的是受控Try外层返回见证，最终为UnsupportedEntry且无协议Completed。不能把任一直接End/Cancel都称作Unsupported；细节只归核心终止契约。
