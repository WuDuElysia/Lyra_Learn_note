当前装配是 `BossEncounter → BossState(Owner/ASC) + BossCharacter(Avatar) + BossAIController(Brain)`。14a 的决策输出是 ActionTag 和来源受校验的原 SpecHandle；[[AbilitySystem/结构|ASC]] 负责激活，GA/GE 执行伤害，[[Movement/结构|CMC]] 负责移动。目标/仇恨、转阶段、替换 Pawn 的完整事务是 [[计划_BOSSAI]] 的后续阶段，相关子图明确标记为目标设计。

## 决策与执行接口契约

| 调用方 → 接口 | 输入 / 前提 | 作用与输出 / 副作用 |
| --- | --- | --- |
| Encounter → `BossState::InitializeFromDefinition(Data)` | BossDefinition 中全形态能力及初始 Form/Phase | 初始化持久 ASC/属性/标签；随后 `AttachAvatar(Pawn)` 把当前实体作为 Avatar。 |
| Encounter → `Controller::ClearActionSelection`、`GetBrainComponent()->StopLogic(Reason)`、`UnPossess` | 显式创建记录中的有效Controller；Brain/Pawn可能为空 | 清一次性决策请求、请求Brain最终停止并解除Possess。StopLogic先于解绑/销毁；调用返回不代表实际BT异步Abort已完成。 |
| Encounter → `State::DetachAvatar(CurrentAvatar)` | 创建State的当前Avatar，可能是外部Pawn | 仅经[[Combatants/结构|宿主公共契约]]解除绑定，由宿主/PawnExtension负责ExpectedASC身份安全清理；不把外部Avatar纳入销毁范围。 |
| BT → `ChooseBossAction::ExecuteTask` | 当前 Phase 的 ActionSet、Blackboard Target、ASC | 全集校验后过滤 Tag/距离/角度/视线及 `CanActivateAbilityByHandle`；`SelectAction` 抽签，`StoreActionSelection` 保存原候选 Spec 身份，Blackboard 仅写 Tag。14a 已编码冻结。 |
| BT → `ActivateAbility::ExecuteTask` | Blackboard ActionTag、Controller 一次性请求、当前来源 | `ConsumeActionSelection` 成功才向 `TryActivateAbility` 提交原 Handle；失败也消费请求。等待该 Spec 结束并解绑。14a 已编码冻结。 |
| BossMeleeAbility → `MeleeTrace::BeginTraceWindow/EndTraceWindow` | Montage Event、Socket 和 Radius | 管判定窗口；`OnMeleeHit` 只回传命中，能力负责生成 GE/Cue。 |
| BossMeleeAbility → `UGGYGOGameData::ResolveDamageGameplayEffect(DamageEffect, bUseSharedDamageEffectWhenUnset)` | 非空覆盖优先；开关蓝图可配且默认false | 只选择GE类；空覆盖且不开共享、或开共享但快照缺失均返回空。配置校验与命中复用规则，缺失类不生成载荷/GE/Cue。 |
| BossState → `DetachAvatar(ExpectedPawn)/AttachAvatar(NewPawn)` | 切形态前后的两个 Pawn | 底层现有换 Avatar 契约；完整转阶段锁、失败回滚及 Brain 恢复仍是目标方案，未实现。 |

Boss 不必复用玩家 Hero 输入或 Squad；只复用 `CombatantState` 的 ASC 宿主接口。[[GGYGO_流程_Boss选招.canvas|当前选招]] 与 [[GGYGO_流程_Boss换形态.canvas|目标事务]] 的状态不可混淆。

## 14a：选招配置与短期请求（完整构建、三项专项自动化通过）

本批仅处理 E10/E11。`ValidateConfiguration(OutError)` 对所有行检查 Tag 唯一、能力类及其 ActionTag 一致、有限数值和有效范围；编辑器 `IsDataValid` 复用同一规则，无效集合整体拒绝并给出原因。空集及全基础权重为零是合法无动作配置；禁用行仍须通过配置校验。`MaxDistance=0` 表示不限远距，有效权重上限保持 `max(MaxWeight, BaseWeight)`。

`BaseWeight=0` 永远不进入候选。先按目标与 GAS 准入筛选，再由 `SelectAction` 使用 Encounter Seed 初始化的随机流抽签；所有合格候选惩罚权重耗尽时，仅恢复这些候选的基础权重并继续本次选择。因此 `RepeatPenalty=0` 是软避重，唯一合法动作仍可继续选择。无合法候选不消耗随机数。权重随 ActionSet 来源改变而失效，不建立冷却镜像或定时恢复器。

Controller 的短期记录包含 Set/Phase/ASC/Tag/Class/Spec/Avatar 身份，UObject 来源用弱引用。记录只服务一次请求，成功或失败消费后都失效；重选、重置随机种子、Possess/UnPossess 和 EndPlay 也清理。消费前重新验证全集和来源；原 Spec 已移除、同类重授、来源变化均拒绝，不按 Tag/Class 换成另一动作。Blackboard 的 `SelectedAction` 仅用于原有行为树的语义传递，未新增键或修改资产。

统筹已完成UHT、完整C++编译/链接与三项BossSelection自动化（统一门禁`ModuleRepairGate_20260930_9`，项目38/38、0 warning/error）；证据见项目 `AAADocs/Module_Repair_14a_Validation.md`。这些测试直接调用ActionSet/Controller接口，真实BT→GAS正常结束/取消/Abort、黑板观察者重入、生产资产与PIE仍待验。完整阶段/仇恨/换形态和Kevin资产接线不在14a完成范围内。

## 14b：Encounter创建责任与回收（完整构建、两项专项自动化通过）

Encounter独立保存三份类型化弱创建记录：`CreatedBossState`、`CreatedBossController`、`CreatedBossAvatar`，均由自己的真实Spawn返回值立即登记。公开`BossState/Controller/Avatar`在装配完成时发布，供调用方访问；创建记录决定回收责任，不从Actor Owner或State的当前Avatar推导。当前Avatar可以已换成外部Pawn；初始创建Avatar即使Owner改变，仍在回收范围内。

`SpawnBoss`仅Authority可启动。已有对象/创建记录、装配或清理中、Encounter正在销毁或EndPlay后均拒绝。当前实际装配为State Spawn/定义初始化 → Controller Spawn/决策Seed初始化 → Deferred Avatar Spawn/注入PawnData → State `AttachAvatar` → `FinishSpawningActor` → Controller `Possess` → 一致性核对并发布三引用。关键回调后复核Encounter、三创建记录与对象有效性，避免回调已清理/EndPlay后旧调用栈仍报告成功。

生成失败的`FailSpawn`与`EndPlay`共用protected `CleanupCreatedBoss`，顺序见[[GGYGO_流程_BossAI.canvas|主流程撤场分支]]：

1. 快照三创建对象，清空公开引用与创建记录，先进入同步清理守卫。
2. 有效Controller清短期请求，通过有效Brain调用`StopLogic`，随后对仍有效且有Pawn的Controller `UnPossess`。
3. 有效State若有当前Avatar，调用`DetachAvatar(CurrentAvatar)`；ASC/PawnExtension解绑唯一归宿主接口，Encounter不直接写ActorInfo或复制ExpectedASC清理。
4. 每步重新检查有效性，依次仅Destroy明确创建的Avatar、Controller、State；外部当前Avatar只解除关系，保留对象，即使Owner指向Encounter也不销毁。

`bSpawningBoss`、`bCleaningUpBoss`仅保护同步重入；`bEndingPlay`阻止EndPlay后再生成，不是Boss阶段/动作状态机。公开引用已空时，清理回调仍不能重入Spawn；重复清理及对象提前失效不会重复释放。失败回滚后可重试，EndPlay后不可重试。本次不实现创建责任转交、完整换形态事务、奖励或脱战重置。

两项测试已冻结并由统筹执行通过：`GGYGO.BossAI.Encounter.CleanupLifecycle`与`GGYGO.BossAI.Encounter.ExplicitCreationOwnership`，各自Success、errors/warnings均0。真实Spawn覆盖成功/重复拒绝、部分失败/重试、装配与清理重入、提前失效、Owner变化及外部Avatar保留；可观测Brain/Pawn/解绑通知/OnDestroyed记录实际调用顺序。夹具初始化Actor但不BeginPlay，显式调用真实Encounter EndPlay，不以无BeginPlay的Destroy冒充引擎EndPlay派发验收。

## 15F：Boss近战伤害GE选择（已构建，未专项动态验证）

`UGGYGOBossMeleeAbility`保留原`DamageEffect`覆盖字段，新增蓝图默认`false`的`bUseSharedDamageEffectWhenUnset`，现有空配置不会自动启用共享伤害。`ValidateMeleeConfiguration`与`HandleMeleeHit`均调用同一`UGGYGOGameData::ResolveDamageGameplayEffect(覆盖, 显式bool)`；Montage、Socket、数值、动作配置及激活生命周期门禁保留，命中仍先检查能力/清理/窗口、目标ASC和Authority等原门禁。

| DamageEffect覆盖 | 显式开关 / 共享快照 | 解析与Boss行为 |
| --- | --- | --- |
| 非空 | 任意 | 始终使用覆盖；其余配置与执行门禁仍须满足。 |
| 空 | false（默认），共享任意 | 返回空；配置校验失败，意外到达命中也拒绝执行。 |
| 空 | true，共享伤害GE可用 | 使用共享类；其余配置与执行门禁仍须满足。 |
| 空 | true，共享伤害GE缺失 | 返回空；配置校验失败，命中报错并返回，不退化为无伤害成功。 |

[[System/结构|System]]唯一持有启动预载及可读取的共享GE快照；解析接口只选择类，GA不加载、不重试、不缓存第二份跨帧状态。解析类非空后，GA继续请求[[AbilitySystem/结构|AbilitySystem]]的`BuildHitEffectPayload`，填写伤害/削韧SetByCaller并通过GAS应用GE和执行Cue。**解析类缺失时在载荷构建前返回，不GE、不Cue**；这不扩大为非空类后Spec构建失败或GE免疫/拒绝的行为变更。CMC执行胶囊位移、Animation提供姿态/窗口语义、CombatTrace查询与去重，原生命周期及清理责任不变。
