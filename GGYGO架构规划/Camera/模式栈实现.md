# CameraModeStack：关键实现

> 所属结构：[[Camera/结构]] · [[GGYGO_结构_相机.canvas|结构图]] · [[GGYGO_流程_相机模式求值.canvas|求值子图]]

## 持有与状态归属

`UGGYGOCameraComponent::OnRegister` 创建一个以组件为 Outer 的 `UGGYGOCameraModeStack`；Stack 创建模式实例时以自己为 Outer，因此模式可经两层 Outer 取回相机组件。Stack 有两个集合：`CameraModeInstances` 是按类复用的实例池，`CameraModeStack` 是当前参与混合的活动栈，索引 0 是栈顶。`ClearStack()` 清活动栈并调用 `OnDeactivation`，不销毁实例池。

模式实例拥有自己的 View、混合进度和本次求值的穿透请求；Stack 拥有活动顺序并聚合输出；CameraComponent 独占 Offset token／alpha 和最终穿透恢复比例。Manager 只管原生 Cache 发布准入，持久 POV 归原生 Cache / LastFrame；Prepared 为一次同步调用的局部候选，无成员 POV 副本或新帧调度器。ThirdPerson 不保存 `CurrentArmLengthRatio`，只保存本模式 `SteeringLateralOffset` 和弱原 CMC／`SourceEpoch` 键；资格、轨迹转向率、WalkRun alpha 与移动执行仍由 Movement 唯一持有。

`ResetCameraRuntimeState()` 立即清活动栈、Offset、有效 token 和恢复比例，但不重置单调 token 计数器。Hero 的模式 generation 同样不因解绑或 EndPlay 重置。

`PrepareCameraView(dt, Prepared)` 完整成功才产生候选，`Prepared.TryGetCandidateView(OutView)` 只读，`CommitPreparedCameraView(MoveTemp(Prepared), Output)` 一次消费并复核原身份、仲裁及配置，绝不重新求值。候选不能跨帧／保存在成员中。兼容 `GetCameraView` 使用同一核心；GG Manager 按 current→pending 调用，Preview 后检查 modifier 再 Commit，最终发布仍受原生 Cache 门禁控制。

`ReinitializeCameraEvaluation()` 只用于显式机制重建：建新 Stack／实例池、清旧活动模式、复核原上下文后安装；保留模式仲裁、Offset 所有权和发号，不发布、不求值或自动重试。正常 `ClearStack` 仍保留旧实例池，不能与显式 Reinitialize 混为一谈。

## 同次 GT 查询既有模式

`CameraComponent::QueryCameraMode(显式精确 ModeClass) const` / Python `query_camera_mode` 返回调用局部的 `FGGYGOCameraModeObservation`。Component 先验证 GT、原 registered Component／Owner／World、具体类与当前 Stack 的 Outer；Stack 内部 const helper 只扫现有池和 active 成员的身份元数据。精确类池对象必须唯一且 Outer 为原 Stack；同类 active 项必须唯一且就是该池对象。无效池／active 指针、重复对象、错 Outer 或 active 不在原池均为 `Unavailable`，保可定位诊断、清空对象与资格输出。

- `NotInstantiated`：原上下文合法，但池中没有精确类；保 Owner／Component／Stack，无 Mode／成员资格。不创建候选，不查 CDO／其他类或替代对象。
- `Available`：`Mode` 是精确原池对象，`bInPool=true`；`bActive` 只表示同次 active 数组中有这个对象。ClearStack／隐藏项裁剪后，同对象仍可能 Available＋inactive。
- `Status / OriginalOwner / OriginalComponent / OriginalStack / Mode / bInPool / bActive / Diagnostic` 为 BlueprintReadOnly 返回字段；内部数组仍受保护，原 UPROPERTY 访问旗标保持。

查询不执行 Push／Evaluate、配置重验、激活／清理或 Reinitialize，不修改 View／Weight／成员集合，也不保存新的长期快照、时钟或状态序号。active 成员不等于正可见贡献、confirmed POV 或未来准入；每次读取重新查询，原生发布资格仍归 Manager。

原 Saved 观察器同时核对原 PC／Manager／ViewTarget／Component 和类／outer 链，保持原 Stack／Mode 对象，只有当前 active＋in-pool 时读取 live `bEnableWalkRunSteeringOffset`。合法覆盖阶段 inactive 为 N/A，不从旧池对象读开关／计关闭覆盖；首次 NotInstantiated 可按原有限绑定截止等待，丢失已捕获身份或 Unavailable 明确失败，不重选同类。查询失败只影响观察结果，不自行改变 Camera 发布状态。三值及原生契约叶／生产证据见 [[Camera/结构#同次 GT 模式只读观察|消费合同]]、[[Camera/结构#身体线性侧倾与 Camera 观察检查点（2026-10-09）|本轮验收]]。

## PushCameraMode 的规则

1. 校验原类、CDO、模式配置与权重，返回 `FGGYGOCameraEvaluationResult`；空／非法类明确失败。已在栈顶的合法模式可成功返回，不重新激活。
2. 在实例池按 Class 查找，没有才 `NewObject`。若该实例已在活动栈里，先计算它当前实际可见贡献：自己的权重乘以所有上层模式的 `(1 - Weight)`；移除旧位置并插入索引 0。新实例且活动栈非空时初始贡献为 0。
3. 只有一个模式时强制权重为 1，给最终视角提供完整基准。其他情况调用 `SetBlendWeight(贡献)`；该函数把权重反解成所选缓动曲线的线性 `BlendAlpha`，下一帧从当前画面继续混合。真正新入栈的模式调用 `OnActivation`。

## EvaluateStack 的规则

`UpdateStack(dt)` 依次调用 `UpdateCameraMode(dt)` 并传播 Result：基类先校验并清本帧旧请求，调用返回 `FGGYGOCameraEvaluationResult` 的 `UpdateView(dt)`；派生成功、配置／View 复核通过后才推进合法 BlendAlpha 并求权重。派生 Failure 直接向 Evaluate／Prepare 传播，保留原 Manager 停更语义。原始 dt 必须有限非负；正 BlendTime 按 dt / BlendTime 推进，合法零时间即使 dt=0 也立即满进度。满权重模式下方已不可见模式经 OnDeactivation 移除。任何配置、数值、权重或输出错误拒绝，不归零／替换曲线／伪造成功；Evaluate 只在整条成功后更新调用方输出，内部已推进状态不承诺整体回滚。

`BlendStack` 以最后一个模式的 View 为基准，从倒数第二个一直混到索引 0；`FGGYGOCameraModeView::Blend` 对位置和 FOV 插值，两个旋转先计算归一化角差，避免跨 ±180° 绕远路。

穿透请求使用与画面相同的遮盖关系。按栈顶到栈底遍历时：

```text
Contribution[i] = Remaining × Weight[i]
Remaining      *= 1 - Weight[i]
```

栈底是完整基底，取得最后剩余贡献。贡献严格大于0且启用的模式才参与请求：Pivot 按贡献归一化，ProbeRadius 取最大合法值，正 RecoverySpeed 取最小正值；全部为0保留立即恢复语义。非法／非有限配置或聚合算术返回 Failure，不替换为零参数或另一查询类型。

## ThirdPerson 的 WalkRun 构图响应

以下机制作为通用显式可选功能保留。当前正式 Pyrios 的 `bEnableWalkRunSteeringOffset=false`，每次原求值清自身侧移／弱来源键并走原构图，不读取未使用的 Movement 来源、不进入响应曲线或滤波尾巴。身体线性侧倾由 [[Animation/结构|Animation]] 按方向误差表现，CMC 继续唯一执行真实移动；关闭这个镜头可选项不禁用原跟随／视角／FOV／碰撞或 GA Offset。

### 原移动事实与状态资格

`UpdateView(dt)` 取原 Pivot／PivotRotation，沿原 Pitch 限制后调用 `UpdateSteeringFromMovement(dt, PivotRotation)`。显式关闭 `bEnableWalkRunSteeringOffset` 时清自身展示并成功，不读取未使用的 Movement 依赖。启用时必须有原 Character 的原 GGYGO CMC；同次 GT 同步读取 `GetLocomotionSteeringSnapshot()`，仅在 Valid 且 `bHasVelocityYawRate` 时继续读原水平速度方向与 `GetWalkRunBlendAlpha()`，期间无外部回调。

`FGGYGOLocomotionSteeringSnapshot` 快照由 CMC 在原 `OnMovementUpdated` 的物理／旋转完成后发布；`ActualSignedYawRate` 是胶囊转向率，`ActualSignedVelocityYawRate` 是原 OldVelocity→完成 Velocity 的真实水平轨迹转向率，两者可能方向相反。Camera 只用后者，不能通过追转方向、输入方向或别的角速度猜轨迹外侧。CMC 决定普通 WalkRun、动作接管／混合、来源有效期及回放资格；Camera 不另设资格状态机、区间时钟或帧号重判。共享事实见 [[Movement/结构|Movement 接口]]，姿态消费见 [[Animation/结构|Animation 接口]]。

| CMC 状态／观测 | Camera 处理 |
| --- | --- |
| `Initial` | 保侧移为 0、继续正常 View 求值；不是已观测的零角速度。包括依赖已接受但无已完成 native 区间，以及 CMC 明确认证的原 PawnExtension 初始化窗口：Set 尚未提交且原生区间未执行。 |
| `NotApplicable` | 目标侧移为 0，经展示滤波回收；正常接管、混合或区间过期不等于坏配置。 |
| `Valid + !bHasVelocityYawRate` | 未有合法非零速度两端，按零目标回收；不拿胶囊角速度补成轨迹观测。 |
| `Valid + bHasVelocityYawRate` | 调纯投影求目标，再更新展示量；真实转向率为 0 时目标为 0。 |
| `Invalid`／原身份失配／未知状态 | 清自身展示与来源键，返回明确 Failure，携模式、Target／Movement 与原 Diagnostic，传播到既有 Manager 停更链。 |

显式空／非法 MovementSet、初始化结束后仍缺配置、原生执行已开始却缺配置或原生命周期退休由 CMC 报 Invalid。Camera 不把它改成 Initial／无期限等待；已 Stopped 的原 Manager 也不因后来配置就绪自动解锁，恢复沿 [[Camera/结构#发布准入与显式重启|原身份显式 Restart]]。

### 世界弯道外侧投影为纯横移

`ComputeSteeringLateralTarget(rate, WorldVelocityDirection, alpha, CameraRotation, OutTarget)` 是无状态构图计算：输入须有限，alpha 在 [0,1]；非零 rate 还要求合法水平单位速度方向。响应曲线 X 为 `abs(ActualSignedVelocityYawRate)`（度/秒），Y 为 [0,1] 强度，至少两个有序键、首键 (0,0)；键、切线、权重与外推枚举须合法，实际求值越界／非有限明确失败，不钳成正常响应。

```text
Gain           = Lerp(WalkSteeringOffsetScale, RunSteeringOffsetScale, alpha)
WorldAmplitude = min(Amplitude × Response(abs(rate)) × Gain, MaxDistance)
WorldOutside   = Cross(WorldUp, normalized WorldVelocityDirection) × -sign(rate)
LateralTarget  = WorldAmplitude × Dot(WorldOutside, CameraRight)
```

UE 正 Yaw 向右，真实右弯的世界外侧在速度左侧。上限在投影前限制世界幅度；camera-right 投影自然让侧视目标接近 0，前视允许屏幕符号反转。原水平朝向的侧视及其邻近角度保持连续，没有角度死区／特判归零；有 Pitch／Roll 时按完整 Euler 右轴计算。

投影的 `CameraRight` 用 double 标量 `DegreesToRadians + SinCos` 计算三轴：Win64 原矩阵向量路径的 float 度数因子曾让精确 90° 留下可观测残差。本修正只提高几何投影精度，保留原 View 的旋转与位置生成规则，不修改 Rotation／ControlRotation／FOV，不改变断言或用容差隐藏问题。

### 展示滤波、合成与清理

`UpdateSteeringPresentation(dt, target)` 仅用当前相机拉取的合法 dt：当目标绝对值小于当前值时取 ReturnSpeed，否则取 EnterSpeed，经 `FInterpTo` 更新本模式标量；显式速度 0 表示立即到目标。配置幅度／上限／增益／速度须有限非负，WalkGain≤RunGain；非法滤波输入或结果返回 Failure，不生成替代 dt 或参数。

`UpdateView` 成功后复制原 `TargetOffset`，仅把 `SteeringLateralOffset` 加到 Y，再按原 PivotRotation 旋转并加 PivotLocation，生成期望 Location；Rotation／ControlRotation／FOV 和穿透请求仍走原规则。该侧移不申请 GA Offset token；完整模式求值后仍严格经过 `Stack Blend → GA Offset → CameraComponent 唯一最终碰撞`。

真正 `OnActivation/OnDeactivation`、原 CMC 或 SourceEpoch 换代会经 `ResetSteeringPresentation()` 清标量、弱 CMC 与 epoch。隐藏模式裁剪／`ClearStack` 调 Deactivation；原 `ResetCameraRuntimeState` 经 ClearStack 复用此清理。实例池可保留，日常仍在活动栈的同类 Push 不反复激活，不能每帧清滤波。源失败和纯投影失败也清本人展示；所有失败都沿显式 Result 传播。没有第二 POV、碰撞恢复比例、移动时钟或执行链。

正式可调字段及 Pyrios 当前显式关闭配置见 [[Camera/结构#设计参数与碰撞策略的归属|配置归属]]；本次冷读／只读观察／最小可视验收见 [[Camera/结构#身体线性侧倾与 Camera 观察检查点（2026-10-09）|本轮检查点]]，此前启用结果保留在 [[Camera/结构#WalkRun 转向构图检查点（2026-10-07）|历史检查点]]；分支见 [[GGYGO_流程_相机模式求值.canvas|求值子图]]。

## Offset 单槽所有权

`SetCameraOffset` 每次成功调用都替换单槽并发放新的 `FGGYGOCameraOffsetHandle`。序号 0 保留为无效值，计数器到达上限后拒绝新请求，Reset 不回绕复用。替换时保留当前 alpha，从正在进行的视觉强度继续过渡；旧 token 不能清除后继请求。

`SetCameraOffset` 在发号和任何成员写入之前，按 `LocationOffset.X → Y → Z → FieldOfViewDelta → BlendInTime → BlendOutTime` 检查。XYZ 与 FOV 增量都必须有限，两种时间还必须非负；NaN/±Inf 或负时间会拒绝整个请求，返回 Invalid Handle（Value=0），保持入口时全部 Offset 字段、active、alpha、有效旧 token 与发号计数器。不把非法值改成零值或立即过渡。全零 Offset、合法零时间和有限负 FOV 增量均正常接受。

失败只记录一条 `LogGGYGOCamera` Error，包含 Component/Owner 路径、首个非法字段与 `non-finite` / `negative` 原因；没有 Tick 日志、重试或诊断缓存。合法输入通过校验后才检查发号耗尽，耗尽另以 `HandleSequence` / `token-exhausted` 诊断并返回 Invalid，同样保持入口状态。

入口原子性只保护进入 Setter 时已有的资源。`UGGYGOGameplayAbility::ApplyCameraOffset` 当前先主动 `ClearCameraOffset()`，再申请新请求，只保存有效返回句柄；Setter 拒绝不会恢复 GA 在调用前已经归还的自身旧资源。这一调用方替换事务仍是独立边界。

Prepare 使用本次原始有限非负 dt；非法 dt、旧 alpha、配置或推进算术明确失败，不生成 SafeDeltaTime 或把 alpha 错误复位后当成功。合法 alpha／正时间下 dt=0 不推进；合法零时间立即到目标 alpha。有限合法结果继续按既定范围钳制，不能与错误触发的替代混淆。

`ClearCameraOffset(Handle)` 只接受当前 token。成功后立即使 token 失效，并保留 Offset 数值供 `BlendOutTime` 回落；重复释放、无效 token 和迟到释放都返回 false 且不改变当前单槽。GA 保存申请时的 CameraComponent 与 token，所以 Avatar 更换后不会误清新 Avatar 的镜头。

## 最终位置唯一碰撞

一次 `PrepareCameraView` 的固定顺序是：

```text
Mode Desired（仅显式启用时含 ThirdPerson 展示侧移；当前 Pyrios 为原构图）→ Stack Blend → CameraOffset → ResolveCameraPenetration → Prepared
Prepared.TryGetCandidateView → modifier 检查 → CommitPreparedCameraView
原生 target blend／摄影检查 → FillCameraCache／发布门禁 → Native Cache
```

CameraComponent 从聚合 Pivot 查到 Offset 后最终位置，忽略 TargetActor。启用且配置／World／Target 有效时，正半径 sphere sweep，合法0半径 line trace；每次 Prepare 最多一种查询。同帧另一次合法调用仍按传入 dt 求值，无帧号去重。收近立即、正速度渐复、合法0恢复速度立即恢复。禁用请求或合法退化路径按正常语义处理；非法依赖／Hit／位置或恢复算术返回失败，不以重置比例掩盖错误。

Prepare 不写 Controller／组件发布字段；Commit 先复核原上下文，再写原 Controller 的 ControlRotation、组件 Transform／FOV及调用方局部输出。Context 失效拒绝后继写入，候选不会重新求值；任意已发生 UE setter／modifier 副作用不承诺整体回滚。空类／空栈不调用 Super 输出替代镜头。

Hero 的模式 Spec＋generation、Stack 的混合、Component 的 Offset／碰撞各有唯一归属。typed H Released 只清原归属资源并保护后继；精确合同见 [[Input/结构#Hero本地ASC身份订阅与原H清理|Input 原 H 清理]]。H1 两入口 `HandleChangeInitState(DataAvailable→DataInitialized)`／`InitializePlayerInput` 经 `ConsumeLocalCameraProviderReady` 调 Activate；早期未装配只等现有入口，重复 Ready 不 Restart，相机失败与输入成功资格分开。

## 原生发布入口与 Cache 保持

普通 `UpdateCamera(dt)` 仅在 Running 时进入受控 `DoUpdateCamera`；其中 GG 目标经 Prepare／Preview／Commit 求值，失败恢复两帧原生 POV、时间戳和附加 PP。Manager 保留准入、原身份和确认资格，持久 POV 只由原生 Cache 保存。

暂停、不要求 full tick 且摄影 provider 支持当前 World 时，LevelTick 虚派发 `UpdateCameraPhotographyOnly()`。NotActivated／Stopped 在调用 Super 前返回，避免 Fill 的 POV 与独立时间戳写入。Running 委托原生 `UpdatePhotographyCamera → FillCameraCache`，保持现有作用域外 POV 写入限制及原生时间戳规则；不额外运行模式栈、不授予新的 confirmed 资格，也不改变 Controller 的暂停 tick 政策。

LP 通过 `HasConfirmedNativeCameraView()` 只读资格：初始化种子无资格，Stopped＋confirmed 可读取保留 Cache；原 LP／PC／World／Manager／PCOwner 在 Super 前后保持才发布本地投影暂存。Activate／原失败身份 Restart 见 [[Camera/结构#发布准入与显式重启|发布契约]]。
