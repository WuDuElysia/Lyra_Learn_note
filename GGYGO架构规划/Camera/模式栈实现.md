# CameraModeStack：关键实现

> 所属结构：[[Camera/结构]] · [[GGYGO_结构_相机.canvas|结构图]] · [[GGYGO_流程_相机模式求值.canvas|求值子图]]

## 持有与状态归属

`UGGYGOCameraComponent::OnRegister` 创建一个以组件为 Outer 的 `UGGYGOCameraModeStack`；Stack 创建模式实例时以自己为 Outer，因此模式可经两层 Outer 取回相机组件。Stack 有两个集合：`CameraModeInstances` 是按类复用的实例池，`CameraModeStack` 是本帧参与混合的活动栈，索引 0 是栈顶。`ClearStack()` 清活动栈并调用 `OnDeactivation`，不销毁实例池。

模式实例拥有自己的 View、混合进度和本帧穿透请求；Stack 拥有活动顺序并聚合输出；CameraComponent 独占 Offset token、Offset alpha 和最终穿透恢复比例。ThirdPerson 已不保存 `CurrentArmLengthRatio`，因此不存在模式内恢复状态与最终镜头恢复状态竞争的问题。

`ResetCameraRuntimeState()` 立即清活动栈、Offset、有效 token 和恢复比例，但不重置单调 token 计数器。Hero 的模式 generation 同样不因解绑或 EndPlay 重置。

## PushCameraMode 的规则

1. 空类直接返回；模式已经在栈顶时直接返回。
2. 在实例池按 Class 查找，没有才 `NewObject`。若该实例已在活动栈里，先计算它当前实际可见贡献：自己的权重乘以所有上层模式的 `(1 - Weight)`；移除旧位置并插入索引 0。新实例且活动栈非空时初始贡献为 0。
3. 只有一个模式时强制权重为 1，给最终视角提供完整基准。其他情况调用 `SetBlendWeight(贡献)`；该函数把权重反解成所选缓动曲线的线性 `BlendAlpha`，下一帧从当前画面继续混合。真正新入栈的模式调用 `OnActivation`。

## EvaluateStack 的规则

`UpdateStack(dt)` 依次调用各模式的 `UpdateCameraMode(dt)`：基类先把 `CameraPenetrationRequest` 重置为默认值，再由 `UpdateView` 计算期望 View 和可选请求；`BlendTime > 0` 时按 `dt / BlendTime` 推进 `BlendAlpha`，合法零时间则直接到满进度，再用 Linear/EaseIn/EaseOut/EaseInOut 得出权重。合法零时间即使 `SafeDeltaTime = 0` 也立即到位。遇到权重满 1 的模式，它下面的模式已不可见，调用 `OnDeactivation` 后移除。

`BlendStack` 以最后一个模式的 View 为基准，从倒数第二个一直混到索引 0；`FGGYGOCameraModeView::Blend` 对位置和 FOV 插值，两个旋转先计算归一化角差，避免跨 ±180° 绕远路。

穿透请求使用与画面相同的遮盖关系。按栈顶到栈底遍历时：

```text
Contribution[i] = Remaining × Weight[i]
Remaining      *= 1 - Weight[i]
```

栈底是完整基底，取得最后剩余贡献。贡献严格大于 0 且 `bEnabled` 的模式参与请求聚合；Pivot 以这些贡献归一化加权，ProbeRadius 取最大安全值，RecoverySpeed 忽略 0 后取最小正值；没有正值时结果为 0，表示立即恢复。无效或非有限输入被归到安全值，结果不依赖数组遍历的偶然顺序。这是当前聚合代码的行为，严格 Offset 短修没有改动这些输入路径；按新规则需要审查的边界见本文末节。

## Offset 单槽所有权

`SetCameraOffset` 每次成功调用都替换单槽并发放新的 `FGGYGOCameraOffsetHandle`。序号 0 保留为无效值，计数器到达上限后拒绝新请求，Reset 不回绕复用。替换时保留当前 alpha，从正在进行的视觉强度继续过渡；旧 token 不能清除后继请求。

`SetCameraOffset` 在发号和任何成员写入之前，按 `LocationOffset.X → Y → Z → FieldOfViewDelta → BlendInTime → BlendOutTime` 检查。XYZ 与 FOV 增量都必须有限，两种时间还必须非负；NaN/±Inf 或负时间会拒绝整个请求，返回 Invalid Handle（Value=0），保持入口时全部 Offset 字段、active、alpha、有效旧 token 与发号计数器。不把非法值改成零值或立即过渡。全零 Offset、合法零时间和有限负 FOV 增量均正常接受。

失败只记录一条 `LogGGYGOCamera` Error，包含 Component/Owner 路径、首个非法字段与 `non-finite` / `negative` 原因；没有 Tick 日志、重试或诊断缓存。合法输入通过校验后才检查发号耗尽，耗尽另以 `HandleSequence` / `token-exhausted` 诊断并返回 Invalid，同样保持入口状态。耗尽分支仅静态核对，未用私有状态注入做动态证明。

入口原子性只保护进入 Setter 时已有的资源。`UGGYGOGameplayAbility::ApplyCameraOffset` 当前先主动 `ClearCameraOffset()`，再申请新请求，只保存有效返回句柄；Setter 拒绝不会恢复 GA 在调用前已经归还的自身旧资源。这一调用方替换事务仍是独立边界。

`GetCameraView` 为整条管线生成同一份有限非负 `SafeDeltaTime`，`UpdateCameraOffsetAlpha` 自身也防御非法或负时间；非有限旧 alpha 会先复位，再钳到 `[0,1]`。在 alpha 已合法且所选进入/回落时间为正时，`SafeDeltaTime = 0` 不推进 alpha；合法零时间走 `BlendTime <= 0` 分支，即使 SafeDt=0 也立即写入目标 alpha：施加状态为 1，回落状态为 0。

`ClearCameraOffset(Handle)` 只接受当前 token。成功后立即使 token 失效，并保留 Offset 数值供 `BlendOutTime` 回落；重复释放、无效 token 和迟到释放都返回 false 且不改变当前单槽。GA 保存申请时的 CameraComponent 与 token，所以 Avatar 更换后不会误清新 Avatar 的镜头。

## 最终位置唯一碰撞

`GetCameraView` 的固定顺序是：

```text
Mode Desired → Stack Blend → CameraOffset → ResolveCameraPenetration → View Output
```

CameraComponent 从聚合 Pivot 扫到 Offset 后的最终位置，忽略 TargetActor。有效请求及 World/Target/非退化路径下，ProbeRadius 大于 0 时用 `ECC_Camera` sphere sweep，等于 0 时用 line trace；每次视图拉取最多执行其中一种查询。同一帧多次拉取仍各自按传入 dt 求值和推进，不新增帧调度器或承诺同帧去重。命中比例小于当前恢复比例时立即收近，避免插值期间穿墙；遮挡解除时，正 RecoverySpeed 用 `FInterpTo` 平滑恢复，0 则立即恢复。无请求、Reset、活动栈为空、World/Target 无效或起终点退化时，恢复比例重置为 1。

最终 View 的 `ControlRotation` 写回 Pawn Controller，Location、Rotation、FOV 写入组件和 `FMinimalViewInfo`。委托没有返回新模式但活动栈仍存在时继续求值已有栈；只有活动栈为空才走 `UCameraComponent::GetCameraView`。

能力覆盖的 Spec+generation 归 HeroComponent，模式实例和混合归 Stack，Offset token 与最终碰撞归 CameraComponent。Hero 在 BeginPlay 只注册一个 `HandleAbilitySystemUninitialized` 协调入口；有效后继输入 guard 可提前返回，并跳过输入与镜头清理。正常清理分支按 `ReleasePlayerInput → 清模式覆盖 → Camera Reset` 执行；EndPlay 先设置 `bEndingPlay`、解绑模式委托，再复用该入口，绕过 guard。完整条件见 [[Camera/结构#解绑协调与后继保护|解绑协调与后继保护]]；配套流程见 [[GGYGO_流程_相机覆盖恢复.canvas]]，该图已按D3-R同步唯一协调入口、后继 guard、正常清理与 EndPlay 分支，并经统筹静态接受冻结；真实解绑叶仍仅证明正常无输入会话路径。
