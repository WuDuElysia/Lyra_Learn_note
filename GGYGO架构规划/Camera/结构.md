## 模块边界

`Source/GGYGO/Camera/` 只负责视角求值、模式实例复用、混合和最终镜头微调。当前有效模式由 `UGGYGOHeroComponent` 仲裁；能力的持有与结束语义见 [[AbilitySystem/结构|AbilitySystem 结构]]。图中的实线关系均对应当前代码，锁定模式和过场镜头仍是计划或外部通道。

| 类 / 数据 | 对外关键接口 | 依赖与职责 |
| --- | --- | --- |
| `UGGYGOCameraComponent` | `DetermineCameraModeDelegate`、`GetCameraView`、`SetCameraOffset`、`ClearCameraOffset`、`ClearCameraModeStack` | Pawn 上的引擎相机入口；持有一个 `UGGYGOCameraModeStack`，把栈的最终视角和微调写入相机视图。`GetCameraView` 是 UE 调用的覆盖点。 |
| `UGGYGOCameraModeStack` | `PushCameraMode`、`EvaluateStack`、`ClearStack` | 按模式类复用 `UGGYGOCameraMode` 实例；栈顶在索引 0，从栈底向栈顶混合。它不知道 Ability Spec 或 PawnData。 |
| `UGGYGOCameraMode` | `UpdateCameraMode`、可覆写 `UpdateView`、`GetCameraModeView`、`GetTargetActor` | 一个模式计算一份 `FGGYGOCameraModeView`；混合权重和生命周期交给栈。 |
| `UGGYGOCameraMode_ThirdPerson` | 覆写 `UpdateView` | 当前第三人称跟随、俯仰限制和遮挡规避。 |
| `FGGYGOCameraModeView` / `FGGYGOCameraOffset` | `Blend` / 配置字段 | 前者是模式输出的镜头位置、画面朝向、控制朝向和 FOV；后者是栈求值后的局部位置与 FOV 微调。 |

## 与其他模块如何交互

1. `UGGYGOPawnData::DefaultCameraMode` 提供常规模式类；`UGGYGOHeroComponent::DetermineCameraMode` 在默认模式与能力覆盖列表之间选出有效类。
2. `UGGYGOCameraComponent` 通过 `DetermineCameraModeDelegate` 取回这个类，再调用 `CameraModeStack->PushCameraMode` 与 `EvaluateStack`。相机组件拥有栈，栈拥有模式实例，模式只产出 `View`。
3. `UGGYGOGameplayAbility` 在激活和结束时调用 Hero 的 `SetAbilityCameraMode` / `ClearAbilityCameraMode`；覆盖项以 `FGameplayAbilitySpecHandle` 标识。能力也可经相机组件施加 `FGGYGOCameraOffset`。这条跨模块边界详见 [[AbilitySystem/结构|AbilitySystem 结构]]。
4. UE 通过当前 ViewTarget 的相机组件调用 `GetCameraView`。相机组件把 `ControlRotation` 写回 Controller；它与画面使用的 `Rotation` 是两份独立值。

`CameraModeStack` 是画面混合栈；HeroComponent 的能力覆盖列表是模式所有权列表。两者不是同一个栈。运行次序和恢复例子见 [[GGYGO_流程_相机.canvas|相机流程图]]。

## 当前边界与缺口

PawnData 尚未给出模式或栈为空时，组件退回 `UCameraComponent::GetCameraView`。目前没有锁定模式蓝图子类、可见的镜头抖动配置和过场镜头实现；这些不应画成已存在的相机类。
