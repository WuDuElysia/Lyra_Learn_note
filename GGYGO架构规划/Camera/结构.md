# Camera：结构与接口

> 结构图：[[GGYGO_结构_相机.canvas]] · 运行流程：[[GGYGO_流程_相机.canvas]] · 全局入口：[[计划蓝图]]

> 关键实现：[[模式栈实现]]（实例池、可见贡献、穿透请求聚合、单槽微调与最终碰撞）。

## 模块边界

`Source/GGYGO/Camera/` 负责视角求值、模式实例复用与混合、单槽镜头微调，以及每次视图拉取对最终镜头位置至多执行一种穿透查询。当前有效模式由 `UGGYGOHeroComponent` 仲裁；能力只申请和归还模式/微调资源，生命周期语义见 [[AbilitySystem/结构|AbilitySystem 结构]]。Camera 不读取 Ability Spec 内部状态，Hero 不计算镜头位置，ThirdPerson 不直接访问场景碰撞。

| 类 / 数据 | 对外关键接口 | 依赖与职责 |
| --- | --- | --- |
| `UGGYGOCameraComponent` | `DetermineCameraModeDelegate`、`GetCameraView`、`SetCameraOffset`、`ClearCameraOffset`、`ResetCameraRuntimeState` | Pawn 上的引擎相机入口；持有一个 `UGGYGOCameraModeStack`，在栈混合和 Offset 后统一处理穿透，再写入最终视图。它是相机碰撞和单槽 Offset 的唯一执行者。 |
| `UGGYGOCameraModeStack` | `PushCameraMode`、`EvaluateStack`、`ClearStack` | 按模式类复用实例；栈顶在索引 0，从栈底向栈顶混合 View，并按本帧实际可见贡献聚合穿透请求。它不知道 Ability Spec、Avatar 或 PawnData。 |
| `UGGYGOCameraMode` | `UpdateCameraMode`、可覆写 `UpdateView`、`GetCameraModeView`、`GetCameraPenetrationRequest` | 一个模式计算一份 `FGGYGOCameraModeView`，可附带一份 `FGGYGOCameraPenetrationRequest`；基类在每帧 `UpdateView` 前清空旧请求。 |
| `UGGYGOCameraMode_ThirdPerson` | 覆写 `UpdateView` | 按视线空间偏移计算期望位置，并声明是否需要穿透保护、枢轴、探针半径与恢复速度；不再自行 sweep，也不保存第二份恢复进度。 |
| `BP_CameraMode_ThirdPerson_Pyrios` | Class Defaults | 已有 Pyrios 参数资产记录：距离/肩位/高度、FOV、Pitch、混合与穿墙参数，父类为 `UGGYGOCameraMode_ThirdPerson`；本轮未重新回读资产。 |
| `FGGYGOCameraModeView` | `Blend` | 模式输出的镜头位置、画面朝向、控制朝向和 FOV。 |
| `FGGYGOCameraPenetrationRequest` | `bEnabled`、`PivotLocation`、`ProbeRadius`、`RecoverySpeed` | 模式对最终位置保护的声明；Stack 聚合，CameraComponent 执行。`RecoverySpeed=0` 表示立即恢复。 |
| `FGGYGOCameraOffset` / `FGGYGOCameraOffsetHandle` | 配置字段 / `Value` | Offset 是栈求值后的局部位置和 FOV 微调；XYZ/FOV 增量须有限，进入/回落时间须有限非负，合法零值可接受。Handle 是单槽所有权凭证，0 无效，成功才发号，序号在组件生命周期内不回绕复用。 |

## 与其他模块如何交互

1. 既有资产接线记录：`BP_PC_Pyrios.HeroComponent.DefaultInputMappings` 配置 `IMC_Default` 与 `IMC_MouseLook`。前者提供 `IA_Look` 的摇杆映射，后者提供 `IA_MouseLook` 的 `Mouse2D` 映射；`DA_InputConfig_Default` 再把两者分别映射到 `InputTag.Look.Stick` 与 `InputTag.Look.Mouse`。本轮没有资产回读或设备验收。
2. `UGGYGOHeroComponent::Input_LookMouse` / `Input_LookStick` 把轴值传给 Pawn 的 `AddControllerYawInput` / `AddControllerPitchInput`，先更新 Controller 的 `ControlRotation`。输入结构详见 [[Input/结构|Input 结构]]。
3. `UGGYGOPawnData::DefaultCameraMode` 选择角色的常规模式类。既有 `DA_Pawn_Pyrios` 记录指向 `/Game/Camera/Modes/BP_CameraMode_ThirdPerson_Pyrios`；`UGGYGOHeroComponent::DetermineCameraMode` 在该默认类与能力覆盖列表之间选出有效类。
4. `UGGYGOCameraComponent` 通过 `DetermineCameraModeDelegate` 取回模式类，调用 `CameraModeStack->PushCameraMode`，再用 `EvaluateStack` 同时取得混合后的 View 与穿透请求。相机组件拥有栈，栈拥有模式实例，模式读取 Pawn 的 ViewRotation。
5. `UGGYGOGameplayAbility` 申请模式时保存原始 Hero、SpecHandle 和 generation；申请 Offset 时仅在返回有效句柄后保存原始 CameraComponent 和 token。`ApplyCameraOffset` 先 Clear 自己的旧请求再 Set；Setter 的入口状态保持不会恢复调用前已归还的资源。结束时只向原接收者归还精确凭证，不按当前 Avatar 重新查找，也不把存活能力的旧镜头请求重放到新 Avatar。
6. `UGGYGOCameraComponent` 先对混合 View 施加 Offset，再按聚合请求从 Pivot 到最终位置执行 `ECC_Camera` 查询：有效请求及路径下，每次视图拉取至多执行一种查询，半径大于 0 用 sphere sweep，半径为 0 用 line trace；收近立即，解除遮挡后按聚合速度恢复。它不新增帧调度器，也不保证同帧多次拉取只推进一次。
7. UE 通过当前 ViewTarget 的相机组件调用 `GetCameraView`。组件把最终 `ControlRotation` 写回 Controller，并把位置、画面 `Rotation` 与 FOV 写入 `FMinimalViewInfo`。
8. Hero 在 BeginPlay 向 PawnExtension 注册唯一的 `HandleAbilitySystemUninitialized` 协调入口，并订阅 initialized 来绑定能力输入重试。输入释放已整合到同一个解绑入口；正常清理顺序为 `ReleasePlayerInput` → 清模式覆盖 → Camera Reset，有效后继输入保护可提前返回。详见下节。

`CameraModeStack` 是画面混合栈；HeroComponent 的能力覆盖列表是模式所有权列表；CameraComponent 的 Offset 是单槽资源。三者分别拥有混合、仲裁与最终微调状态，互不建立第二份权威状态。

## 解绑协调与后继保护

外置 ASC 的 Owner、Avatar 绑定和 Attach/Detach 入口归 [[Combatants/结构|Combatants]]。`PawnExtension::UninitializeAbilitySystem(ExpectedASC)` 先检查本地缓存：缓存为空或 ExpectedASC 不匹配时直接返回；匹配时先清本地缓存，再广播本地 uninitialized。广播已经不受共享 ASC 当前 Avatar 是否为本 Pawn 的条件限制，这是已实现的 C4。

共享 ASC 的副作用另有条件：仅当旧 ASC 仍以本 Pawn 为 Avatar 时，才取消非 `Ability.Behavior.SurvivesDeath` 能力、清能力输入与 Cue，并解除 Avatar；Owner 仍在时保留 Owner。Avatar 已失配时仍通知本地订阅者，却不清另一 Avatar 的共享 ASC 状态。

Hero 的解绑订阅按 UObject 去重，BeginPlay 仅注册一个协调器，[[Input/结构|Input]] 已扩展这一入口。未进入 EndPlay 且输入会话有效时，当前输入 ASC 与本地缓存/Avatar 一致，或输入刚建立且没有 ASC 缓存与两项旧订阅，都会使入口提前返回；输入与镜头清理均被跳过。否则入口先释放输入，再清 Hero 覆盖并 Reset 本 Pawn 的 Camera。EndPlay 先设置 `bEndingPlay`、解除模式委托，再复用该入口，绕过提前返回。

无参数广播不携带旧 ASC 或镜头请求代次。旧请求失效与后继新请求保持的组合仍需独立重入验证；`ReleasePlayerInput` 内 `RemoveMappingContext` 也可同步触发后继回调。第22次新增、并在第26/27次复跑的真实解绑叶没有建立输入会话或 IMC，不能据此确认这两类重入已闭环，也不能把保护分支写成每次解绑必然 Camera Reset。

## 设计参数与碰撞策略的归属

- C++ `UGGYGOCameraMode_ThirdPerson` 保留期望视角算法和安全默认值；CameraComponent 保留统一场景查询与恢复算法。
- CameraMode 蓝图的 Class Defaults 保存设计师可调的构图和穿透请求参数；Pyrios 既有配置记录为 `TargetOffset=(-350,0,60)`、`FOV=85`、`Pitch=-70..70`、`BlendTime=0.5`、`EaseOut/4`、穿墙开启、`ProbeRadius=14`、`RecoverySpeed=4`。这些数值保留记录来源，本轮没有重新保存或回读资产。
- 多模式混合时，只统计实际可见贡献严格大于 0 且启用保护的请求。Pivot 按这些请求的贡献归一化加权，ProbeRadius 取最大有限非负值；存在正恢复速度时取最小正值，全部为 0 时保持 0 的立即恢复语义。
- 每个角色或形态由自己的 PawnData 选择 CameraMode 类；角色蓝图的 CameraComponent Transform/FOV 会被 `GetCameraView` 的模式结果逐帧覆盖，不作为常规构图入口。
- 大幅临时换机位使用 Ability 的 `AbilityCameraMode`；只改局部位置或 FOV 使用 `FGGYGOCameraOffset`。

## 关键接口契约

| 调用方 → 接口 | 输入 / 前提 | 作用与输出 / 副作用 |
| --- | --- | --- |
| GA → `HeroComponent::SetAbilityCameraMode(Class, SpecHandle)` | 有效模式类与本 GA 的 SpecHandle | 返回非零单调 generation，并把同 Spec 的新请求置顶；无效输入或计数器耗尽返回 0。`ClearAbilityCameraMode(SpecHandle, Generation)` 同时匹配才移除并返回 true，否则 false。GA 保存申请时的弱 Hero 与双键。 |
| GA → `CameraComponent::SetCameraOffset(Offset)` | 申请时Avatar上的CameraComponent；按LocationOffset.X→Y→Z→FieldOfViewDelta→BlendInTime→BlendOutTime校验，XYZ/FOV有限，两时间有限非负 | 校验先于发号及成员写入；非法输入一次`LogGGYGOCamera` Error（Component/Owner/首个字段/non-finite或negative），返回Invalid（Value=0），保持入口Offset/active/alpha/旧token/发号计数器。合法全零Offset、零时间及有限负FOV接受；成功替换单槽、发新handle且保留alpha。合法输入通过后才检查耗尽，另以HandleSequence/token-exhausted诊断并返回Invalid、不回绕。`ClearCameraOffset(Handle)`仅当前token成功并失效，按原BlendOut回落；旧/重复/无效token返回false。GA仅保存有效句柄的弱原Camera/token；先Clear再Set的调用方边界见上文。 |
| 宿主 → `PawnExtension::UninitializeAbilitySystem(ExpectedASC)` | 本地有 ASC；ExpectedASC 为空或匹配 | 先清本地缓存，再广播；共享 ASC 清理另受 Avatar 匹配条件限制。缓存空或 ExpectedASC 失配无副作用，详见 [[Combatants/结构]]。 |
| PawnExtension / EndPlay → `HeroComponent::HandleAbilitySystemUninitialized` | 唯一无参数解绑订阅或 Hero EndPlay | 已合并 Input 释放；有效后继输入 guard 可提前返回，否则清模式覆盖并 Camera Reset。EndPlay 绕过 guard。generation 与 Offset token 计数器均不重置。 |
| CameraComponent → `DetermineCameraModeDelegate` | 本帧 UE 拉取视角 | HeroComponent 返回栈顶能力覆盖类，否则返回 PawnData 默认类；它不返回模式实例。空返回不会主动清除已存在的活动栈。 |
| CameraComponent → `Stack::PushCameraMode(Class)` | 有效 Mode 类 | 从实例池复用/创建模式并置顶，恢复旧模式的可见贡献；活动栈索引 0 为顶。 |
| CameraComponent → `Stack::EvaluateStack(dt, OutView, OutRequest)` | 活动模式与 DeltaTime | 更新模式、从栈底向顶混合 View，并按相同遮盖关系聚合穿透请求。 |
| CameraComponent → `ResolveCameraPenetration` | Offset 后 View、启用聚合请求与有效非退化路径 | 忽略 TargetActor，每次拉取在 sphere sweep / line trace 中最多选一种并维护唯一恢复比例；无请求、Reset、空栈或退化路径重置该比例。 |
| UE → `CameraComponent::GetCameraView(dt, DesiredView)` | ViewTarget 的 CameraComponent | 执行 `Mode Desired → Stack Blend → Offset → ResolvePenetration → View Output`；仅活动栈为空时调用 Super。 |

具体权重逆算、贡献公式、Offset 与碰撞顺序见 [[模式栈实现]]。
