## 模块边界

`Source/GGYGO/Camera/` 负责模式求值、实例复用与混合、单槽 Offset、最终位置唯一碰撞，以及原生 CameraManager 的发布准入。`AGGYGOPlayerCameraManager` 控制启用／停止／显式重启，持久 POV 只保存在原生 CameraCache / LastFrameCameraCache；不增加第二个帧调度器或 POV 成员副本。当前有效模式由 `UGGYGOHeroComponent` 仲裁；能力只申请和归还资源，生命周期见 [[AbilitySystem/结构|AbilitySystem 结构]]。Hero 不计算镜头位置，ThirdPerson 不直接查询碰撞。

| 类 / 数据 | 对外关键接口 | 依赖与职责 |
| --- | --- | --- |
| `UGGYGOCameraComponent` | `PrepareCameraView`、`CommitPreparedCameraView`、`ReinitializeCameraEvaluation`、兼容 `GetCameraView`、Offset / Reset 接口 | 独占 Stack、Offset、最终碰撞；Prepare 求值一次且不写 Controller／组件发布字段，Commit 消费一次候选并复核原上下文，不重新求值。Reinitialize 显式重建 Stack／实例池，保留模式仲裁和 Offset 所有权，不发布视图。 |
| `UGGYGOCameraModeStack` | `PushCameraMode`、`EvaluateStack`、`ClearStack` | 按类复用实例；索引 0 为顶，自底向顶混合并聚合贡献。Push / Evaluate 返回 `FGGYGOCameraEvaluationResult`；失败逐层传播，输出只在完整成功后更新。Clear 清活动栈、保留实例池。 |
| `AGGYGOPlayerCameraManager` | `ActivateCameraEvaluation`、`RestartCameraEvaluation`、`HasConfirmedNativeCameraView`、状态／结果只读 Getter | 只管原生发布准入与失败策略；沿用原生 Update / DoUpdate / target blend 顺序。受控 DoUpdate 失败保持两个原生 POV、时间戳及附加 PP；任意 UE setter／modifier 副作用不承诺整体回滚。 |
| `FGGYGOPreparedCameraView` | `TryGetCandidateView` | 不透明、仅移动的调用局部候选；Preview 只读，Commit 一次消费；不得跨帧或保存在成员中。 |
| `UGGYGOLocalPlayer`（跨模块） | `GetProjectionData` | [[System/结构|System]] 的投影门禁，只读实际 Manager 的 confirmed 资格；前后核对原身份，成功才发布局部投影输出，无 POV 或准入副本。 |
| `UGGYGOCameraMode` | `UpdateCameraMode`、可覆写 `UpdateView`、`GetCameraModeView`、`GetCameraPenetrationRequest` | 一个模式计算一份 `FGGYGOCameraModeView`，可附带一份 `FGGYGOCameraPenetrationRequest`；基类在每帧 `UpdateView` 前清空旧请求。 |
| `UGGYGOCameraMode_ThirdPerson` | 覆写 `UpdateView` | 按视线空间偏移计算期望位置，并声明是否需要穿透保护、枢轴、探针半径与恢复速度；不再自行 sweep，也不保存第二份恢复进度。 |
| `BP_CameraMode_ThirdPerson_Pyrios` | Class Defaults | 已有 Pyrios 参数资产记录：距离/肩位/高度、FOV、Pitch、混合与穿墙参数，父类为 `UGGYGOCameraMode_ThirdPerson`；本轮未重新回读资产。 |
| `FGGYGOCameraModeView` | `Blend` | 模式输出的镜头位置、画面朝向、控制朝向和 FOV。 |
| `FGGYGOCameraPenetrationRequest` | `bEnabled`、`PivotLocation`、`ProbeRadius`、`RecoverySpeed` | 模式对最终位置保护的声明；Stack 聚合，CameraComponent 执行。`RecoverySpeed=0` 表示立即恢复。 |
| `FGGYGOCameraOffset` / `FGGYGOCameraOffsetHandle` | 配置字段 / `Value` | Offset 是栈求值后的局部位置和 FOV 微调；XYZ/FOV 增量须有限，进入/回落时间须有限非负，合法零值可接受。Handle 是单槽所有权凭证，0 无效，成功才发号，序号在组件生命周期内不回绕复用。 |

## 与其他模块如何交互

1. 既有资产接线记录：`BP_PC_Pyrios.HeroComponent.DefaultInputMappings` 配置 `IMC_Default` 与 `IMC_MouseLook`。前者提供 `IA_Look` 的摇杆映射，后者提供 `IA_MouseLook` 的 `Mouse2D` 映射；`DA_InputConfig_Default` 再把两者分别映射到 `InputTag.Look.Stick` 与 `InputTag.Look.Mouse`。本轮没有资产回读或设备验收。
2. `UGGYGOHeroComponent::Input_LookMouse` / `Input_LookStick` 把轴值传给 Pawn 的 `AddControllerYawInput` / `AddControllerPitchInput`，先更新 Controller 的 `ControlRotation`。输入结构详见 [[Input/结构|Input 结构]]。
3. `UGGYGOPawnData::DefaultCameraMode` 选择角色的常规模式类。既有 `DA_Pawn_Pyrios` 记录指向 `/Game/Camera/Modes/BP_CameraMode_ThirdPerson_Pyrios`；`UGGYGOHeroComponent::DetermineCameraMode` 在该默认类与能力覆盖列表之间选出有效类。
4. `PrepareCameraView(dt, Prepared)` 内部通过 `DetermineCameraModeDelegate` 取模式类，消费 Push / Evaluate 的真实结果，再推进 Offset 并执行唯一碰撞。委托未绑定、类／栈／配置／时间无效时明确失败，不沿用旧栈或输出默认镜头。候选只在整条 Prepare 成功后产生。
5. GA 申请模式保存原 Hero／Spec／generation，申请 Offset 仅保存有效原 Camera／token；`ApplyCameraOffset` 先 Clear 再 Set，拒绝不恢复调用前已归还的资源。默认 `CleanupAbilityResourcesForTermination(Context)` 已消费原 Termination 记录中的镜头凭证：先摘仍匹配的成员，再向原接收者归还；不按当前 Avatar 重找或重放。派生清理完整迁移与端到端终止链尚未完成，不能泛称所有 End 路径已安全。
6. `UGGYGOCameraComponent` 先对混合 View 施加 Offset，再按聚合请求从 Pivot 到最终位置执行 `ECC_Camera` 查询：有效请求及路径下，每次视图拉取至多执行一种查询，半径大于 0 用 sphere sweep，半径为 0 用 line trace；收近立即，解除遮挡后按聚合速度恢复。它不新增帧调度器，也不保证同帧多次拉取只推进一次。
7. GG 生产路径由 Manager 的 `UpdateViewTarget` 调用 `PrepareCameraView → Prepared.TryGetCandidateView → modifier 检查 → CommitPreparedCameraView`，每个目标求值一次，并保留原生 current→pending 顺序。Commit 输出为调用局部暂存；原生处理后的 POV 经混合／摄影／Cache 门禁发布。兼容 `GetCameraView` 也使用同一 Prepare／Commit 核心，不再调用 Super 替代失败。明确非 GG CameraActor／CameraStyle 路径保留原生行为。
8. H1 在 `HandleChangeInitState(DataAvailable→DataInitialized)` 的 InputComponent 空检查之前，以及 `InitializePlayerInput` 的输入资源释放之前，调用 `ConsumeLocalCameraProviderReady`；真实本地原来源就绪后调用 `ActivateCameraEvaluation(OriginalPawn, OriginalCamera)`。BeginPlay／PawnData 尚未就绪时只等待已有生命周期入口，不轮询。Helper 的 bool 表示原初始化尾部是否仍可继续，不表示相机成功；相机失败与输入结果分开，原身份失效则停止旧尾部。重复 Ready 不调用 Restart。

9. L1 `GetProjectionData` 核对原 LP／PC／World／Manager 槽及原生 PCOwner，读取 `HasConfirmedNativeCameraView()`；未确认则返回 false。使用本地 `ProjectionScratch` 调用 Super，返回后再次核对身份与资格，完整成功才写调用方输出。Stopped＋confirmed 仍可取景，初始化种子不能取景。

`CameraModeStack` 拥有混合，Hero 覆盖列表拥有仲裁，CameraComponent 拥有 Offset／碰撞，Manager 拥有发布准入，原生 Cache 拥有持久 POV；LP 只读资格，各自不建立第二份权威状态。

### 发布准入与显式重启

- `NotActivated`：等待原 provider 的明确首次 Activate，早期原生 Update 不求值，不误判坏配置；InitializeFor 的 FOV 种子不计 confirmed。
- `Running`：沿原生更新链执行并确认实际成功发布。首次缺配置／非法求值拒绝启用；已有画面时失败保留最后确认的原生 Cache。
- `Stopped`：停止受控求值并保留失败定位信息；修好配置或重复 Ready 都不恢复。`RestartCameraEvaluation(ExpectedOriginalTarget, ExpectedOriginalComponent)` 校验精确原失败身份、Controller、World；GG 来源先 Reinitialize 再尝试一次，失败仍停止。明确原生来源失败的 Component 参数为 null，不收养替代对象。

最终原始 blend 算术在 FillCameraCache 的 NaN 诊断前检查，覆盖 `AllowPhotographyMode=false`，不强制摄影模式。暂停时 LevelTick 直接调用非虚 `UpdateCameraPhotographyOnly` 的端口只拒外部 POV 写入，仍无法阻止后续时间戳写入；该保持契约未覆盖，未改引擎、摄影或暂停 full tick 政策。

## 解绑协调与后继保护

外置 ASC／Host 与本地 opaque H 的生命周期归 [[Combatants/结构|Combatants]]／[[Character/结构|Character]]。Hero 经 `PrepareLocalAbilitySystemSubscription` 注册原 Extension 的 typed Notice，由 `ConsumeLocalAbilitySystemNotice(ExpectedSubscription, Notice)` 消费 Ready／Refreshed／Released；不再把无参数解绑广播写成当前契约。

matching 原 H Released 先撤回原记录及派生关联，只释放确实属于原 H 的输入／retry；汇合后再次核对原记录、镜头代次与后继保护，再清原 overrides 并只 Reset 捕获的原 Camera。无 Controller／InputComponent 不阻止原镜头撤回；新 H、新输入／retry 或新镜头请求使旧清理停止。EndPlay 先关闭准入、解绑模式委托并释放自身资源，计数器不重置。

详细参数、回放与释放顺序以 [[Input/结构#Hero本地ASC身份订阅与原H清理|Input 原 H 精确合同]] 为准。旧真实解绑叶的无输入证明保留，不能外推 Input／IMC 重入或全部终止链；[[GGYGO_流程_相机覆盖恢复.canvas|覆盖恢复子图]] 已同步至上述接口合同；只增补静态图文一致性，不新增动态证明。

## 设计参数与碰撞策略的归属

- C++ `UGGYGOCameraMode_ThirdPerson` 保留期望视角算法、通用配置字段与合法性校验；CameraComponent 保留统一场景查询与恢复算法。
- CameraMode 蓝图的 Class Defaults 保存设计师可调的构图和穿透请求参数；Pyrios 既有配置记录为 `TargetOffset=(-350,0,60)`、`FOV=85`、`Pitch=-70..70`、`BlendTime=0.5`、`EaseOut/4`、穿墙开启、`ProbeRadius=14`、`RecoverySpeed=4`。这些数值保留记录来源，本轮没有重新保存或回读资产。
- 多模式混合时，只统计实际可见贡献严格大于 0 且启用保护的请求。Pivot 按这些请求的贡献归一化加权，ProbeRadius 取最大有限非负值；存在正恢复速度时取最小正值，全部为 0 时保持 0 的立即恢复语义。
- 每个角色或形态由自己的 PawnData 选择 CameraMode 类；角色蓝图的 CameraComponent Transform/FOV 会被运行时 Commit 的模式结果覆盖，不作为常规构图入口。
- 大幅临时换机位使用 Ability 的 `AbilityCameraMode`；只改局部位置或 FOV 使用 `FGGYGOCameraOffset`。

## 关键接口契约

| 调用方 → 接口 | 输入 / 前提 | 作用与输出 / 副作用 |
| --- | --- | --- |
| GA → `HeroComponent::SetAbilityCameraMode(Class, SpecHandle)` | 有效模式类与本 GA 的 SpecHandle | 返回非零单调 generation，并把同 Spec 的新请求置顶；无效输入或计数器耗尽返回 0。`ClearAbilityCameraMode(SpecHandle, Generation)` 同时匹配才移除并返回 true，否则 false。GA 保存申请时的弱 Hero 与双键。 |
| GA → `CameraComponent::SetCameraOffset(Offset)` | 申请时Avatar上的CameraComponent；按LocationOffset.X→Y→Z→FieldOfViewDelta→BlendInTime→BlendOutTime校验，XYZ/FOV有限，两时间有限非负 | 校验先于发号及成员写入；非法输入一次`LogGGYGOCamera` Error（Component/Owner/首个字段/non-finite或negative），返回Invalid（Value=0），保持入口Offset/active/alpha/旧token/发号计数器。合法全零Offset、零时间及有限负FOV接受；成功替换单槽、发新handle且保留alpha。合法输入通过后才检查耗尽，另以HandleSequence/token-exhausted诊断并返回Invalid、不回绕。`ClearCameraOffset(Handle)`仅当前token成功并失效，按原BlendOut回落；旧/重复/无效token返回false。GA仅保存有效句柄的弱原Camera/token；先Clear再Set的调用方边界见上文。 |
| 原 Extension → `Hero::ConsumeLocalAbilitySystemNotice(ExpectedSubscription, Notice)` | 原订阅记录、typed H、Notice 与真实上下文 | Ready／Refreshed／Released 按原 H 消费；Released 只撤回原归属资源，镜头清理受后继保护。详见 [[Input/结构#Hero本地ASC身份订阅与原H清理|精确合同]]。 |
| Hero 的两原生入口 → `ConsumeLocalCameraProviderReady(Pawn, NativeEntry)` | DataInitialized 或 InitializePlayerInput；本地原 provider 已装配 | 真实就绪时调用 Activate；相机结果不成为输入成功门禁；身份改变停止旧初始化尾部。 |
| CameraComponent → `DetermineCameraModeDelegate` | 本次 Prepare 的原仲裁绑定 | Hero 返回覆盖类或 PawnData 默认类；未绑定或无效类返回失败，不继续旧栈。 |
| CameraComponent → `Stack::PushCameraMode(Class)` | 有效原 Mode 类与配置 | 复用／创建并置顶，返回真实 Result；任何失败向 Prepare 传播。索引0为顶。 |
| CameraComponent → `Stack::EvaluateStack(dt, OutView, OutRequest)` | 原活动栈与有限非负 dt | 完整成功才输出 View／Request；模式、权重、混合、请求非法明确失败。 |
| CameraComponent → `ResolveCameraPenetration` | Offset 后 View、原聚合请求、有效 World／Target | 每次 Prepare 在 sweep／line trace 中至多执行一种，维护唯一恢复比例；禁用或合法退化路径按正常语义处理，非法依赖不改为成功。 |
| Manager → `PrepareCameraView(dt, Prepared)` / `Prepared.TryGetCandidateView` / `CommitPreparedCameraView(MoveTemp(Prepared), Output)` | 调用局部原候选，不跨帧；原目标／组件／Controller／World／仲裁有效 | Prepare 求值一次；Preview 只读；Commit 一次消费并复核上下文，不再求值。兼容 GetCameraView 使用同一核心，失败不 Super。 |
| Hero → `ActivateCameraEvaluation(Target, Component)` | 原本地首次 provider Ready；精确目标／组件 | 返回 Result；重复原 Ready 幂等，Stopped 不恢复。 |
| 显式恢复请求 → `RestartCameraEvaluation(OriginalTarget, OriginalComponent)` | 已 Stopped；原失败身份与上下文仍匹配 | GG 源先重建机制，再尝试一次；失败仍停止，不换来源。 |
| LP → `HasConfirmedNativeCameraView()` / `GetProjectionData` | 原 LP／PC／World／Manager／PCOwner 关联 | 只读 confirmed；种子拒绝、Stopped＋confirmed 可取景；Super 前后核对，仅成功发布本地投影暂存。 |
