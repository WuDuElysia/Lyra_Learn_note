# Combat：近战判定结构与接口

> 当前 PlayerCombo/BossMelee 的 C++ 生产消费者已接 Owned 窗口和原生命中订阅，保存原 Activation、原 Trace、窗口句柄及订阅 token，并在自身原资源清理中归还。Gate79 完整 Editor 编译成功；七项必要冒烟为 5 Success / 2 Fail / 0 Warning，四个 RuntimeHit Case 的行为断言均 PASS，两个 Fail 保留三条真实生产 Error。正式动画/资产、Legacy 蓝图绑定迁移、完整 Boss 命中与联机未由此证明。玩家接入见 [[计划_玩家普攻连段]]。

> [[GGYGO_结构_Combat.canvas|结构图]] · [[GGYGO_流程_Combat.canvas|判定流程]] · [[GGYGO_流程_伤害结算.canvas|后续伤害流程]]

`UGGYGOMeleeTraceComponent` 是当前 `Combat/HitDetection/` 的运行时组件，提供 Legacy 与 Owned 两种明确入口，共用一份活动窗口、采样、去重和 Tick。Legacy 的 `BeginTraceWindow(StartSocket, EndSocket, Radius)` / `EndTraceWindow()` / `OnMeleeHit(HitActor, HitResult)` 保留原蓝图签名与普通窗口行为；活动 Owned 窗口存在时，Legacy 开关明确拒绝。Owned 以 `FGGYGOMeleeTraceWindowHandle` 校验原窗口，只分发携原窗口身份的原生命中回调，不广播全局 `OnMeleeHit`。组件只报告碰撞候选，不决定伤害数值，也不直接修改目标属性。

窗口内每帧取主 Mesh 两端 Socket 世界位置，按武器长度与半径推导采样间距，逐点从上帧扫到本帧，降低跨帧漏判。查询显式请求 PhysicalMaterial，使同一个 `FHitResult` 可同时供伤害衰减与表面 Cue 使用。第一帧只建立基线；同一 Actor 在一次窗口内只广播一次，新窗口可再次命中。当前默认通道是 `ECC_Pawn`，专用 TraceChannel 与敌我过滤仍需配置。[[BossAI/结构|BossMeleeAbility]] 接收命中后应用 [[AbilitySystem/结构|共享命中载荷/伤害 GE/Cue]]，材质标签见 [[Physics/结构]]。

## 判定防护增量（独立自动化通过，真实动画接入待验收）

无效 Mesh/Socket/半径拒绝开窗，缺失 Socket 不回退原点。分段数由上帧/本帧最大长度除半径向上取整，默认预算 64，超预算关闭并告警。唯一 `uint64 WindowSerial` 在每次成功开窗时递增，关闭不递增、不重置；耗尽后返回 `SerialExhausted`，禁止回绕复用。`bIsTracing` 与 serial 校验原窗口；Legacy 广播返回或 Owned 每次原生回调返回后，窗口关闭/替换即退出旧扫掠，禁止写回后继窗口基线。该身份只保护组件查询生命周期，不承担 GA Activation 状态机或另建调度器。

私有 `CloseCurrentTraceWindow` 是统一执行清理入口：先使原窗口失效并脱离其订阅，再关闭 Tick、清空上一帧两端、baseline 和本窗口命中去重，最后释放回调持有资源。公共 `EndTraceWindow` 只清 Legacy；`CloseOwnedTraceWindow` 只清匹配原身份的 Owned 窗口。内部判定失败及 `Deactivate`、`OnUnregister`、`EndPlay` 使用私有入口；生命周期清理栈内拒绝重入开窗，重复关闭幂等，重新注册不继承旧窗口状态。Trace 使用 Combat 自有日志类别，不依赖 GA/GAS，不拥有伤害、位移或能力终止机制。

### 原窗口接口（已实现）

下列原生接口在 GameThread 调用，不新增反射接口或第二窗口状态。句柄只有组件能签发，内部保存签发组件弱身份与 serial，可复制、比较；`HasWindow()` 仅表示曾签发，当前资格必须查询。没有公开的“取得当前窗口句柄”入口，也不维护历史结束原因缓存。

| 接口 | 输入、作用与结果 |
| --- | --- |
| `TryOpenOwnedTraceWindow(StartSocket, EndSocket, Radius, ExpectedWindow, OutWindow)` | 空 Expected 只取得空闲窗口；非空只替换本组件仍活动的同一 Owned 窗口。先快照 Expected 再清 Out，允许两参数引用同一变量。成功返回 `Opened` 与新句柄；旧身份/已有窗口冲突返回 `WindowConflict`，非法/异组件预期返回 `InvalidExpectedHandle`，均不改当前窗口。授权替换后配置/可用性失败结束原窗口并返回 `InvalidConfiguration` / `Unavailable`，不继续旧业务；身份耗尽返回 `SerialExhausted`。失败 Out 为空，不接管 Legacy。 |
| `CloseOwnedTraceWindow(Window)` | 仅匹配原窗口时返回 `Closed` 并清理。已结束/被替换返回 `AlreadyInactive`，不触碰后继；空句柄或异组件返回 `InvalidHandle` / `WrongComponent`。失败不得回落到无身份 `EndTraceWindow`。 |
| `QueryOwnedTraceWindow(Window)` | 返回 `Active` / `Inactive` / `InvalidHandle` / `WrongComponent`；Inactive 包括已结束或被替换，不猜测当前 Activation。 |
| `SubscribeWindowHit(Window, Callback, OutSubscription)` | 仅为确切活动 Owned 窗口及已绑定回调返回 `Subscribed` 与独立 `FDelegateHandle`；其余明确返回 `InvalidHandle` / `WrongComponent` / `WindowInactive` / `InvalidCallback`，输出令牌为空。原生 `FGGYGOMeleeTraceWindowHitDelegate` 回调携 `(OriginalWindow, HitActor, HitResult)`，开窗/订阅不同步发命中。 |
| `UnsubscribeWindowHit(Subscription)` | 按确切令牌移除，成功 true；不存在或已清理 false。窗口结束自动退其订阅；旧令牌不能移除后继订阅，不使用按对象全量解绑。 |

Owned 分发先快照原窗口与回调集合，逐项检查原窗口仍活动、令牌仍在，再外调并复核原窗口。退订的快照成员跳过；新增订阅从后续命中开始。若 B 的原命中回调关闭 B、开启并订阅 C，立即中止 B 的后续分发/扫掠/基线回写；C 首次 Tick 自行建基线。消费者按注册时的原 Activation、原资源来源及回传窗口核验，不通过回调时读取可变“当前 Activation”补认领。**Combo/Boss 已消费这条 Owned 资源契约**；Legacy Begin/End/OnMeleeHit 仍作为兼容入口保留，连续 Legacy 窗口之间仍不能证明某个旧 GA 只关闭自己的原窗口。C++ 消费接线不等于正式蓝图绑定已迁移或已核查，Owned 不额外复播旧全局事件。

### 生产消费者与原资源清理（共同生命周期接线）

窗口身份、查询、baseline、去重和 Tick 唯一归 Combat；消费者保存的窗口/token 是其原 Activation 所持资源，不是另一份活动窗口权威。Activation、结束/取消及完成发布归 [[AbilitySystem/结构|GAS共同生命周期]]，原 Montage/输入任务各自管理自己的资源；本组件不新增 GA 状态、计时器或第二执行链。

| 消费者 | 已实现的开窗/命中/清理接缝 |
| --- | --- |
| `UGGYGOPlayerComboAbility` | 原 Montage Event → `OpenTraceWindow(Original)`：先 `ReleaseTraceWindow(Original)` 退本段原资源，再 `TryOpenOwnedTraceWindow` 取得窗口并 `SubscribeWindowHit`。回调按值捕原 Activation、step token、原 Task/Trace 与 OpenedWindow，核段/来源、回传窗口及 `QueryOwnedTraceWindow==Active` 后进入生产 `HandleMeleeHit`。HitWindowEnd/换段释放仅清自己的原窗口；`CleanupAbilityResourcesForTermination(Context)` 匹配原资源 Activation 后先快照、脱开成员，再按确切 token 退订、按原窗口关闭，并恢复自己持有的 Mesh/任务等资源。 |
| `UGGYGOBossMeleeAbility` | 原 Montage 回调核原 Task/资源批次；已有窗口查询为 Active 时重复 Begin 保留本窗去重，Inactive 才释放旧资源并重新开窗。`FOriginalMeleeResources` 保存不可变 Original、原 Trace、Window/WindowHits；弱回调捕原批次/Activation/Trace，在 `HandleOriginalMeleeHit` 中核回传窗口、原批次来源、窗口活动及权威。`CloseOriginalTraceWindow(Resources)` 先清批次窗口/token，再精确退订/关窗；共同 Cleanup 匹配 Context 后先脱开整个原批次，归还自身持有资源。 |

开窗或订阅失败明确诊断并按消费者真实生命周期处理；不改用 Legacy End、另一窗口或另一能力。原命中可否执行由消费者核自身原 Activation/来源与权限；终止清理按原 Context 的资源归属执行，不要求仍用“GA 当前活动”重新认领，也不向 Combat 转移能力结束权。

两者命中依赖失败政策不同：显式无 GE 是共享 Builder/Combo 的正常 Cue 模式；Boss 仍要求 ResolvedGE 与有效必需 Spec。Combo 的必需 GE/Builder 运行期失败经 `RequestAbilityEnd(Original, true, true)` 结束该原动作，即使用户取消被禁用也不继续错误业务；Boss 的伤害类/Builder/必需 Spec 失败只拒绝该次 hit，不据此自动结束整个能力。有效载荷下各自继续 GA/GE/Cue 路径；GE 免疫/应用拒绝不吞掉既定碰撞 Cue 政策。伤害数值、配置模式和这些响应均归消费者/GAS，Trace 只报告同一 `HitResult`。
