`AGGYGOCombatantState : AInfo, IAbilitySystemInterface, IGGYGOAvatarBindingHostInterface` 是玩家 Slot 与 BossState 共用的最小外置 ASC 宿主。构造时拥有 ASC、HealthSet、CombatSet 默认子对象；玩家编队、Boss选招／阶段及能力授予不下沉到本类。

## 状态所有权与依赖方向

- Host 持有 ASC 与基础属性集，拥有 Avatar 选择／复制、自己的 Pawn 销毁订阅及唯一的绑定生命周期关闭。Destroyed／EndPlay均先于Super进入私有Close；仅借用Extension颁发的原H、ASC原Context和弱Extension，不另发绑定身份或维护第二ActorInfo。
- [[AbilitySystem/结构|ASC]] 唯一执行 ActorInfo事务、绑定身份、能力取消、Cue移除及真实发布；原已提交清理来源和失败Init实际写入证明也唯一归ASC。Host只给原Context／Operation及纯作用域查询，不再签第二证明。步骤历史不授当前资格。
- [[Character/结构#ASC 本地资源四阶段接口（L1）|PawnExtension]] 唯一拥有本地资源及 Installed／Ready／Withdraw／Released语义。Host已调用四阶段；Extension三个兼容入口已请求Host，Getter只认真实Ready，不保留第二套原生ActorInfo执行或旧ASC缓存。
- [[Teams/结构|CharacterSlot]] 与 [[BossAI/结构|BossState]] 继承共同宿主，分别提供 PawnData／BossDefinition及Authority能力授予。
- Health拥有Pawn本地死亡阶段及自己的唯一原资源记录；记录持原H、认证Context、ASC／HealthSet弱引用和五个精确token。Base只持原Extension通知token，将Ready／Refreshed／Released typed Notice转交Health的原H入口，不另存ASC／H／Ready。两者源码已接，当前Avatar一致才单调投影Dying／Dead。

依赖方向：派生宿主 → CombatantState → ASC与Character的原生资源端口；Base消费Extension typed Notice再调用Health。各自只清自己的原资源，不新增帧调度器或ActorInfo执行链。Hero A动作消费者已源码冻结、有限接受；B的typed H／Source→CMC尚未接，整链仍未完成。

## 关键接口与资源输入输出

| 接口 | 输入／前提 | 作用、结果与清理归属 |
| --- | --- | --- |
| `GetAbilitySystemComponent()`／`GetGGYGOAbilitySystemComponent()` | Host默认子对象已构造 | 返回持久ASC；不是Pawn本地Ready资格查询。 |
| `RequestAvatarBinding(Request)` | 原ExpectedHost／ASC／Pawn／Extension、Operation、Context及原H；Initialize要求空H | 同步协调Initialize／Release／Refresh；返回真实Outcome／Reason／Steps。ASCResult保留实际bCommitted，LocalResult保留本地改变；结果不授当前Ready或清理后继的权限。 |
| ASC `CheckAvatarBindingCleanupContext(ExpectedContext, OutReason)` | 已提交的原完整Context；Host原端点／H／槽另由纯query重检 | ASC认证原issuer、write、allocation及actual快照；Succeeded可包含精确Revoked／有效Destroy原对象的清理来源。仅供原资源Cancel／Cue／Clear，不授Init／Refresh／Ready资格。 |
| ASC `TryCleanupFailedAvatarActorInfoInit(OriginalOperation, IsOriginalCallerCurrent)` | 原Init完整返回、未commit且原Result.Operation有效；query固定原端点／选择／入口空H及本地槽 | ASC仅消费自己保留的原失败actual写入证明，执行物理Clear。缺Proof／后继写入返回真实拒绝；不commit、不发Receipt／Notice／Ready，原Init仍失败。 |
| `AttachAvatar(NewPawn)` | Authority，Pawn含Extension，禁止隐式抢占其它原资源 | 兼容选择入口先捕原资源；不同Pawn先原Release、核对自身Clear提交，再Initialize。跨Host由外层显式旧释放→新绑定，新绑定失败保持未绑定，不自动回滚。 |
| `DetachAvatar(ExpectedPawn)` | Authority；ExpectedPawn只筛选原资源目标 | 清理权限来自原H／完整Context，不来自当前找到的Pawn或ASC。无原资源幂等返回。 |
| `OnRep_AvatarPawn()`／`SynchronizeAvatarBinding()` | 原服务器复制选择 | 走同一协调请求链；客户端不能自行选择未复制的Pawn。每次外调后旧栈只认原范围，不覆盖后继。 |
| `Destroyed()`／`EndPlay()` → 私有 `CloseAvatarBindingLifecycle(EntryPoint)` | 原Host生命周期关闭；固定原ASC／完整Context／H（若有）／selection | 两入口均先于Super调用唯一Close，覆盖pre-BeginPlay Destroy。先关准入，重复入口不重捕；有H复用原Release，无H由ASC认证原Context后真实ClearActorInfo／Receipt发布。Busy／失败保留；只退役原Context或自己的Clear Commit，Invalidate不等于物理Clear。 |

端点事实：ASC由Host `CreateDefaultSubobject` 创建，组件 `GetOwner()==Host` 在Request入口校验。Release／Refresh消费者可从原H指向的ASC组件Owner捕获端口；不能用会变化的ActorInfo Owner猜旧Host。接口定义见 [[Character/结构#Host原生请求接口（已定义，生产迁移中）|原生请求端口]]。

## 关键实现：实际提交、发布与退出

### 初始化与Ready

Host向ASC发原Context的原生Init请求；实际Succeeded且bCommitted后才安装Extension本地H。Host公布自己的原H／Context／Avatar与销毁订阅，然后调用ASC `PublishAvatarBindingNotice`。

栈内订阅桥必须认证原Receipt、同一After／Operation及真实 `IsAvatarBindingNoticeDispatching`，才调用Extension `NotifyLocalResourcesReady(H, Receipt)`。发布前纯查询只检查Installed与原范围，不以Ready为前置形成循环；Refresh使用同一原H和真实新发布，不代替首次Ready。桥的精确FDelegateHandle由原调用栈归还。

Ready／Released普通回调允许立即完成后继；旧栈失去原身份后停止，不能排队补播、改读当前H或执行尾部清后继。

### 原资源释放

实际主链为：`WithdrawLocalAbilitySystemResources(H)` → ASC原Context取消非SurvivesDeath能力 → 原范围全输入退休 → 移除原Cue → 明确模式的Clear事务 → 退Host原资源及原Pawn订阅 → 真实发布桥消费 `NotifyLocalResourcesReleased(H)`。

H1中，Release输入清理前及已提交Init失败收尾用 `CheckAvatarBindingCleanupContext`，不复用新工作准入。ASC唯一判断原来源；Host的pure query只检查原端点／完整Context／H／opaque槽和原选择，允许仍有效已分配的原对象处于Destroy／EndPlay，不要求Ready或Withdraw后的Installed。

Clear发出前由Host明确选择：原Owner／ASC组件宿主正在Destroy，或Host本次生命周期已关闭时请求 `ClearActorInfo`；活跃持久宿主普通解绑请求 `PreserveOwner`。拒绝后不换模式重试。组件 `GetOwner()==Host` 的端点身份保持；完整Clear清的是ActorInfo，不是替换ASC组件或复活业务。实际提交后才进入真实Released发布。

每一步保存真实结果并重检原H／Context／opaque槽。Release不要求Ready或新安装准入；Extension关闭时仍可退休原通知义务，真实Failed／LifecycleClosed不能写成已通知观察者。安装后未公布到Host的失败分支也只能清它自己安装的原H；失败保留，不制造成功。

Host依赖ASC `ClearAbilityInput` 的全局无回调退休边界；Hero自身资源退出以后应精确撤自己的输入请求，不能复用Host的全清入口。

### 未提交Init的原写入清理

H2覆盖Avatar及owner-only Init失败分支。完整Try返回后，只有 `!bCommitted`且原 `Result.Operation` 有身份才请求 `TryCleanupFailedAvatarActorInfoInit`；Issued不等于一定有清理Proof。ASC失效无法调用、缺原Proof或后继实际写入已退休来源时，保留明确诊断或接口真实拒绝，不改读当前Context／ActorInfo构造旧证明，不回滚、不清当前、不重试。

独立pure query固定原Host／默认ASC／组件Owner、原选择及入口空H／本地槽；Avatar请求还固定原Pawn／Extension。query允许有效Closing原对象，不复用要求新工作开放的Init查询。owner-only没有Avatar安装记录，不虚构Extension资源。

原 `ActorInfoInit` Step和顶层失败Outcome／Reason保持，清理另记实际 `ActorInfoClear + ASCResult`。物理清理Succeeded不等于原Init成功，不产生Commit／Receipt／Notice／Ready；owner-only仍返回false，并分别诊断原失败和清理结果。原actual写入证明和Busy窗口唯一归ASC，Host不建快照、证明缓存、计数或执行器。

### Host生命周期关闭（H3）

PostInitializeComponents可在BeginPlay前建立owner-only或Avatar ActorInfo；仅靠EndPlay不能覆盖pre-BeginPlay Destroy。H3让Destroyed与EndPlay在各自Super前调用同一个私有 `CloseAvatarBindingLifecycle`，由Host承担绑定退出，不让派生宿主重建清理链。Destroyed进入Super后再次经过EndPlay时不会重新派发。

首次Close先将既有 `bAvatarBindingPermitted` 置false，再固定原Host／默认ASC／完整Context／H／selection。重复入口在任何快照前void返回，不重捕回调后继；该flag仅是准入与单次派发边界，不记录清理成功。真实下一次BeginPlay的重开机制保持，关闭后的原资源清理不借用新工作资格。

有H只发捕获的原Request.Release，复用H1／H2并保留真实步骤历史；退休Context仅能取入口原请求或该次ActorInfoClear的真实bCommitted。不能用当前不同Binding替代原H来源，也不从回调后的Getter找新资源。

owner-only无H时，以原ASC／原Context调用 `CheckAvatarBindingCleanupContext`。pure query固定原Host／默认ASC／组件Owner、原selection、空Host H及本次已关闭准入，不读当前Context／ActorInfo造来源，不要求Ready／Installed。ASC认证后显式一次 `ClearActorInfo`真实事务，记实际ActorInfoClear结果；Succeeded且commit后用原真实Receipt发布ASC Notice并记实际Publish返回。没有Extension安装记录，不伪造H、Released通知或本地发布桥。H2未提交Init清理仍无Commit／Receipt；H3的已提交Context清理是独立的真实Clear事务。

最后仅Invalidate入口原Context或自己的真实Clear Commit；提交后Outcome变Stale仍保留本次Commit历史，后继Context不符则退休请求真实拒绝。Invalidate的元数据退休Accepted与物理Clear结果分开。Busy、无原已提交Context、原ASC失效、query／Clear／Publish失败均保留实际结果与可定位诊断，不能因flag关闭或Invalidate成功写成已清理；不换模式、重试或排队，第二生命周期入口不补清。

## 配置复制与死亡投影

- CharacterSlot的OnRep_PawnData与Authority初始化复用幂等规则配置；AbilitySet只由Authority InitializeForPawnData授予。
- BossState的OnRep_BossDefinition与Authority初始化按初始形态PawnData安装规则；Boss AbilitySet只由Authority InitializeFromDefinition授予。
- Health的StartDeath投影Dying；FinishDeath保持Dying并投影Dead。晚绑定补阶段但不重放死亡事件；解绑不清持久ASC死亡标签，NotDead不等于隐式复活。

当前不包含复活、死亡后重新挂接或完整Boss换形态业务；这些由派生模块与明确请求组合提供。
