# Combatants：持久 ASC 宿主结构

> [[GGYGO_结构_Combatants.canvas|结构图]] · [[GGYGO_流程_角色初始化.canvas|跨模块初始化流程]] · [[计划蓝图|返回导航]]
>
> 2026-11-03：绑定改为 Lyra 式——宿主释放旧 Avatar 后调用原生 `InitAbilityActorInfo`，由新 Pawn 的 PawnExtension 广播 Ready；ASC 不再保存绑定事务、身份或发布记录。

`AGGYGOCombatantState : AInfo, IAbilitySystemInterface, IGGYGOAvatarBindingHostInterface` 是玩家 Slot 与 BossState 共用的最小外置 ASC 宿主。构造时拥有 ASC、HealthSet、CombatSet 默认子对象；玩家编队、Boss选招／阶段及能力授予不下沉到本类。

## 状态所有权与依赖方向

- Host 持有 ASC 与基础属性集，拥有 Avatar 选择与复制（`AvatarPawn`）、对当前 Avatar 的 `OnEndPlay／OnDestroyed` 订阅及绑定进行中标志；绑定流程由它编排，ActorInfo 只经原生 `InitAbilityActorInfo／ClearActorInfo` 写入。
- [[AbilitySystem/结构|ASC]] 只在 `InitAbilityActorInfo`／`ClearActorInfo` 覆盖中清输入，并在新 Pawn Avatar 时通知能力实例、尝试 OnSpawn。能力取消与 Cue 移除用原生接口。
- [[Character/结构|PawnExtension]] 以本地订阅 `FGGYGOLocalASCSubscription` 发布 Ready／Released：订阅时回放当前 Ready，重复 Ready 不回调，Released 只给消费过同一资源的订阅。Hero、CMC、Health、LocomotionFX 各自订阅。
- [[Teams/结构|CharacterSlot]] 与 [[BossAI/结构|BossState]] 继承共同宿主，分别提供 PawnData／BossDefinition及Authority能力授予。换人不重新绑定，每个槽位有独立 ASC。
- Health 拥有 Pawn 本地死亡阶段，自己订阅 PawnExtension（游戏世界中 OnRegister 与 BeginPlay 各尝试一次），当前 Avatar 一致才单调投影 Dying／Dead。

依赖方向：派生宿主 → CombatantState → ASC 原生 ActorInfo 接口；PawnExtension → 本地订阅者。各组件只清自己的资源，不新增帧调度器或第二条 ActorInfo 执行链。

## 关键接口与资源输入输出

| 接口 | 输入 → 作用 → 输出 |
| --- | --- |
| `AttachAvatar(Pawn)` | 仅服务器；nullptr 表示解除 → `BindAvatar` → `EGGYGOAvatarBindResult`：`Bound`、`AlreadyBound`（同一 Pawn）、`Cleared`、`Reentrant`（绑定进行中再请求，Warning `NestedRequestDuringBinding`）、`AuthorityDenied`、`LifecycleClosed`、`InvalidPawn`、`HostDying`、`PawnBoundElsewhere`。 |
| `OnRep_AvatarPawn()` | 客户端收到复制的 Avatar → 同一绑定流程；客户端不自行选择未复制的 Pawn。 |
| `DetachAvatar(ExpectedPawn)` | 仅服务器；ExpectedPawn 为空或等于当前 Avatar 时解除 → ActorInfo 回到 Owner-only。 |
| `ReleaseAvatarBinding(ExpectedAvatar)`（宿主接口） | PawnExtension 在死亡销毁前请求 → 仅释放仍为当前绑定的 Pawn。 |
| Avatar `OnEndPlay`／`OnDestroyed` | 晚到的解绑；只释放仍是当前绑定的 Pawn。未开局就销毁的 Actor 只有 OnDestroyed。 |
| `Destroyed()`／`EndPlay()` | 关闭宿主生命周期，释放当前 Avatar 并 `ClearActorInfo`；之后的绑定请求返回 `LifecycleClosed`。 |

## 绑定与释放顺序

```text
BindAvatar(NewPawn)
  拒绝：绑定进行中 / 同一 Pawn / 宿主关闭 / Pawn 无效 / 宿主死亡 / Pawn 已绑别处
  ReleaseAvatar(Old, bClearActorInfo=false)
    取消能力（保留 Ability.Behavior.SurvivesDeath）→ ClearAbilityInput → RemoveAllGameplayCues
    → InitAbilityActorInfo(this, nullptr)（宿主关闭时 ClearActorInfo）→ 旧 Pawn 的 Extension 广播 Released
  InitAbilityActorInfo(this, NewPawn) → 订阅 NewPawn OnEndPlay/OnDestroyed
  服务器写 AvatarPawn 并 ForceNetUpdate → 新 Pawn 的 Extension HandleAbilitySystemBound → 广播 Ready
```

Released 在 ActorInfo 解除之后广播，与 Lyra 一致；Controller 变化只 `RefreshAbilityActorInfo`，不经过宿主。

## 配置复制与死亡投影

- CharacterSlot的OnRep_PawnData与Authority初始化复用幂等规则配置；AbilitySet只由Authority InitializeForPawnData授予。
- BossState的OnRep_BossDefinition与Authority初始化按初始形态PawnData安装规则；Boss AbilitySet只由Authority InitializeFromDefinition授予。
- Health的StartDeath投影Dying；FinishDeath保持Dying并投影Dead。晚绑定补阶段但不重放死亡事件；解绑不清持久ASC死亡标签，NotDead不等于隐式复活。

当前不包含复活、死亡后重新挂接或完整Boss换形态业务；这些由派生模块与明确请求组合提供。
