## Experience显式来源配置（09-G3：已编码，未编译）

源码：`Source/GGYGO/GameModes/GGYGOExperienceDefinition.h/.cpp`。C++提供稳定反射字段、纯值转换和校验；具体本局启用哪些插件、各插件来源与默认编队由Experience数据资产配置，不在通用代码硬编码角色。

| 调用方／配置 → 接口 | 输入与作用 | 输出／边界 |
| --- | --- | --- |
| Experience资产 → `GameFeaturesToEnable` | 原有根插件名数组，旧属性序列化保持 | 同名根去重；不是完整依赖列表，也不证明Loaded／Active。 |
| Experience资产 → `GameFeatureSources` | 每个完整GFP闭包节点配置`PluginName`、`Source`、`ExternalOwnerLabel`，包括非Activate依赖 | Managed必须空Label；Borrow必须非空且无首尾空白Label。Label只是声明，不提供保护权限。 |
| GameMode `InitGame`／编辑期 → `TryBuildGameFeatureInput(OutInput, OutErrors)` | 同步检查配置形状及所有根的有效来源，复制根名和声明为Resolver的`FInput` | 全成功才交候选值；失败清空OutInput，错误定位Experience路径、字段、原索引。GameMode失败明确拒绝；转换本身无native、policy、加载或Ready。 |
| 编辑期 → `IsDataValid(Context)` | 调用同一转换并追加全部错误，再执行既有Squad校验 | 编辑期Valid仅说明配置形状；完整URL／依赖与来源准入仍由GI／Resolver处理。 |

两数组均空是明确的正常“无GameFeature”配置；只有来源而无根、缺根声明、空白名字、非法枚举、Managed有Label、Borrow无有效Label或同插件冲突声明均拒绝，不静默修剪或默认托管。完全相同声明去重；依赖遗漏、未使用声明和真实URL仍由后续完整闭包解析拒绝。

GameMode的`InitializeGameFeatureSession`已先核对原World／AuthGameMode／GI，再确认Experience有效且`TryBuildGameFeatureInput`返回true，随后才判断`RootPluginNames`与`DeclaredSources`均空的正常NoGF模式；失败空OutInput不能冒充无GF成功。非空成功值进入已保存的原World Session，Session再调用GI。实际来源资产未迁移，完整闭包配置未回读；Borrow形状可合法转换，但GI仍明确拒绝Borrowed，C15未关闭。

原World Active预检发现原生依赖升级可能不重走子树的静态风险，未动态复现。租期`GetActivationPluginURLs`提供完整激活请求值；Session先平铺登记完整请求集合Active，再真实激活根并核对全集合当前实际Active。09-G4-2 GameMode已成为该Session的源码消费者；请求值或完成通知均不直接授予装配资格。见[[GameFeature/结构#不可变激活请求URL（09-G4-0：源码冻结，未生产消费）|请求集合接口]]及[[GameFeature/结构#原World Active会话（09-G4-1：源码冻结，未生产接线）|会话合同]]。

项目没有自定义GameInstance；薄GI子系统利用原生collection实现，不扩展到UEngineSubsystem。Experience→GameMode→Session→GI的源码调用现已接通；当前退场仅移出并Close自身原Session。两种项目资源生命周期分开，GameMode结束不能释放GI跨地图Loaded保留。

独立 PIE 各 GameInstance 分别持有保留需求，插件状态仍在进程内共享；本实例终止不能误停其他原生 Active 持有者。GameInstance 结束后可按剩余原生需求清理，**不保证 PIE 停止后永不卸载**；World 的 Action 隔离还需独立验证。

GI在受限正常生命周期内同步调用冻结解析器、校验全Managed并连接原Loaded加载；Session消费GI租期与完整激活请求值，GameMode已消费Experience输入、原Session与当前成功资格。实际来源资产、插件运行、跨图／停用、外部借用和PIE Action隔离仍未验。根Loaded加`TrackDependencies`不足以证明全部依赖Loaded，`IsActive`不能证明本局所有权。原World观察者抑制、GameMode双入口关闭与自身Active排空已有源码；局部幂等或静态接受不证明整链动态退场安全。完整目标见[[计划_GameFeature#11.4 最终策略：只停用、不卸载（目标，未实施）|生命周期计划]]。

本策略只涉及实际GameFeature内容，不表示Kevin、Camera或GAS C++模块已经插件化。本次GF-N4只同步四份既有局部图文到09-G4-2冻结消费者；Teams三段Spawn内部仍未迁移，另租Squad原创建Actor终止消费者也不能替代装配创建责任。Source README及全局入口由后续独立范围维护。

## Loaded 资源核心：提交与精确释放

源码：`Source/GGYGO/GameModes/GGYGOGameFeatureRetention.h/.cpp`。它是资源所有权包装，不是插件状态机；`ESPMode::ThreadSafe` 只保护共享内存寿命，API 仍要求游戏线程。

| 调用方 → 接口 | 输入 / 前提 | 实际输出与副作用 |
| --- | --- | --- |
| GI Initialize → `TryCreate(OwnerLabel, OutError)` | 非空 Label；游戏线程、非退出、原生 lifetime control 启用、实际 Engine/Subsystem 可用 | `InitAndRegister(Label, None)` 创建自己的原生 handle；返回共享资源或明确空/错误。bool 与实际 handle 有效性都核对；不创建 GI 宿主。 |
| 已有受限登记入口 → `RetainAlreadyLoaded(ValidatedManagedURLs)` | 非空 URL 集合；**调用方先证明** GFP 身份、完整依赖与项目管理权限 | 去重后整批先查稳定 `Loaded/Active`；每次 `AddOrUpdateReference(原handle, URL, Loaded, false)` 前后及末尾复核。不触发另一业务、不补来源或自动收依赖。 |
| GI Prepare → `LoadAndRetainValidatedManagedClosure(URLs, Completion)` | 调用方先证明完整已安装／映射GFP闭包、全部显式Managed及合法policy窗口；复制去重且非空 | 同原handle逐URL真实native Load；记录在调用前，全部回调成功＋native完整返回＋Loaded/Active观察才交Loaded。native失败为Failed，关闭为Interrupted，已登记的引用仍归原资源。 |
| 返回 `FRetainResult` | `Rejected / Submitted / Interrupted`，本次 `NumSubmittedURLs` 与 Error | `Submitted` 只证明 void 登记发出，非原生 ack 或整体 Loaded 确认；中途失败可能已有引用，仍归本资源。提交数是调用栈历史，不是使用人数。 |
| GI owner最后归还 → `ReleaseOwnedReferences(Completion)` | GI与原租期已归还，原core仍须排空自身真实pending；Session先完成自身Active释放门禁再归还原租期 | 游戏线程先封闭准入、停止尚未发出的URL，等已发真实回调及调用返回排空，再执行自身 `ReleaseAndUnregister`。错线程明确 `RejectedWrongThread`、资源不变；重复 pending 立即只回 `Pending`，完成后重放原终态，不重试原生。 |
| 原生 completion → `OnNativeReleaseCompleted` / `FinishReleaseIfReady` | 原回调结果＋原生调用完整返回＋handle 已失效 | 三条件满足且前提保持才 `Released`；失败或不能确认分别 `Failed/Unconfirmed`。同步 callback 先记录，不能在 native 尾部尚未注销时提前通知调用方。每次 Completion 至多一次。 |
| 最后共享引用 → 析构 | 仍有效的原 handle | 移出原 handle，独立清理不捕获裸 this/GI/World、不调用 AsShared；必要时仅借 Core 已有 game-thread 队列一次投递。引擎退出或机制失效明确未确认，不裸 API 兜底。 |

正常 API 调用以栈内/回调共享引用保活该资源；core 的 closing/pending/终态仅描述**这一份资源释放**，不是第二套插件状态。`None` 与 `bCollectDepends=false` 明确不替调用方取得依赖闭包。

## GI薄宿主与原World租期（09-G2：已编码，未编译）

源码：`Source/GGYGO/GameModes/GGYGOGameFeatureSubsystem.h/.cpp`。原生GI collection为正常Game／PIE创建`UGGYGOGameFeatureSubsystem`，无自定义GI类或新配置；当前实际值通路为Experience成功转换→GameMode保存并Start原Session→GI Prepare。GameMode不直接取得或释放GI Loaded资源。

| 接口／资源 | 输入、作用与输出／归还责任 |
| --- | --- |
| `Initialize(Collection)` / `Deinitialize()` | 创建一个ordinary owner持原Retention；GI结束先关闭准入并撤GI共享持有，不提前释放仍被原租期持有的资源。 |
| `PrepareManagedLoadedClosure(World, FInput, Completion)` | 按值显式roots／来源；完成可同步。当前World／正常GI合法窗口内解析候选，全部节点显式Managed且无Borrowed才实际调用Loaded加载；失败交空租期和原错误，不授Active资格。 |
| `FGGYGOGameFeatureLoadedLease` | 完成前已构造；强持同一个ordinary owner，弱持原World及不可变根／激活请求URL快照。pending completion持原租期；Session强持到自身真实pending及Active释放门禁完成，异常未确认时保留。 |
| `GetRootPluginURLs()` | 返回原复制根URL只读view，使用view时保活原租期；不是当前插件状态，不能获取或释放native handle。 |
| `GetActivationPluginURLs()` | 返回根及沿`bShouldActivate=true`边可达节点的去重URL只读view；view使用须保活原租期。是本次请求值，不是Active状态／句柄／释放权限。 |
| `IsAdmissionOpenFor(World)` | 游戏线程核对原World／GI准入，只描述该请求可进入，不证明policy Ready或Active成功；不能转交新World。 |
| 最后原owner归还 | GI持有与所有原租期都归还后调用既有`ReleaseOwnedReferences`；仍在原core真实加载排空门禁内。异常非GT归还明确诊断，使用原core独立清理，不新建调度器。 |

合法policy窗口只支持已核对的正常引擎Game／PIE创建与关闭次序；同步读取当前policy后不持有。exact `UGGYGOAssetManager` 的 `HasCompletedSharedAssetPreload()` 只作为既有启动尝试完成的额外拒绝条件，失败资产也算尝试完成，**不是GF Ready标志**。对象存在、Outer或bool admission都不能单独证明就绪。手工／RPC GI、动态policy／subsystem重载、初始化／关闭重入、不稳定元数据不在受限合同内。

实际顺序：原GI owner → 原World／显式输入准入 → Resolver → 整闭包Managed校验 → 校验并复制激活请求URL → 已构造原租期 → Retention真实逐URL加载 → Loaded且原World仍开放才交租期。原World退出／替换或GI关闭后的晚到成功改为Interrupted＋空租期；原生失败保留，不自动重试。缺声明与Borrowed均在native前拒绝，C15未完成。GI拒绝空闭包；GameMode仅在转换成功且两份配置数组均空时选择明确NoGF模式，不把坏配置回落为空。

## 不可变激活请求URL（09-G4-0：源码冻结，未生产消费）

`PrepareManagedLoadedClosure`在Resolver及全Managed校验后、native加载前构造两份自有值：原根URL与激活请求URL。`FGGYGOGameFeatureLoadedLease::GetActivationPluginURLs()`返回私有`const TArray<FString>`的`TConstArrayView<FString>`，调用方保活租期；不保留Resolver指针、policy或插件运行状态。

### 启动门禁与原生唯一权威

真实Loaded成功并交原租期后，Session验证两份非空唯一URL快照和根⊆激活请求集；`InitAndRegister(Label, None)`只建立一个GUID，bool与实际有效性均核对。**先对全部`GetActivationPluginURLs()`逐项`AddOrUpdateReference(handle, URL, Active, false)`平铺登记，再对`GetRootPluginURLs()`逐根调用带原handle的原生`LoadAndActivateGameFeaturePlugin`**。void登记非ack；请求集不是当前Active状态，false-only节点仍由GI完整Loaded闭包保留。

每个真实根pending先登记再native调用；同步完成不能绕过整批dispatch返回或GI Prepare调用返回。所有真实根回调成功、准备和dispatch调用完整返回、pending清空、全激活集合实际`Active`且原World／租期准入仍开，才发布Ready；发布前再核原身份。失败保留原native错误，**native Failed优先于Interrupted**，失败／关闭停止尚未发出的根，已发项真实排空。先摘观察者再通知，至多一次；观察者应弱绑定并复核同一Session／原World。显式Close或旧World已无效时抑制业务通知，原native资源记账继续，不能通知新World。

`WorkKeepAlive`只保活这一份资源的真实未完成工作（Loaded准备、根请求、释放）；实际回调另持共享Session，未收到真实完成不会清pending、伪造Closed或超时替代业务。状态字段仅描述自身操作历史与资源寿命，不新增插件状态机、使用计数、policy缓存或Tick／Timer。

### 关闭、租期归还与独立清理

Close先撤观察者，真实工作与调用栈排空后才`ActiveHandle.ReleaseAndUnregister`。释放callback先记录，**callback到达＋释放调用已返回＋本GUID失效＋原生守卫保持**才交可确认终态并归还原Loaded租期；终态先记录，租期Reset可能引发最后GI owner收尾重入。根／Loaded工作或释放callback尚未到达保持Pending；无自有Active handle且真实工作已排空可直接Closed归还租期，不伪造native调用。

原生true→Closed；守卫正常时原生false→**Failed**，自有引用已在原生降级前撤回、GUID已注销，此时仍归还租期，不能把降级失败称作成功清理。基础设施／lifetime control失效、回调错线程或GUID未按合同失效→**Unconfirmed**并保留租期；缺真实回调仍Pending。终态Close不自动native重试，不能用裸API、另一World或成功结果兜底。

析构独立清理记录接管同一资源；仍须真实release callback、调用返回及GUID失效后才归还租期。没有原生服务、守卫变化、已未确认的失效GUID或丢失回调时，自持记录保留原资源并明确诊断，**可能持续到进程结束**；这是可见的未确认／pending边界，不是已完成回收。正常守卫下native false记录失败后归还已撤引用的租期。
