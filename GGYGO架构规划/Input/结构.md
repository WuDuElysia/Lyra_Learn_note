# Input：结构与接口

> 结构图：[[GGYGO_结构_输入与意图.canvas]] · 流程图：[[GGYGO_流程_输入与意图.canvas]] · 文字计划：[[计划_输入与意图]]

`Input/` 只定义 `UGGYGOInputConfig`（InputAction ↔ InputTag）与 `UGGYGOInputComponent`（按 Tag 绑定并返回解绑句柄）。玩家 Pawn 上的 `UGGYGOHeroComponent::InitializePlayerInput` 是它们的消费者，不属于 `Input/` 源码目录。

| 入口 | 传给谁 | 边界 |
| --- | --- | --- |
| `Input_Move`、`Input_LookMouse`、`Input_LookStick` | `UGGYGOCharacterMovementComponent` / Controller | 连续轴值直接进入移动和视角控制；不激活 GA。 |
| `Input_AbilityInputTagPressed/Released` | `UGGYGOAbilitySystemComponent::AbilityInputTagPressed/Released` | 只提交输入事实，不在回调里决议最终能力。 |
| `AGGYGOPlayerController::PostProcessInput` | `UGGYGOAbilitySystemComponent::ProcessAbilityInput` | 本帧输入回调结束后统一消费。 |
| `UGGYGOHeroComponent` 缓冲与重试 | ASC 的拒绝原因和组释放委托 | 保存待重试的 InputTag；组空出时重新提交激活请求。 |

当前代码的“意图层”主要在 HeroComponent 的缓冲与重试中；没有单独的通用 Intent UObject。计划中的语义意图扩展见 [[计划_输入与意图]]。移动去 [[Movement/结构|Movement]]，能力仲裁去 [[AbilitySystem/结构|AbilitySystem]]。
