## 4. 输入层与意图层

### 4.1 Lyra 的事实（已读源码确认）

Lyra 的输入分成**两条完全独立的路**：

```
路 A（动作 → GAS）：
  按键 → UInputAction → ULyraInputConfig 查表 → FGameplayTag(InputTag.*)
       → ULyraInputComponent::BindAbilityActions
       → ULyraHeroComponent::Input_AbilityInputTagPressed(InputTag)    [LyraHeroComponent.cpp:343]
       → ULyraAbilitySystemComponent::AbilityInputTagPressed(InputTag) [:351]
       → 按 Tag 扫描 Spec，缓存 Handle
       → ProcessAbilityInput（每帧）→ TryActivateAbility

路 B（移动/视角 → 不走 GAS）：
  按键 → BindNativeAction(InputTag_Move / Look_Mouse / Look_Stick / Crouch / AutoRun)
       → ULyraHeroComponent::Input_Move / Input_LookMouse ...           [:285-289]
       → 直接 AddMovementInput / AddControllerYawInput
```

**关键结论：Lyra 的移动完全不经过 GAS。** 只有跳跃、开火、交互这类"动作"走 Ability。GGYGO 与此一致（D3）。

两个值得抄的细节：
- `AddAdditionalInputConfig` / `RemoveAdditionalInputConfig`：运行时增删输入配置。**队伍换角色时正好用它换掉整套角色技能键位**。
- `NAME_BindInputsNow`：通过 `UGameFrameworkComponentManager` 广播的扩展事件，GameFeature 插件可以在这个时机注入输入绑定。

### 4.2 意图层：要有，但位置和职责必须收紧

**同意加意图层**，理由是 Lyra 的 `InputTag → Ability` 是一对一硬映射，动作游戏里同一个按键的语义依赖上下文：

- 轻攻击键在地面是普攻、空中是空袭、闪避后是反击
- 长按 0.3 秒变蓄力，连按变连段
- 方向键 + 闪避 = 定向闪避，无方向 = 后跳
- 攻击键在受击硬直窗口内按下，要进输入缓冲而不是丢弃

这些都是"一个物理输入 → 多种语义动作"，用 InputTag 直连表达不了，会退化成在每个 GA 的 `CanActivateAbility` 里塞上下文判断，逻辑分散且无法做输入缓冲。

**但意图层必须严格限制在"解释"，不能碰"执行"：**

| 意图层**可以**做 | 意图层**不可以**做 |
|---|---|
| 读原始输入与输入历史（长按时长、连按次数、方向） | 决定角色实际执行什么动作 |
| 读只读的上下文（CMC 的 MovementMode、ASC 的 Tag） | 修改 ASC 状态、应用 GE、改变属性 |
| 记录本解释层输入历史、首观察及候选的原有效窗口（目标设计） | 在 Hero 再建 ASC 激活失败等待／许可，或直接改 Actor 位置／播放动画 |
| 产出结构化的候选动作请求 | 跳过 GAS 自己"执行"这个意图 |
| 把意图翻译成候选 Ability 的 InputTag | 决定最终哪个 Ability 胜出（那是仲裁层的事） |

**意图层的输出只有一件事：一个带优先级的候选动作请求，交给仲裁层，最终仍然通过 ASC 的既有受控 `TryActivateAbilityWithTerminationBoundary` 进入原生 GAS。候选解释不拥有重试许可／等待或第二帧消费。**

这在联机下是硬要求。GAS 的客户端预测建立在"客户端调 `TryActivateAbility` → 生成 PredictionKey → 服务器验证"这条链上。如果意图层自己决定并执行了动作，就没有 PredictionKey，服务器无法验证，客户端也无法回滚。**意图层只跑在本地、只产出请求。**

### 4.3 落地结构

当前生产职责分布如下；I1／X1／C2 的本轮有限验收已闭合，其他输入／移动／网络范围按各自证据区分：

| 所属位置／类 | 唯一职责与所持资源 |
| --- | --- |
| InputConfig／InputComponent | InputTag↔InputAction配置与native绑定句柄，不决定GA。 |
| PlayerInput／原RouteObserver | 唯一原生物理观察、Movement来源Session／Request／Fact发行及原路由资源；不持CMC执行／FAILED。 |
| MovementInputTypes／OriginResource | 中性身份值；初次资格及原生创建票据分别由原资源管理，不复制held。 |
| HeroComponent | 原 native Session 的 IMC／绑定／Action 首观察、原 ID／deadline；typed H 订阅及派生 association；原移动 Scope／薄映射通知，装配 Source→CMC。 |
| PlayerController | 在原PostProcessInput驱动ASC统一消费；不新增帧调度器。 |
| ASC／CMC | ASC唯一原请求、Spec held／Queued许可、有序等待及既有 Process；CMC唯一移动执行与失败门禁。 |

首次真实Action Triggered先安装观察，锁定Tag和原绝对deadline，再尝试Receive。未Ready、无效窗口或拒绝留下无ID的已观察记录，同Action不补发；原生Injected／Chord／Combo属于正常Action来源。Completed和Canceled对已分配原ID调用End(Released)，绑定／输入／ASC失效精确End(Invalidated)。

ASC 在真实 Try／Can Queued 失败时先给原请求／Spec 提交许可与等待，再调用 Super 失败观察；完整 Retryable 通知仍在外调返回并重验后发出。GroupFreed 快照并消费整个有序等待集合，仅排入下一次既有 Process，不内联 Try、不按 GroupTag 猜配。重复 notice 保持原次序，候选被消费后仅新实际 Queued 失败可再次入尾；许可在 Try 前耗尽。同 Spec 每次 Process 至多一次，无第二 Tick／等待表／跨帧 Valid。Hero 不再持旧缓冲或生产 Retryable／GroupFreed 订阅。

4.2的上下文语义意图层仍是未来设计，没有独立Intent UObject。原生Action观察不等于通用物理键解释器。需要蓄力、方向普攻或空中变招时，再由真实业务决定解释层形态。

**连段边界**：不同能力实例的 `SingleInstanceQueued` 失败只有 ASC 的原请求／Spec 获有限许可，组释放依原截止唤醒；同一活跃普攻 GA 的段请求由该 GA 缓存、Task／Montage窗口解释，不能混入第二激活等待。正式连段资产与业务验收以 [[计划_玩家普攻连段]] 为准；本轮不重新验收全部连段。见 [[GGYGO_流程_战斗链路.canvas]]。

### 4.4 移动输入

移动／视角不进GAS。当前Move使用捕获原Scope的`FInputActionInstance`回调，核原Session／Binding及Source `GetMovementInputRequest`真实held证明后，按原镜头yaw投射两次`AddMovementInput`。Look仍走原`BindNativeAction`和Controller yaw/pitch入口。

移动轴值只是方向／大小；轴零、Acceleration零、Action Completed/Canceled或H Released都不能替代Source的真实物理Released／Neutral证明。

### 4.5 移动来源与当前实施边界

### 4.6 Hero身份订阅与生产装配

B1生产BeginPlay先持原记录并注册Extension typed Notice，Ready只为既有 native Session 建立原 H association；输入后建立时在Initialize尾部关联。Refreshed同H不重绑、不改输入代次或IMC。晚返回token、退订与请求精确退休都限定原记录/H，ASC仍独占ActorInfo及publication。见[[Input/结构#Hero本地ASC身份订阅与原H清理|H接口与清理]]。

B2的原移动Scope／薄Observer在自身IMC添加前建立；仅真实映射重建通知且自身注册计数已齐才装配。依次原CMC serial→Source Begin并持原Session→CMC Bind CAS并保存Binding→Attach；H Ready不是其前置。原Receiver直交捕获原CMC，Move只读原Session GetRequest。见[[Input/结构#Hero移动来源装配与精确退出（B2）|装配与退出接口]]。

原 H 在 Withdraw 摘槽／EndPlay 关准入时发布一次 Closing（空 Context），不表示 native Cancel／Clear成功。Hero 先退休匹配原 H association／observations，再 exact End 原 SourceASC ID；native绑定／IMC／活动 Action首观察保留，真实 Completed／Canceled才结束旧 Action。原 H 与弱 native Session来源留至真实Released／自身Release，便于精确归还。matching Released 仍独立按原来源释放 native输入；随后核原记录、空 H、native代次与镜头代次再清原 overrides／Camera，不收养后继。C2 的 DataInitialized认证一次camera-provider后直接进 private native core，独立Setup仍走public认证；没有跨帧Ready缓存。

### 4.7 原生观察／恢复义务及能力来源接续

PlayerInput保有唯一原Key/Device raw事实与ObservationRevision；Movement参与／恢复义务只派生自己的边界，End／Adopt不篡改raw或轴完整性。数字真Released及全部必要轴分量归零的证明起始必须晚于原屏障；真实Flush记录连续性缺口，合成松键不恢复。拆分已冻结并进入Gate59编译，正式移动动态未验。见[[Input/结构#原生观察与Movement义务分离|事实与义务接口]]。

能力来源按真实EnhancedInput Action回调＋原绑定／输入会话观察，原生Injected／Chord／Combo允许；不借Movement Session，不要求通用硬件因果证明，不在Hero建物理held。能力Completed／Canceled的Request Released是已确认Action结束语义；Movement Released仍只来自Source真实物理观察。H Released仅本地撤回，SessionInvalidated仅生命周期失效，四者不得混写。

ASC唯一执行held／queued聚合，CMC唯一持有移动执行与FAILED；Hero只解释并持自身观察／资源。本轮 RetryIdentity 与两 Origin 诊断按冻结 finite deadline／普通 Occupant 受控启动契约适配后复测成功；内部 raw 重入与原严格断言保持。首轮失败日志及历史边界保留，有限夹具结果不代替硬件、完整移动、视觉或联机验收。
