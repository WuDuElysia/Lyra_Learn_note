# Messages：只读观察事件结构

> [[GGYGO_结构_Messages.canvas|结构图]] · [[GGYGO_流程_Messages.canvas|发布与重入流程]] · [[计划蓝图|返回导航]]

## 职责与真实接口

`FGGYGOVerbMessage` 是“谁对谁发生了什么”的值载荷。HealthSet 负责数值和边沿，`UGameplayMessageSubsystem::BroadcastMessage(Verb, Message)` 只在当前 GameInstance 同步通知观察者。路由不保存 GAS 状态、不提供网络转发。Messages 没有独立计时器、结算器或伤害规则。

| 字段 / 接口 | 输入与输出契约 |
| --- | --- |
| `Verb` | 消息通道；HealthSet 使用 `Message.Damage`、`Message.PoiseBreak`。 |
| `Instigator` | GE 上下文的 EffectCauser；缺失时为空，不用目标或当前 Avatar 补造来源。 |
| `Target` | HealthSet 的 OwningActor，即 ASC 宿主，不保证是 Pawn。 |
| `InstigatorTags / TargetTags` | 对应 Modifier 的已捕获来源/目标 Tag 快照；不通过消息反向维护 ASC Tag。 |
| `ContextTags` | 通用扩展字段；当前 HealthSet 不额外填入命中部位或暴击语义。 |
| `Magnitude` | 按下表解释，不统一视为实际扣血量。 |
| `RegisterListener / FGameplayMessageListenerHandle::Unregister` | 消费者持有并在结束使用时注销订阅；长期缓存须复制需要的数据并处理参与者失效，不保存载荷栈地址。 |

能力失败的文本/Montage 专用消息仍归 AbilitySystem。驱动指定 Actor 的能力逻辑使用 `GameplayEvent`，见 [[AbilitySystem/结构]]。死亡/破韧逻辑委托与只读观察消息各有消费者，消息本身不请求 GA、不修改 ASC。

## HealthSet 的 Current 结算

GAS 拥有真实聚合器与属性集注册；`UGGYGOHealthSet` 拥有 Health/Poise、meta 消费、可见边界和死亡/破韧锁存。`Health / Poise` 的有限内部 Base 可以低于 0 或高于 Max，聚合后的 Current 限制在 `0..Max`；Max 自身至少为 1。非有限输入明确拒绝并诊断，不选择替代业务值。持续 GE 移除后沿同一 Current 边界与既有归零逻辑执行。

| 调用方 / 关键接口 | 输入、作用与输出 |
| --- | --- |
| GAS → `PreGameplayEffectExecute(Data)` | 对本 Modifier 做免疫和数值合法性校验；meta 用当前资源值调用 ASC 的换算接口做支持性预检，不保存候选 Base。通过才保存对应 EffectSpec、真实来源、Tag 与原幅度；拒绝不留下 Modifier 帧。 |
| GAS → `PostAttributeChange(Attribute, OldValue, NewValue)` | meta 首次写入记录本 Modifier 的实际贡献；资源实际写入保存一次性 setter 标记的真实 Post 值，并在原生委托之前提交 Changed 与归零锁存。新嵌套 GE 的初始写入优先配对。 |
| GAS → `PostGameplayEffectExecute(Data)` | 按原回调身份配对 Modifier，先用 GAS setter 扣除自身 meta 贡献；该 setter 的原生回调返回后再读最新 Current/Max，计算本次有限目标 Current。直接属性 Modifier 的 Post 不重复写值。 |
| HealthSet → `TrySetCurrentValue(Attribute, DesiredCurrent, Frame)` | 请求 ASC 计算 Base；仅 Ready/None 时立即沿原生 `SetNumericAttributeBase` 写入。使用原标记在 Post 捕获的值确认提交，后续回调改变 Current 不改写此事实。拒绝、失配或未确认都有诊断，不重试或回滚别人的写入。 |
| HealthSet → `ASC::TryCalculateNumericAttributeBaseForCurrentValue(this, Attribute, ExpectedCurrent, DesiredCurrent)` | ASC 只做权威侧计算：复核原 Set、ASC、有限 Base/Current 与真实原生聚合来源，返回 Ready / Rejected / Stale、Reason 和仅 Ready/None 可用的有限 CalculatedBase。资格与可逆性归原生 GAS，计算本身不写属性或保存长期缓存；接口归属见 [[AbilitySystem/结构|AbilitySystem 结构]]。 |
| GAS → `PreAttributeBaseChange / PreAttributeChange` | 前者接受有限 Health/Poise Base 越界；后者限制可见 Current 并应用所属 Modifier 的 MinimumHealth。非有限写入明确诊断、拒绝该输入并保留先前值，不把非法聚合表现为正常限幅成功。 |
| GAS → Max 的 `PostAttributeChange` | Current 超过新 Max 时：权威侧以新 Max 为 Current 目标调用同一换算/提交入口；客户端请求原生同 Base 投影。上限变化本身不生成 Damage。 |

开发期 `Cheat_GodMode` 拒绝普通正伤害；`Cheat_UnlimitedHealth` 保留原幅度、来源与有效伤害消息，将对应 Current 下限限制为 1。自毁沿既有绕过规则。Buff 移除后 Current 归零继续触发既有死亡/破韧边沿；没有额外复活或补偿机制。

## 消息发布契约

| 事件 | 发送条件 | Magnitude |
| --- | --- | --- |
| Damage | 正伤害 Modifier 通过校验，且本次 Current 写入已由原帧 Post 事实确认 | 原始 Modifier 幅度，未 Clamp；可以大于实际生命损失。 |
| PoiseBreak：削韧 meta | 本次真实 Poise 正值到零 | 原始削韧 Modifier 幅度，未 Clamp。 |
| PoiseBreak：直接 Poise 写入 | 本次真实 Poise 正值到零 | 本次可确认的正向损失 `OldValue - NewValue`，不把 Override 目标当伤害量。 |

普通削韧、治疗和保持为零不发上述破韧消息；Current 恢复为正后重新打开边沿锁存。客户端限幅投影只产生实际属性/边沿委托，复制差值不重建 GameplayMessage；其回调后的真实 GE 或直接写入仍按各自来源处理。

Damage 候选在原位置保存幅度，meta 清理回调后重新换算；提交失败仅移除该原帧的 Damage 候选。PoiseBreak 由实际 Post 的归零事实生成。Changed 结果先于对应死亡/破韧委托，锁存在通知前提交。

`FlushPendingResults()` 等所有同步 Modifier 与属性联动退出后，把结果先 swap 到局部数组，再依次发布事实。帧与结果只存活于同步作用域，不跨帧重试。GAS 逐 Modifier 执行；同 GE 的 Damage/PoiseDamage 不构成 Health/Poise 原子事务。发布时 ASC 可能已有后续嵌套变化，消息载荷仍描述原事件，观察者不能用实时 Current 替换历史。

## Router 生命周期与发布

`PublishMessageResult(Result)` 输入一条已排队的本地事件事实，逐条复核 Set/Outer、Owner Actor、Owner World 与消息 World、GameInstance 和 Router，再返回以下结果：

| 结果 | 条件与可见作用 |
| --- | --- |
| `Delivered` | 依赖有效，调用当前 GameInstance 的 `BroadcastMessage(Verb, Message)` 同步派发。PreBeginPlay 和没有监听者都是合法状态。 |
| `Retired` | 真实销毁、Actor 正在销毁、World teardown/cleanup 或 GI 销毁使该次发布退休；不追送旧事件。 |
| `DependencyFailure` | Owner 无效或 World/GI/Router 缺失，明确记录模块、Set、Owner、World、GI、Verb、Effect 与原因。每个缺失原因在恢复成功前只报告一次。 |

Router 恢复后诊断标记清零，只发送随后发生的新事件。不自动创建 Router、不缓存重播、不因投递失败撤销结算，也不跳过队列中的属性/边沿委托。来源为空仍保持为空，不用目标、Avatar 或默认动作补造来源。

## 复制、消费者与验证边界

`OnRep_Health / OnRep_Poise` 处理属性复制历史及逻辑委托；复制可能合并多次修改且没有逐次 GE 上下文。客户端消息传输需由明确的传输接口负责，`UGameplayMessageSubsystem` 本身只在当前 GameInstance 派发。

### HealthSet 的复制调用作用域

`FRepNotifyFrame` 保存本次同步宏的阶段、弱 Outer Actor / Owning ASC、显式 Base 写入标记和一次性有效复制快照。它不持有聚合器或长期执行状态。创建钩子和以下辅助接口均为 HealthSet 私有协作机制：

| 接口 | 输入、作用与输出 / 清理 |
| --- | --- |
| `BeginRepNotifyFrame(Attribute)` | 复核活动旧帧，安全确认 Outer Actor 后查询 ASC，保存弱身份并检验实际注册实例。 |
| `CanClassifyRepNotifyFrame(Frame)` | 比较当前 Outer/ASC 与原弱来源，并用 `ASC->GetAttributeSet(Attribute.GetAttributeSetClass()) == this` 确認注册。观察到失配后，本帧直到宏退出都停用分类，切回不复活。 |
| `OnAttributeAggregatorCreated(Attribute, NewAggregator)` | 原参数转发 Super；同属性、来源匹配且未判定的全部活动帧记录迟到创建，包括嵌套 OnRep 外层；不保存或解引用聚合器指针。 |
| `PostAttributeChange(Attribute, OldValue, NewValue)` | GE / Expected write / Explicit Base 配对优先；其余写入按阶段处理，最终复制值和锁存在原生委托前提交。 |
| `EndRepNotifyFrame(Frame)` | 四个 OnRep 的 GAS 宏 Scope 结束时按准确帧身份清理，然后发布属性复制历史。 |

| 调用局部阶段 | 当前含义与转移 |
| --- | --- |
| `Undetermined` | 无迟到创建信号的首个未归属 Post 是已有聚合器临时回退：抑制项目事实、上限联动和锁存，转入等待最终写入；迟到创建则直接转入真实变化。 |
| `AwaitingFinalWrite` | 下一未归属 Post 捕获一次有效复制值、提交锁存后转入真实变化；创建钩子不重置已捕获快照。 |
| `RealChanges` | 后续真实写入继续走 Changed/边沿/消息链，不覆盖复制快照；恢复为正重新打开归零锁存。 |

没有初始聚合器且没有属性 Post 时，复制历史使用入宏前 incoming。来源/注册失配只停用分类，不取消已发生的复制历史、不回滚锁存或清理 GAS；ActorInfo 的 Owner/Avatar 刷新本身不是属性来源换代。宏 Scope 清理后，Health/MaxHealth/Poise 使用 incoming 或已捕获有效快照，不拿迟到恢复后的实时值替换历史，也不回写旧锁存。

### 客户端上限的 NetReceive 投影

客户端 Max 下调只投影原生真实 Base，客户端不调用权威 Current→Base 换算接口。请求由本次 `PreNetReceive / PostNetReceive` 管理：

| 入口 | 输入、作用与输出 / 清理 |
| --- | --- |
| `PreNetReceive()` | 保存本次弱 Owner/ASC 来源并进入 Super 的原生接收批处理；只持请求标记，不保存候选 Base/Current。 |
| `RequestClientMaxReevaluation(Attribute)` | Max 的实际 Post 或 `OnRep_MaxHealth / OnRep_MaxPoise` 宏返回后发现 Current 超上限，记录本次源匹配请求；后者同时覆盖 Max 无聚合器、原生宏只广播的分支。 |
| `PostNetReceive()` | 先调用 Super 结束原生批处理并排空 dirty 工作，再移除本次请求帧；随后用原弱来源执行请求，回调不能重放旧请求。 |
| `ReevaluateClientMax(Attribute, Owner, ASC)` | 重验实际注册与来源、客户端模式和有限 Base/Current/Max；重新读取真实值。已在边界内则无需额外写入；超界时沿 `ASC::SetNumericAttributeBase(Attribute, 同一真实 Base)` 触发原生重新聚合。来源失效、批处理仍开放或非法输入明确拒绝/退休并诊断。 |

不在 NetReceive 内且原生批处理已关闭的 OnRep 可同步投影；仍开放的批处理不假报同步提交。一次性 expected-write 标记确认实际 Post，并只识别该次客户端投影来源；后续原生回调里的真实写入不会被吞掉。GAS 保有聚合器和 dirty 执行，没有独立 Tick、timer、RPC 或第二复制调度器。

### 消费接口与验收记录

观察者通过 `RegisterListener<FGGYGOVerbMessage>(Verb, Callback)` 取得自有订阅句柄，结束使用时 `Unregister`；跨回调保存需复制所需数据并处理对象失效。死亡由 HealthComponent 消费 `OnOutOfHealth` 并转发指定 ASC 的能力事件；`OnPoiseBroken` 提供真实破韧逻辑委托。能力事件走 `HandleGameplayEvent`。

运行证据、历史失败与未验场景见项目现有记录 `AAADocs/Modules/Messages/Module_Repair_13_Validation.md`；调用链见 [[GGYGO_流程_Messages.canvas|发布与重入流程]]。
