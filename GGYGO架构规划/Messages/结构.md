## 职责与真实接口

`FGGYGOVerbMessage` 是“谁对谁发生了什么”的值载荷。HealthSet 负责数值和边沿，`UGameplayMessageSubsystem::BroadcastMessage(Verb, Message)` 只在当前 GameInstance 同步通知观察者。路由不保存 GAS 状态、不提供网络转发。Messages 没有独立计时器、结算器或伤害规则。

| 字段 / 接口 | 输入与输出契约 |
| --- | --- |
| `Verb` | 消息通道；HealthSet 使用 `Message.Damage`、`Message.PoiseBreak`。 |
| `Instigator` | GE 上下文的 EffectCauser；缺失时为空，不用目标或当前 Avatar 补造来源。 |
| `Target` | HealthSet 的 OwningActor，即 ASC 宿主，不保证是 Pawn。 |
| `InstigatorTags / TargetTags` | 对应 Modifier 的已捕获来源/目标 Tag 快照；不通过消息反向维护 ASC Tag。 |
| `ContextTags` | 通用扩展字段；当前 HealthSet 不额外填入命中部位或暴击语义。 |
| `Magnitude` | 按下表解释，不统一视为实际扣血量。 |
| `RegisterListener / FGameplayMessageListenerHandle::Unregister` | 消费者持有并在结束使用时注销订阅；长期缓存须复制需要的数据并处理参与者失效，不保存载荷栈地址。 |

能力失败的文本/Montage 专用消息仍归 AbilitySystem。驱动指定 Actor 的能力逻辑使用 `GameplayEvent`，见 [[AbilitySystem/结构]]。死亡/破韧逻辑委托与只读观察消息各有消费者，消息本身不请求 GA、不修改 ASC。

## 第 13 批已实现主路径

| 事件 | 发送条件 | Magnitude |
| --- | --- | --- |
| Damage | 正伤害 Modifier 通过现有免疫校验并结算 | 原始 Modifier 幅度，未 Clamp；残血时可大于实际生命损失。 |
| PoiseBreak：削韧 meta | 本次真实 Poise 正值到零 | 原始削韧 Modifier 幅度，未 Clamp。 |
| PoiseBreak：直接 Poise GE | 本次真实 Poise 正值到零 | 该次可确认的 `OldValue - NewValue`，正的实际损失，不把 Override 目标值当伤害。 |

普通削韧、治疗和保持为零不发上述破韧消息；韧性恢复为正后可再次触发。破韧的主语义是边沿，不能把其数值累计当完整削韧统计。

GAS 对每个输出 Modifier 单独调用 `PreGameplayEffectExecute / PostGameplayEffectExecute`。同一 GE 中 Damage 与 PoiseDamage 分开执行；不承诺一次消息已经包含整次命中的两项最终结果。

瞬时 GE 的原生属性委托可在 Pre/Post 之间和 setter 内重入。HealthSet 保存各 Modifier 的同步上下文，分别消费 meta，在实际属性变化处捕获数值和提交边沿；项目通知使用固定来源/数值快照。存在祖先未消费输入时，结果仅暂存于当前同步调用作用域，退出该作用域后发布，不跨帧保存。项目消息回调引起新 GAS 调用时，旧结果不能覆盖新状态。

消费 meta 的 setter 本身也能触发原生委托。因此先扣除本 Modifier 的输入，setter 返回后再读取最新 Health/Poise 结算；直接 Health/Poise GE 已经完成实际写入，Post 阶段不重复赋值。结算 setter 配对原 Modifier，确保死亡逻辑委托仍取得真实 EffectSpec，破韧消息仍取得原始削韧幅度。

开发期 `Cheat_GodMode` 拒绝普通正伤害；`Cheat_UnlimitedHealth` 保留伤害、来源和消息结算，只将生命下限限制为 1。自毁伤害保留现有绕过规则。同一次属性变化的 Changed 通知先于死亡/破韧委托；边沿锁存在任何项目通知前提交。

事件快照描述其所属修改。发布时 ASC 可能已经经历后续嵌套修改；读取实时属性得到的是当前状态，不能把它当该事件的历史新值。消息观察者仍应只读，重入防护不改变状态写入权限。

## 复制、消费者与验证边界

`OnRep_Health / OnRep_Poise` 只处理 GAS 复制及属性委托。复制快照可能合并多次修改，没有逐次 GE 上下文，不能据此重建 Damage/PoiseBreak GameplayMessage。客户端逐次消息传递属于后续设计与联机验收范围。

### HealthSet 的复制调用作用域

聚合器及属性集注册归 GAS；属性数值、死亡/破韧锁存和项目通知归 `UGGYGOHealthSet`。`FRepNotifyFrame` 只保存本次同步宏的阶段、弱 Outer Actor / 弱 Owning ASC 身份、显式 Base 写入标记和一次性有效复制快照，不持有聚合器或跨帧执行状态，不构成第二套 GAS 状态。

以下辅助机制为 HealthSet 私有实现；创建钩子和属性回调继承 GAS 接口，不向消息消费者开放写入入口。

| 接口 | 输入、作用与输出 / 清理 |
| --- | --- |
| `BeginRepNotifyFrame(Attribute)` | 复核所有活动旧帧，建立当前属性帧；安全 Cast 并确认 Outer Actor 有效后才查询 Owning ASC，保存弱身份并检验实际注册实例。 |
| `CanClassifyRepNotifyFrame(Frame)` | 比较当前 Outer / ASC 与弱快照，通过公开 `ASC->GetAttributeSet(Attribute.GetAttributeSetClass()) == this` 确认注册；一旦观察到失配，本帧直到宏退出都停用分类，切回也不复活。 |
| `OnAttributeAggregatorCreated(Attribute, NewAggregator)` | 原参数转发 Super；只向同属性、来源/注册匹配且仍未判定的全部活动帧记录迟到创建，包含嵌套 OnRep 的外层帧；不保存或解引用聚合器指针，不重置有效快照。 |
| `PostAttributeChange(Attribute, OldValue, NewValue)` | 先配对 GE Modifier / Expected write / Explicit Base；真实写入不消耗复制阶段。其余写入按下面阶段识别，最终复制值与边沿锁存在原生属性委托之前提交。 |
| `EndRepNotifyFrame(Frame)` | 宏局部 `ON_SCOPE_EXIT` 按准确帧身份移除；四个 OnRep 的 GAS 宏结束后先出栈，再发布项目复制历史。 |

| 调用局部阶段 | 当前含义与转移 |
| --- | --- |
| `Undetermined`（未判定） | 无迟到创建信号时，首个未归属 Post 是已有聚合器的临时回退：不生成项目事实，不改变上限联动或锁存，转入等待最终写入。迟到创建则直接转入真实变化。 |
| `AwaitingFinalWrite`（等待最终引擎写入） | 下一未归属 Post 捕获一次有效复制值，提交锁存后转入真实变化；创建钩子不能重置此阶段或已捕获快照。 |
| `RealChanges`（后续真实变化） | 写入继续走原有 Changed / 边沿 / 消息链，不覆盖复制快照；迟到 GE 恢复为正值会重新打开归零锁存。 |

无初始聚合器且没有属性 Post 时，历史使用入宏前的 incoming 值。复制有效值捕获不注册临时原生委托，也不依赖多播顺序；普通 setter 与瞬时 GE 的既有配对优先。来源/注册失配只停用分类资格，不取消已发生的复制历史、不回滚锁存、不清理 GAS；ActorInfo 的 Owner / Avatar 刷新本身不是属性来源换代。

四个 OnRep 在没有合法存活 Actor / ASC 时避免 GAS 宏的 checked 查询，但仍保留 incoming 历史。宏 Scope 清理后，Health / MaxHealth / Poise 历史使用 incoming 或已捕获有效快照，不取迟到恢复后的实时值替换历史，也不以旧快照覆盖内层更新后的锁存。详细发布链见 [[GGYGO_流程_Messages.canvas|发布流程]]。

### 已验证范围与剩余边界

- **既有回归**：12 组 `GGYGO.AbilitySystem.HealthMessage.*` 在第 21 次新 DLL 门禁均 Success，包括瞬时 GE / setter 重入、meta 清零、来源/Tag/幅度、Changed 与边沿顺序、复制历史及已有聚合器 Infinite +0 回退用例。它们不覆盖已有聚合器下的新持续 GE 矩阵。
- **LateCreate 两例**：无初始聚合器，Health / Poise 分别复制 `10→0`，在原生委托内施加无周期 Infinite `+5`，OnRep 返回后公开移除。严格断言证明 `10→0`、`0→5`、`5→0` 各有一次 Changed、两次归零边沿、真实 native / 创建 / Post 顺序及活动 GE `0/1/0`；Poise 移除恰好一条幅度 5 的 Break，复制不伪造 GameplayMessage。
- **真实历史**：P1 前按 Post 次数分类误吞迟到恢复，第 19 次该诊断为 2 Fail / 13 errors。P1 后第 21 次完整构建 Succeeded，常规 52/52，独立 LateCreate 2/2 Success，0 errors / warnings，严格夹具未改；上述迟到创建场景已修复。复制回归是实际 ASC / GE 加 OnRep 契约模拟，不能代替网络验收。
- **未验 / 不保证**：已有聚合器的新持续 GE / 同栈移除、嵌套 OnRep、重登记 / 来源迁移和 Scope 中止没有新增动态证明。引擎回退与最终写入之间迁移来源、同 Set 被多 ASC 注册并交错写入、Dirty 广播栈任意聚合器移除 / 销毁不由 P1 保证；当前实现没有扩大到这些生命周期规则。
- **其余缺口**：非零持续 Health / Poise Modifier 与 meta 的 Current→Base 混合语义沿用旧规则，尚待业务决定与验证；真实网络 / 聚合批处理 / 预测、PIE、蓝图资产及消费者接线仍待验收。E8 保持开放。

UI、音频、统计的订阅为目标接入方向。当前源码检索未发现项目 C++ 消费者；这不证明蓝图没有消费者，资产查询和动态接线仍待验收。
