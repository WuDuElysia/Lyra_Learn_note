## 工具安全契约（A8–A9）

以下为脚本当前实现；23 项 Fake Unreal 离线回归通过，修订后的脚本尚未在 UE 执行。本次没有修改地图资产、运行时 CMC 或上述场景参数。

### 创建与只读复核

`AAADocs/Scripts/create_movement_test_level.py` 导入时不建图；调用 `run()` 才执行。以 `__main__` 执行文件仍会调用 `run()`。

```text
run()
  preflight：无 PIE / 无脏地图
    → GameMode → Experience → 全部 Roster 项的 PawnData/PawnClass
    → 可选 MovementSet/InputConfig 的类型与路径
    → Cube、已有网格材质、引用包的未保存修改
  已有地图 → 要求已主动打开且干净 → inspect_current() → 只写检查报告
  不存在地图 → 创建并保存缺失材质 → new_level()
    → 原有五个 Actor → inspect_current() → save_current_level() → 报告
  任一步失败 → 记录阶段与真实产物，保留现场
```

为什么这样写：配置的缺失或空引用应在资产修改前发现；创建、保存和报告落盘是不同结果。把保存返回成功与包文件存在性分别核对，避免把已保存的空地图或仅存在于内存中的材质当成完整成果。若把预检移回保存之后，缺失 Experience/PawnData 会重新产生无法直接重跑的半成品。

- 遍历默认编队的每一项；不只检查首个角色。`MovementSet` 和 `InputConfig` 按 PawnData 契约允许为空，报告写 `null`；这不等于已验证该角色能通过当前输入进行曲线移动。
- 预检不替代项目完整资产验证器；报告的 Roster 是 Experience 默认配置快照，实际 PIE 编队仍可能被存档覆盖。
- 已有地图不会被脚本自动打开、重建、保存或删除；必须由调用者先打开。预检遇到脏地图或所引用内容包的未保存修改会停止。
- `inspect_current()` 只核对 GameMode、默认配置引用、五个预期 Actor 的存在/类型、地面位置/缩放/旋转/网格/材质引用/碰撞，以及 PlayerStart 位置和朝向。地面必须未旋转，才报告顶面 Z=0；不会修正发现的差异。
- `configuration_verified` 仅对应报告中的 `configuration_verification_scope`，不是场景全量验收。照明、材质着色、额外 Actor、实际编队生成与 PIE 仍需另外检查。
- 输出为 `Saved/LevelDesign/map_configuration_<run-id>.json`，不覆盖之前的报告。`material_created`/`map_created` 在调用发生但分配结果不明时为 `null`，成功获得创建结果后才为 `true`。`*_package_present` 只表示磁盘文件存在，不代表最终构建已保存。
- 状态区分 `created`、`existing_inspected`、`preflight_failed`、`partial_failure`、`existing_requires_review` 和 `report_failed`。报告落盘失败时，函数返回值及日志仍保留资产结果。

**恢复边界：**完整地图已保存、仅报告失败时，在干净且已打开的地图上重跑，可只读复核并生成新报告。地图保存失败后，先人工检查并显式保存，再走同一路径；脚本不会自动补存可能包含人工修改的脏地图。不完整地图或未保存材质必须先人工检查处理，再决定保留还是重新创建；没有自动删除、回滚或覆盖恢复。

### 移动探针

`AAADocs/Scripts/verify_movement_test_level.py` 导入时不启动；PIE 中调用 `start()`，提前停止调用 `stop()`。以 `__main__` 执行文件仍调用 `start()`。升级脚本前应结束旧版已启动的探针；新版不能接管旧版没有登记的回调。

```text
start()
  已有活动探针 → 返回同一实例
  上次仍有资源待清理 → 拒绝新启动，先 stop() 重试
  验证 PIE / Pawn / 动画观察接口 / 输入
    → 保存节流原值 → 关闭后台节流 → 注册一个 ticker
tick()
  World/Pawn 更换、采样失败或达到 38 秒 → stop(reason)
stop()
  标记停止 → 尝试注销回调 → 尝试输入归零
  finally：恢复原节流设置 → 释放 PIE 引用 → 输出报告
  无待清理资源 → 释放单实例槽
```

为什么这样写：回调、注入输入和临时编辑器设置由同一个探针管理；输入子系统失效不能阻断设置还原。单实例槽保存在独立的 Python 会话模块中，重复执行/重新加载脚本不会产生第二个活动探针。若改回文件末尾无条件构造实例，会重新出现输入竞争和原节流值被覆盖。

- `stop()` 可重复调用；已成功释放的回调/设置不会重复处理。注销或设置还原失败会记录错误并保留清理所有权，阻止新探针覆盖原值；再次 `stop()` 可重试。注销失败但回调仍触发时，停止状态仅返回 `False` 让 ticker 退出，不再采样或注入。
- 保留原 38 秒与 1/31/3/3 秒时序、原输入轴值。时间字段明确为 **编辑器 ticker 秒数**，不是 World 模拟时间；暂停、时间膨胀等情况下不能据此推导游戏计时。
- 输出为 `Saved/LevelDesign/movement_runtime_<run-id>.json`，顶层包含状态、原因、错误、`cleanup_pending` 与 `samples` 数组。它与旧版直接输出数组的固定文件格式不同。
- `completed` 仅表示采样过程正常结束；`runtime_acceptance_verified=false`。输入释放、还原设置或采样异常均保留错误，不宣称完成验收。报告写入失败仍会先完成资源清理，可对返回的探针再次 `stop()` 重试报告。

### 离线门禁与待验收

`AAADocs/Scripts/tests/test_movement_level_tools.py` 共 23 项回归，覆盖重复启动/重载、正常时序、PIE 结束、输入失效、注册/注销/设置还原/报告失败，以及全编队预检、合法空配置、脏包、资产类型、材质/地图保存失败、部分产物、报告恢复和旋转冲突。Mock 文件仅写入临时目录；这不证明 UE 中反射 API、对象销毁、实际包保存及渲染行为已经通过。

后续由统筹执行编辑器动态门禁：同一 PIE 重复启动、提前退出 PIE、正常完成与设置还原；建图工具在隔离环境核对前置失败无资产变化、部分失败报告与已有地图只读复核。本说明保留的历史 PIE 证据不能代替这轮验收。

## 2026-09-29 原版脚本 PIE 证据（历史）

UE 5.8.1 的真实 InViewPort PIE 正常生成并附身 `BP_PC_Pyrios_C_0`。通过 `EnhancedInputLocalPlayerSubsystem.inject_input_vector_for_action(IA_Move)` 注入轴值，经过原输入回调和 CMC；没有传送角色或写入速度/步态来伪造移动。

- 总采样 38.0018 秒、4513 帧：1 秒静置、31 秒向前、3 秒反向、3 秒松开。
- 全部采样 `grounded=true`、`MOVE_WALKING`；胶囊中心 Z 始终约 90.15 cm，没有持续下坠。
- Walk 首次出现于 1.0123 秒，Run 于 2.5183 秒，两者相差 1.506 秒。
- 32 秒反向输入后依次记录 Turning（32.0113）、Braking（32.3363）、RunOut（33.053）；最终 Yaw=180°。
- 最远 X=325.96 米；稳定曲线跑速约 10.50 米/秒，峰值 15.43 米/秒。从中心到边缘按稳定速度估算约 47.6 秒。
- 最终网格材质和灯光修正后重新启动 PIE，确认地面、角色与天空可见且玩家正常落地；材质 D3D_SM6 编译成功，不再使用失败后的默认材质。

历史证据：工程 `AAADocs/Movement_Test_Verification.json`、`AAADocs/References/Movement_Test_PIE.png`；当时的完整采样在本机 `Saved/LevelDesign/movement_runtime.json`（忽略的运行产物）。新版脚本改用独立 run-id 报告，入口、清理和验证边界见上文。

当前结论限于本机单人 PIE 和 InputAction 注入。物理键盘操作、联机预测、边缘跌落、导航和流送未在本轮验收；TurnBack 的动作美术质量由 Movement/Animation 后续专项评估。
