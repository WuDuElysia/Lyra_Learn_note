# Teams：结构与接口

> 结构图：[[GGYGO_结构_队伍与装配.canvas]] · 装配/切换流程：[[GGYGO_流程_队伍与装配.canvas]] · 文字计划：[[计划_队伍与装配]]

| 类 / 数据 | 关键接口 | 责任 |
| --- | --- | --- |
| `AGGYGOCombatantState` | `AttachAvatar`、`DetachAvatar`、`GetAvatarPawn`、`GetGGYGOAbilitySystemComponent` | 可跨 Pawn 生命周期的最小战斗状态宿主；统一更新复制 Avatar、PawnExtension 与 AbilityActorInfo。 |
| `AGGYGOCharacterSlot` | `InitializeForPawnData`；继承 `AttachAvatar` | 玩家编队中一个位置，持有独立 ASC、基础属性与授予的能力。 |
| `UGGYGOSquadComponent` | `SetRoster`、`RegisterSlot`、`GetActiveSlot`、`SwitchToSlot` | 挂 PlayerState，保存局内编队名单、实际 Slot 与出战索引。 |
| `UGGYGOSquadPresets` | `SetPresetMembers`、`SetActivePresetIndex`、`ResolveActivePresetRoster` | LocalPlayer SaveGame 中的跨局编队预设。 |
| `AGGYGOPlayerState` / `AGGYGOPlayerController` | 队伍宿主 / Possess 与输入后处理 | 玩家生命周期与附身入口。 |

`Presets → Roster → Slots → Pawn Avatar` 是四种不同生命周期的数据。[[GameFeature/结构|GameMode]] 先生成 Slot 并授予 [[AbilitySystem/结构|AbilitySet]]，再生成 Pawn、注入 ASC，最后 Possess 出战角色；换人仅切换当前 Pawn 的附身关系，待命 Slot 的 GAS 状态仍存在。Boss 只共用 `CombatantState`，不进入玩家编队链，见 [[BossAI/结构|BossAI]]。

## 装配接口契约

| 调用方 → 接口 | 输入 / 前提 | 作用与输出 / 副作用 |
| --- | --- | --- |
| LocalPlayer 预设 → `ResolveActivePresetRoster(OutRoster)` | 出战预设中的 PrimaryAssetId | 解析 PawnData 列表；GameMode 再调 `SquadComponent::SetRoster`，无结果才用 Experience 默认。 |
| GameMode → `SpawnSquadSlot(PlayerController, PawnData)` | Owner 必须是该 PlayerController | 创建持久 Slot 并 `InitializeForPawnData`，先授予 ASC/属性/能力。 |
| GameMode → `SpawnSquadMember(PlayerController, PawnData, Transform)` | 对应 Slot 已生成 | 创建 Pawn 并 `PawnExtension::SetPawnData`；调用方随后 `Slot::AttachAvatar(Pawn)`。 |
| GameMode → `SquadComponent::RegisterSlot(Slot)` | Slot 与 Pawn 已绑定 | 登记装配结果；首个位置通过 `SwitchToSlot(0)` 出战并由 Controller Possess。 |
| 玩家 → `SquadComponent::SwitchToSlot(Index)` | 目标 Slot/Avatar 可用 | 转移 Controller 附身并更改 ActiveSlotIndex；不重建待命 Slot/ASC，Buff/冷却持续。 |

`CombatantState::AttachAvatar` 是玩家 Slot 与 BossState 的共同底层契约；预设、换人和 Mixed 复制只属于玩家编队。
