## 状态所有权与类关系

| 类 / 数据 | 关键接口 | 责任 |
| --- | --- | --- |
| `GGYGOSquad` / `GGYGOSquadTypes.h` | `IsMemberCountWithinCapacity(int32)` | 共享无状态容量规则；唯一上限 `GGYGO_MAX_SQUAD_SIZE=4`。 |
| `AGGYGOCombatantState` | `AttachAvatar`、`DetachAvatar(ExpectedPawn)`、`GetAvatarPawn`、`GetGGYGOAbilitySystemComponent`；`Destroyed / EndPlay` → private `CloseAvatarBindingLifecycle` | 最小持久战斗宿主；拥有 ASC/基础属性/复制 Avatar，唯一协调绑定生命周期关闭，ASC 唯一执行 ActorInfo/能力清理事务。H3 两原生入口在 Super 前消费原绑定，不重捕后继。 |
| `AGGYGOCharacterSlot` | `InitializeForPawnData`、`GetPawnData`、`IsPawnDataInitializationComplete`；继承 `AttachAvatar` | 玩家编队中一个位置；配置并授予独立 ASC 的角色能力，不拥有编队名单或控制权。 |
| `UGGYGOSquadComponent` | `SetRoster`、借用 `RegisterSlot`、private `RegisterCreatedSlot`、`GetActiveSlot`、`SwitchToSlot`；native `DestroySquad`、`EndPlay`、`OnComponentDestroyed` | PlayerState 唯一队伍组件；持有 Roster、Slots、ActiveSlotIndex 和唯一原始创建弱责任台账。三终止入口共用 private `ConsumeCreatedSlotResources`，只请求原创建 Actor 销毁，不执行 Host 绑定清理。 |
| `UGGYGOSquadPresets` | `TryLoadForLocalPlayer`、`ResolveActivePresetRoster`、`Serialize / HandlePostLoad`、同步/异步原生保存 overrides；编辑接口保持 | 保存跨局 ID 数据，返回显式加载/解析结果；检查原始非法保存及原主 LP 保存来源。无具体 GGYGOLocalPlayer 反向 accessor，不拥有缓存、Roster 或第二保存执行器。 |
| `UGGYGOLocalPlayer` | `TryGetSquadPresets(OutPresets, OutError)`；兼容 `GetSquadPresets()` | 唯一预设缓存宿主；只有合法原主 LP 来源可发布。原模型/LP/GI/platform user/槽元数据是派生来源记录，失效明确失败，不清空后另读或重建替代。 |
| `AGGYGOPlayerState` / `AGGYGOPlayerController` | `GetSquadComponent()` / `UnPossess`、`Possess`、`PostProcessInput` | PlayerState 构造唯一 Squad 默认子对象；Controller 持有玩家连接并执行附身/输入后处理。 |
| `UGGYGOExperienceDefinition` / `AGGYGOGameMode` | `IsDataValid(Context)`、`SpawnSquadForPlayer`、native bool `SpawnSquadSlot / SpawnSquadMember`、`Logout(Exiting)`；private `ConsumeUntransferredSquadActors` | 默认配置与服务器创建/退出编排；只持原 Context/输入快照及自己未交付的原资源。创建交付 true 后只归 Squad。Logout 先抽原 PC 留存批次、关闭原 Squad，再消费 Creator 原批次；完整契约见下节。插件资源仍归 [[GameFeature/结构|GameFeature / GameMode]]。 |

`Presets → Roster → Slots → Pawn Avatar` 是四种不同生命周期的数据：跨局意图、本局名单、实际成员、可替换实体。`Slots` 是唯一成员名单，`ActiveSlotIndex` 是唯一出战索引；`IsSquadAssembled()` 仅读取 `Slots.Num()>0`，不证明整份名单成功装配。`CreatedSlotResources` 只保存显式交付的原始 Slot/Pawn 弱身份对，不复制，不保存当前 Avatar 或活动状态，也不构成第二份名单；终止消费与未退休字段仍归这一台账。组件关闭/消费/最终销毁标志只限制自身生命周期与重入，不形成第二套装配或绑定权威。

依赖按职责为：装配请求者 GameMode → Squad / Slot；Slot → [[Combatants/结构|CombatantState]]；宿主 → [[Character/结构|PawnExtension]] / [[AbilitySystem/结构|ASC]]。Squad 通过公开 getter 读回宿主和绑定，不直接写 ActorInfo；private friend GameMode 只开放创建交付权限，不使 Squad 反向调用 GameMode。终止时 Squad 请求原创建 Actor 的 `Destroy()`，原 Slot 实际发生的 `Destroyed / EndPlay` 再由 Host H3 唯一协调原绑定关闭；Squad 不持 H/Context，也不调用 Host/Extension/ASC 的解绑或 GA 清理。Boss 只共用 CombatantState，不进入玩家编队链，见 [[BossAI/结构|BossAI]]。

## 容量、保存与本局名单接口

| 调用方 → 接口 | 输入 / 权限 | 作用与输出 / 失败边界 |
| --- | --- | --- |
| Presets / Squad / Experience → `GGYGOSquad::IsMemberCountWithinCapacity(Count)` | int32 原始数量 | 0～4 为 true，负数或超限为 false；不读名单、不截断、不加载。0 是否业务可用归调用方。 |
| 编成调用方 → `SetPresetMembers(Index, IDs)` | 有效预设序号、原始 ID 数组；本地存档对象 | 超限整体 false，原名单不变；合法时一次替换。空 ID 可作空位，但仍计入原始容量。编辑不自动落盘，调用方显式保存。 |
| 读档 → `Serialize(Ar)` / `HandlePostLoad()` | 原始已保存数据 | loading Archive 错误事实累计保留；非法原始出战索引/超限只诊断，不修正、截断或删除。显式取得入口据这些事实拒绝非法来源，原文件与字段保留。 |
| 装配 / 预览 → `ResolveActivePresetRoster(Out)` / `ResolvePresetRoster(Index, Out)` | 当前/指定预设、原始 ID 数量、真实 AssetManager | 返回 `FGGYGOSquadPresetRosterResolveResult`：`Resolved / Unconfigured / Invalid`，先清输出。原始超限在加载前拒绝；仅显式空 ID 跳过，非法 ID/路径/类型/加载失败整体 Invalid，不发布部分名单。仅完整 Resolved 一次发布 PawnData[]；正常无配置与错误分开。 |
| 名单提供者 → `Squad::SetRoster(PawnData[])` | Owner 为 Authority，Slots 尚为空，组件未终止且有效 | 先校验原始数量，再在临时 Candidate 中跳过 null；至少一名有效成员才一次替换 Roster。终止后、非权威、已装配、空/全空或超限 false，原 Roster 不变。 |
| 编辑器 / 生成前 → 容量规则 | 编辑期默认 `SquadMembers`；运行时实际选定 Roster 或 Experience 原数组 | 编辑期错误成员报 Invalid；运行时 GameMode 在 PawnData 弱复制、ChoosePlayerStart 和 Actor 生成前检查原始 Num，空项也计数。超限整体停止，不过滤后缩到上限、不截断/补员；空数组容量合法但本次生成要求非空。 |

实际来源先用非空已有 Roster；为空时调用 `TryApplySavedRoster`，通过原 `UGGYGOLocalPlayer::TryGetSquadPresets` 与模型解析消费来源：`Applied` 使用完整已设置名单；只有正常 `Unconfigured` 才选择 Experience 默认；`Invalid` 明确诊断并在 Actor 生成前停止。服务器远程 PC 明确没有 LP 是既有正常 Unconfigured 模式，次级本地 LP 的保存拒绝不能伪装成此模式。原始容量及后续真实出生点准入适用于实际选定来源；空/非法依赖不替换为另一编队。已交付成员不回滚，整队成功政策仍未闭合。

## 主玩家保存与唯一缓存

用户已选择保留既有 `GGYGOSquadPresets` 原槽，只允许原 GameInstance 的主 LocalPlayer 持久化；次级本地玩家明确拒绝，不访问主玩家文件。非法旧文件/字段保留，未授权迁移、修复、重置或覆盖。该政策限制保存来源，不把每名玩家的本局队伍改为主玩家独占；远程上报及次级玩家的显式本局名单接线仍按现有边界处理。

| 调用方 → 真实接口 | 输入 / 输出 | 来源、生命周期与失败 |
| --- | --- | --- |
| LP 宿主 → `TryLoadForLocalPlayer(const ULocalPlayer*)` | `FGGYGOSquadPresetLoadResult`；`Loaded / CreatedForMissingSlot / Invalid`，Error、原 LP/GI/user/index/槽及 scoped strong Candidate | 原主 LP、原 GI/platform user 与固定原槽均须合法并重检。既有文件读取/类型/已观察 Archive/原始索引错误明确 Invalid。明确缺槽才创建内存候选，工厂自身不保存；Invalid 不创建替代对象。 |
| 兼容 → `LoadOrCreateForLocalPlayer(LP)` | 委托上述入口；Invalid 返回 nullptr | 不再通过引擎 LoadOrCreate 掩盖错误或创建另一对象来源。 |
| GameMode / PC → `TryGetSquadPresets(UGGYGOSquadPresets*& OutPresets, FString& OutError) const` | bool，失败清 Out 并给 Error | `UGGYGOLocalPlayer` 的原一份 UPROPERTY 缓存是唯一宿主；原 cache/LP/GI/user/index/槽及模型原生 association 均须一致。来源失效、重入或取得失败不发布，不 Reset 后另读/重建。临时强引用只保本次回调生命周期，派生元数据不形成第二缓存。 |
| 蓝图兼容 → `GetSquadPresets()` | 委托 TryGet；失败日志/空值 | 取得失败是显式失败结果，不能当成正常未配置。 |
| 保存 → `SaveGameToSlotForLocalPlayer()` / `AsyncSaveGameToSlotForLocalPlayer()` | 原 native bool；private `RequestSaveForOriginalSource(bool bAsync)` | 请求前检查原模型、原主 LP/GI、platform user/index、原 native/实际 virtual 槽路由、已知 Archive 错误和原始索引；拒绝不改文件或重置内存。通过才委托 Super，计数、执行与完成仍归引擎。 |
| 三个 PC 编辑 Exec → 原生同步保存 | 取得前后核对原 PC/LP；复制诊断后消费 native bool | false 记录拒绝/失败，当前内存编辑保留；true 只报告请求结果，不证明持久化。没有额外监听器、计数器或执行器。 |

`GetForPlayerController` 已从保存模型移除，实际 GameMode/PC 取得端均经 LP facade；模型只依赖引擎 `ULocalPlayer` 参数，不依赖具体项目 LP 缓存实现。编辑 setter 的正常规则与不可信读档校验分开，`HandlePostLoad` 不自行修复非法旧值。

本合同是已检测来源/数据错误的拒绝与请求准入；不声明原生文件头解析的全覆盖，不撤销已经接受的异步请求，也不拦截任意 `GameplayStatics` 绕过保存入口。落盘、旧文件异常及真实主/次玩家动态验收未由编译证明。政策证据见[原主玩家保存决定](F:/ue_project/GGYGO/Saved/ValidationRecords/TeamsSaveSlotPolicy_20261004_UserDecision.json)。

| --- | --- | --- |

| GameMode → `PawnExtension::SetPawnData(Data)` | Authority、原 Pawn 的有效原 Extension、非空原角色配置 | 准备 helper 外调后重取原 Pawn/Extension，验证同一 Extension、Owner 与原 PawnData；缺组件或读回失配返回 false 并保留原产物。供 Pawn InitState 使用，不再次授予 Slot 的能力。 |
| GameMode → `Slot::AttachAvatar(Pawn)` | 原 Context/Slot/Pawn 准备资格仍匹配 | 继承 CombatantState 唯一绑定入口，协调复制 Avatar、PawnExtension 缓存和 ActorInfo；void，不证明绑定成功。外调后 Creator 重检原资格，再由 `RegisterCreatedSlot` 执行唯一接收/绑定验证；不在 Creator 复制绑定规则或清理。 |
| Squad → `Slot::GetGGYGOAbilitySystemComponent()` / `GetAvatarPawn()` / `GetPawnData()` | 只读 | 获取持久 ASC、当前 Avatar 和配置；再对照 ASC Owner/Avatar 与 PawnExtension 的 ASC/PawnData，避免重复写绑定。 |
| 原 Slot 的原生 `Destroyed / EndPlay` → Host `CloseAvatarBindingLifecycle` | Host 自己的原 H/已提交 Context；两入口均在 Super 前关闭 | H3 覆盖 BeginPlay 前销毁与 owner-only；有 H 复用原 Release，无 H 由 ASC 认证原 Context 后真实 Clear/Publish。Teams 只请求原创建 Actor 销毁，不调用 `DetachAvatar`、`UninitializeAbilitySystem` 或 `ClearActorInfo`。Destroy 接受不证明绑定物理清理成功；Busy/失败仍须保留。 |

### 登记上下文与新成员准入

两个接收入口先拒绝已终止、无效或正在销毁的组件，再读回实际 `AGGYGOPlayerState::GetSquadComponent()==this`，要求 PlayerState/Controller 有效且不在销毁、Authority、同 World，并要求 `PlayerState.GetOwner()` 为该 Controller、`Controller.GetPlayerState<AGGYGOPlayerState>()` 指回同一宿主。动态添加的第二 Squad 即便挂在 PlayerState 上也不能替代唯一队伍。

合法重复在上述权限/唯一宿主检查之后、容量与新成员绑定检查之前处理。新成员才需要 Slot 有效且不在销毁、Authority/同 World/Owner 为该 Controller，05a1 查询完成；ASC 有效且不在销毁，OwnerActor 为 Slot；Avatar 是有效且不在销毁的 `AGGYGOCharacterBase`、Authority/同 World/Owner 同 Controller，Controller 为空或同 Controller；ASC AvatarActor 等于 Slot Avatar；PawnExtension 有效且不在销毁，其 ASC 与 Slot ASC 相同，PawnData 与 Slot PawnData 相同。不要求尚未 Possess 的 Pawn 已 GameplayReady；死亡是否可出战由现有切人准入另行决定。

## 两个接收入口与原始创建责任

| 接口 | 输入 / 权限 | 输出与责任 |
| --- | --- | --- |
| `bool RegisterSlot(Slot)` | public BlueprintCallable；上述权威上下文，新成员通过绑定与容量验证 | 只接收借用成员关系。新增成员进入 Slots，默认待命；尚无出战位时尝试原 `SwitchToSlot(0)`。true 表示关系已接收，不保证自动激活/Possess。 |
| `bool RegisterCreatedSlot(Slot, OriginalCreatedPawn)` | private、非 UFUNCTION，仅 friend `AGGYGOGameMode` 的 C++ 创建交付；新请求显式原 Pawn 必须是当前已验证 Avatar | 同时提交 Slots 与原始创建责任，早于表现/自动激活回调。真实 GameMode 已调用并先消费 bool：true 退休 Creator 责任，即使回调已终止；false 不接收，Creator 请求销毁未交付原对。Squad 三终止入口唯一消费已交付原 Actor；不以自动激活/Possess 成功决定归属。 |

| 重复 / 失败路径 | 当前契约 |
| --- | --- |
| 普通重复（含已创建登记的成员） | 权限有效时 true，不重放待命/激活，不新增、升级或降级创建责任；已满也不误拒绝。 |
| 已借用成员再走创建入口 | false，不能通过一次补调用接管其 Slot/Pawn 的清理。 |
| 同 Slot、同原始 Pawn 创建重复 | 按原始弱对象 index+serial 身份 true，即使当前 Avatar 已替换；不要求当前绑定仍是原 Pawn。 |
| 同 Slot、不同原始 Pawn，或原 Pawn 已在另一创建记录 | false，旧责任不变；不让两个记录共同接收同一原 Pawn。 |
| 创建记录存在但 Slots 缺失 | false，不覆盖原记录或降级成借用。 |
| 新请求权限/初始化/容量/绑定失败 | false，提交前无名单、创建记录、待命或附身副作用。 |
| 提交后表现、自动 Switch 或 Possess 失败/重入 | 仍 true；名单与责任先于外部回调一起提交，重复不重放。待命外调后组件已终止/销毁时停止旧栈并保持已接收事实；自动激活前再读当前上下文和首位绑定，失配则跳过尝试，不交回责任。 |

弱身份使用 `HasSameIndexAndSerialNumber`，不通过两个失效 `Get()==nullptr` 推断同对象；原始记录不随 `GetAvatarPawn()` 替换而迁移。重复 true 只确认已接收身份，不证明当前可出战；后续上下文失效返回 false 也不会撤销先前责任。创建者须保留已成功交付事实，不能按一次重试结果或当前 Avatar 推断是否可回滚。

## GameMode 创建准备、交付与未交付责任（创建者 A）

| 接口 / 数据 | 输入与输出 | 责任与清理 |

1. 全部 Slot 准备在 Pawn 阶段之前完成；每次外调后只重取原弱身份并重检资格。选定名单先检查原始容量，再复制为本次 PawnData 弱快照。ChoosePlayerStart 后保存原 Actor/Root 弱身份，拒绝 null、失效、销毁中、错 World、缺 Root 或 Root 替换；真实 Root 世界 Transform 在快照前后复核原 Context/身份，并用 `IsValid()` 拒绝非法值。真实有效世界原点 Identity 合法，不能以缺依赖代入 Identity。

## 原 Controller Logout 与 Creator 留存收尾

1. 原 PC 筛选用 `HasSameIndexAndSerialNumber`，即使弱对象后来失效仍区分原身份；不能用两个 `Get()==nullptr` 把不同失效 Controller 混为同一来源。只把匹配的**既有留存条目**移入本次局部批次并从主账本移除，其他 Controller 条目保留，早于任何 Squad/Actor 清理外调。
2. `BeforeActorDestroy` 调用现有 `CloseOriginalSquad`：捕获原 PS/World/Squad、验证权威与原归属，再调用 `Squad::DestroySquad()`。Squad 先关闭登记、移出自己的已交付台账，再控制/广播/Destroy；原创建 Context 随之拒绝继续移交。已提交的 Created true 仍是历史接收，责任不反交。
3. 钩子之后 Creator 仅将自己的已抽出批次交给原 Finish/Request。创建中的原产物仍归原同步栈；已交付原物仍归 Squad。回调新留存条目不被旧清理 Reset，也不自动扫描重试。
4. 嵌套 Controller 退出只能取得主账本中尚未移出的匹配条目。首次整体关闭可在消费护栏中接管主账本剩余条目，不能取得外层已移出的批次；后继整体关闭即使护栏已释放也不重扫。只有取得护栏的原外层在原 Creator 可用时释放该护栏；没有新计时器、队列、账本或 Destroy 执行器。
5. 单次整体关闭是 **GameMode Creator** 的合同；Squad 后续显式/真实终止入口仍沿其既有消费协议。原生接受 Destroy 不是物理清理、Host Clear 或能力退出完成。原生拒绝且 Creator 尚可用时保留原字段并诊断；最终来源已不可用时明确无法留存，不制造成功。

原生断线顺序为 PC 的 PawnLeavingGame/UnPossess → Controller 调用 GameMode Logout → CleanupPlayerState/OnDeactivated → Squad 组件生命周期；普通断线本已有后续 Squad 清理。新增同步关闭发生在原生公开 Logout 通知前，避免依赖后续 PS 销毁才关闭原队伍；不改变持久存档或切人玩法。Host 仍独占原 Slot 实际生命周期的绑定清理，Teams 不持 H/Context，不新增 GA/ASC 清理链。

## 当前装配与换人链

1. GameMode 的原 GF Session 资格成功就绪后，从实际 PlayerState 取得 Squad 并选择名单；资格失败拒绝装配，原插件请求结束本身不代表成功，见 [[GameFeature/结构|原会话装配门禁]]。
2. native `SpawnSquadSlot(Context, Data, OutActors)` 先准备全部 Slot，Owner 为原 Controller；原生 pre-spawn 捕获产物，`InitializeForPawnData` 后读回原配置/完成事实。false 仍保留原身份并进入 Creator 收尾。
3. native `SpawnSquadMember(Context, Data, Transform, OutActors)` 再准备每个原 Pawn，Owner 同原 Controller；捕获原产物并严格验证原 Extension/PawnData。资格或准备失败消费未交付原对，存活拒绝停止请求。
4. `Slot::AttachAvatar(Member)` 后重检原资格，移出原对并调用 private `RegisterCreatedSlot(Slot, Member)`。先消费 bool：true 只归 Squad，false 由 Creator 请求销毁原 Slot→原 Pawn；再重检当前 Context。详细类型/输出和失败责任见上述创建者 A 契约。
5. 登记只尝试首位出战；后续 `SwitchToSlot(Index)` 先拒绝已终止组件，再校验 Authority、目标索引/实体/死亡状态。正常顺序仍为 `UnPossess → DeactivateSlot → ActiveSlotIndex → ActivateSlot → Possess → 广播`；外调后重检原组件、Controller、Slot/Pawn 身份与终止状态，终止后旧栈不再写出战索引或继续附身。不会每次重设 ActorInfo，也不重建 Slot/ASC，待命 GE/CD/属性仍由 Slot 保有。

本轮只补组件终止、原对象失配时停止旧登记/切人/显隐栈；`ActivateSlot / DeactivateSlot` 在显隐、碰撞和移动外调后检查原 Slot→Character 关系。此保障不等于完整换人事务：切人 GA 退出策略、不可取消能力准入、输入释放政策及完整 Possess 失败/回调重入提交控制仍未接，原生 UnPossess 内部回调事务也不在本步关闭范围。输入/GA 执行边界见 [[Input/结构|Input]] 与 [[AbilitySystem/结构|AbilitySystem]]。
