## 状态所有权与类关系

| 类 / 数据 | 关键接口 | 责任 |
| --- | --- | --- |
| `GGYGOSquad` / `GGYGOSquadTypes.h` | `IsMemberCountWithinCapacity(int32)` | 共享无状态容量规则；唯一上限 `GGYGO_MAX_SQUAD_SIZE=4`。 |
| `AGGYGOCombatantState` | `AttachAvatar(Pawn)` → `EGGYGOAvatarBindResult`、`DetachAvatar(ExpectedPawn)`、`GetAvatarPawn`、`GetGGYGOAbilitySystemComponent`；订阅 Avatar 的 `OnEndPlay／OnDestroyed` | 最小持久战斗宿主；拥有 ASC／基础属性／复制 Avatar。绑定流程（释放旧 Avatar → `InitAbilityActorInfo` → Ready）见 [[Combatants/结构|Combatants]]。换人不重新绑定。 |
| `AGGYGOCharacterSlot` | `InitializeForPawnData`、`GetPawnData`、`IsPawnDataInitializationComplete`；继承 `AttachAvatar` | 玩家编队中一个位置；配置并授予独立 ASC 的角色能力，不拥有编队名单或控制权。 |
| `UGGYGOSquadComponent` | `SetRoster`、借用 `RegisterSlot`、private `RegisterCreatedSlot`、`GetActiveSlot`、`SwitchToSlot(Index, Source)`、`ServerRequestSwitchToSlot(Index)`、`ServerRequestSwitchToAdjacentSlot(±1)`、`GetMemberState(Index)`；native `DestroySquad`、`EndPlay`、`OnComponentDestroyed` | PlayerState 唯一队伍组件；持有 Roster、Slots、ActiveSlotIndex、原始创建弱责任台账，以及服务器上与 Slots 同序的队员运行记录（状态、续放 Spec、退场 Spec、本组件施加的 Tag 与移动开关）。订阅各槽位 ASC 的 `OnAbilityEnded` 推进留场／退场。三终止入口只消费原创建责任，并退订、撤回本组件施加的 Tag。 |
| `UGGYGOGameplayAbility` | `OnAvatarSwitchOut(FGGYGOSwitchContext)` → `EGGYGOSwitchOutDecision`；`NotifyOwnerControlLost／Regained` → 蓝图 `OnOwnerControlLost／Regained` | 能力自行决定换出时取消或留场；默认读 `AvatarExitPolicy`（Cancel／ContinueInBackground）。失去控制通知在补发释放之后、解除附身之前，Controller 仍可读。 |
| `UGGYGOAbilitySystemComponent` | `ReleaseHeldInputForControlLoss()`；`State.SwitchReturnPending` 准入 | 对仍按住的活动 Spec 派发一次真实释放再清空输入；ReturnPending 期间拒绝输入缓冲发起的新激活并登记重试，标签移除后唤醒。 |
| `UGGYGOSquadTransitionAbility` | `TransitionMontage`；由 `Event.Squad.SwitchIn／SwitchOut` 触发 | 进场／退场能力基类：播 Montage，播完正常结束、被打断或失败以取消结束；蓝图实现 ActivateAbility 时由蓝图接管；默认 ServerInitiated。 |
| `UGGYGOHeroComponent` | `ReleasePlayerInput()` | 只退役自身原输入绑定、来源/请求及订阅；ASC 的 `ClearAbilityInput()` 负责原 GAS held/队列。Squad 依次调用公开入口，不复制输入状态。 |
| `UGGYGOSquadPresets` | `TryLoadForLocalPlayer`、`ResolveActivePresetRoster`、`Serialize / HandlePostLoad`、同步/异步原生保存 overrides；编辑接口保持 | 保存跨局 ID 数据，返回显式加载/解析结果；检查原始非法保存及原主 LP 保存来源。无具体 GGYGOLocalPlayer 反向 accessor，不拥有缓存、Roster 或第二保存执行器。 |
| `UGGYGOLocalPlayer` | `TryGetSquadPresets(OutPresets, OutError)`；兼容 `GetSquadPresets()` | 唯一预设缓存宿主；只有合法原主 LP 来源可发布。原模型/LP/GI/platform user/槽元数据是派生来源记录，失效明确失败，不清空后另读或重建替代。 |
| `AGGYGOPlayerState` / `AGGYGOPlayerController` | `GetSquadComponent()` / `UnPossess`、`Possess`、`PostProcessInput` | PlayerState 构造唯一 Squad 默认子对象；Controller 持有玩家连接并执行附身/输入后处理。 |
| `UGGYGOExperienceDefinition` / `AGGYGOGameMode` | `IsDataValid(Context)`、`SpawnSquadForPlayer`、native bool `SpawnSquadSlot / SpawnSquadMember`、`Logout(Exiting)`；private `ConsumeUntransferredSquadActors` | 默认配置与服务器创建/退出编排；只持原 Context/输入快照及自己未交付的原资源。创建交付 true 后只归 Squad。Logout 先抽原 PC 留存批次、关闭原 Squad，再消费 Creator 原批次；完整契约见下节。插件资源仍归 [[GameFeature/结构|GameFeature / GameMode]]。 |

`Presets → Roster → Slots → Pawn Avatar` 是四种不同生命周期的数据：跨局意图、本局名单、实际成员、可替换实体。`Slots` 是唯一成员名单，`ActiveSlotIndex` 是唯一出战索引；`IsSquadAssembled()` 仅读取 `Slots.Num()>0`，不证明整份名单成功装配。`CreatedSlotResources` 只保存显式交付的原始 Slot/Pawn 弱身份对，不复制，不保存当前 Avatar 或活动状态，也不构成第二份名单；终止消费与未退休字段仍归这一台账。组件关闭/消费/最终销毁标志只限制自身生命周期与重入，不形成第二套装配或绑定权威。`bSwitchRequestInProgress` 只覆盖一个同步调用栈（含广播），退出时清除；队员运行记录只在服务器、只由本组件写，随能力结束事件推进，没有切人 Tick、计时器、排队器或第二套能力执行器，也不复制——可见性、碰撞与移动由 Pawn 原生复制，OffField／ReturnPending 由复制的 loose tag 承载。

依赖按职责为：装配请求者 GameMode → Squad / Slot；Slot → [[Combatants/结构|CombatantState]]；宿主 → [[Character/结构|PawnExtension]] / [[AbilitySystem/结构|ASC]]。Squad 通过公开 getter 读回宿主和绑定，不直接写 ActorInfo；private friend GameMode 只开放创建交付权限，不使 Squad 反向调用 GameMode。终止时 Squad 请求原创建 Actor 的 `Destroy()`，原 Slot 实际发生的 `Destroyed / EndPlay` 再由 Host 的 `CloseAvatarBinding` 关闭绑定；该终止消费者不调用 Host/Extension/ASC 的解绑或 GA 清理。换人只经 GA 的换出决定与原终止入口（`RequestAbilityCancel`）、ASC 的补发释放、Hero 的输入退役和原生 Possess；不写绑定，不复制能力状态。Boss 只共用 CombatantState，不进入玩家编队链，见 [[BossAI/结构|BossAI]]。

## 容量、保存与本局名单接口

| 调用方 → 接口 | 输入 / 权限 | 作用与输出 / 失败边界 |
| --- | --- | --- |
| Presets / Squad / Experience → `GGYGOSquad::IsMemberCountWithinCapacity(Count)` | int32 原始数量 | 0～4 为 true，负数或超限为 false；不读名单、不截断、不加载。0 是否业务可用归调用方。 |
| 编成调用方 → `SetPresetMembers(Index, IDs)` | 有效预设序号、原始 ID 数组；本地存档对象 | 超限整体 false，原名单不变；合法时一次替换。空 ID 可作空位，但仍计入原始容量。编辑不自动落盘，调用方显式保存。 |
| 读档 → `Serialize(Ar)` / `HandlePostLoad()` | 原始已保存数据 | loading Archive 错误事实累计保留；非法原始出战索引/超限只诊断，不修正、截断或删除。显式取得入口据这些事实拒绝非法来源，原文件与字段保留。 |
| 装配 / 预览 → `ResolveActivePresetRoster(Out)` / `ResolvePresetRoster(Index, Out)` | 当前/指定预设、原始 ID 数量、真实 AssetManager | 返回 `FGGYGOSquadPresetRosterResolveResult`：`Resolved / Unconfigured / Invalid`，先清输出。原始超限在加载前拒绝；仅显式空 ID 跳过，非法 ID/路径/类型/加载失败整体 Invalid，不发布部分名单。仅完整 Resolved 一次发布 PawnData[]；正常无配置与错误分开。 |
| 名单提供者 → `Squad::SetRoster(PawnData[])` | Owner 为 Authority，Slots 尚为空，组件未终止且有效 | 先校验原始数量，再在临时 Candidate 中跳过 null；至少一名有效成员才一次替换 Roster。终止后、非权威、已装配、空/全空或超限 false，原 Roster 不变。 |
| 编辑器 / 生成前 → 容量规则 | 编辑期默认 `SquadMembers`；运行时实际选定 Roster 或 Experience 原数组 | 编辑期错误成员报 Invalid；运行时 GameMode 在 PawnData 弱复制、ChoosePlayerStart 和 Actor 生成前检查原始 Num，空项也计数。超限整体停止，不过滤后缩到上限、不截断/补员；空数组容量合法但本次生成要求非空。 |

实际来源先用非空已有 Roster；为空时调用 `TryApplySavedRoster`，通过原 `UGGYGOLocalPlayer::TryGetSquadPresets` 与模型解析消费来源：`Applied` 使用完整已设置名单；只有正常 `Unconfigured` 才选择 Experience 默认；`Invalid` 明确诊断并在 Actor 生成前停止。服务器远程 PC 明确没有 LP 是既有正常 Unconfigured 模式，次级本地 LP 的保存拒绝不能伪装成此模式。原始容量及后续真实出生点准入适用于实际选定来源；空/非法依赖不替换为另一编队。已交付成员不回滚，整队成功政策仍未闭合。

## 主玩家保存与唯一缓存

用户已选择保留既有 `GGYGOSquadPresets` 原槽，只允许原 GameInstance 的主 LocalPlayer 持久化；次级本地玩家明确拒绝，不访问主玩家文件。非法旧文件/字段保留，未授权迁移、修复、重置或覆盖。该政策限制保存来源，不把每名玩家的本局队伍改为主玩家独占；远程上报及次级玩家的显式本局名单接线仍按现有边界处理。

| 调用方 → 真实接口 | 输入 / 输出 | 来源、生命周期与失败 |
| --- | --- | --- |
| LP 宿主 → `TryLoadForLocalPlayer(const ULocalPlayer*)` | `FGGYGOSquadPresetLoadResult`；`Loaded / CreatedForMissingSlot / Invalid`，Error、原 LP/GI/user/index/槽及 scoped strong Candidate | 原主 LP、原 GI/platform user 与固定原槽均须合法并重检。既有文件读取/类型/已观察 Archive/原始索引错误明确 Invalid。明确缺槽才创建内存候选，工厂自身不保存；Invalid 不创建替代对象。 |
| 兼容 → `LoadOrCreateForLocalPlayer(LP)` | 委托上述入口；Invalid 返回 nullptr | 不再通过引擎 LoadOrCreate 掩盖错误或创建另一对象来源。 |
| GameMode / PC → `TryGetSquadPresets(UGGYGOSquadPresets*& OutPresets, FString& OutError) const` | bool，失败清 Out 并给 Error | `UGGYGOLocalPlayer` 的原一份 UPROPERTY 缓存是唯一宿主；原 cache/LP/GI/user/index/槽及模型原生 association 均须一致。来源失效、重入或取得失败不发布，不 Reset 后另读/重建。临时强引用只保本次回调生命周期，派生元数据不形成第二缓存。 |
| 蓝图兼容 → `GetSquadPresets()` | 委托 TryGet；失败日志/空值 | 取得失败是显式失败结果，不能当成正常未配置。 |
| 保存 → `SaveGameToSlotForLocalPlayer()` / `AsyncSaveGameToSlotForLocalPlayer()` | 原 native bool；private `RequestSaveForOriginalSource(bool bAsync)` | 请求前检查原模型、原主 LP/GI、platform user/index、原 native/实际 virtual 槽路由、已知 Archive 错误和原始索引；拒绝不改文件或重置内存。通过才委托 Super，计数、执行与完成仍归引擎。 |
| 三个 PC 编辑 Exec → 原生同步保存 | 取得前后核对原 PC/LP；复制诊断后消费 native bool | false 记录拒绝/失败，当前内存编辑保留；true 只报告请求结果，不证明持久化。没有额外监听器、计数器或执行器。 |

`GetForPlayerController` 已从保存模型移除，实际 GameMode/PC 取得端均经 LP facade；模型只依赖引擎 `ULocalPlayer` 参数，不依赖具体项目 LP 缓存实现。编辑 setter 的正常规则与不可信读档校验分开，`HandlePostLoad` 不自行修复非法旧值。

本合同是已检测来源/数据错误的拒绝与请求准入；不声明原生文件头解析的全覆盖，不撤销已经接受的异步请求，也不拦截任意 `GameplayStatics` 绕过保存入口。落盘、旧文件异常及真实主/次玩家动态验收未由编译证明。政策证据见[原主玩家保存决定](F:/ue_project/GGYGO/Saved/ValidationRecords/TeamsSaveSlotPolicy_20261004_UserDecision.json)。

## Slot 初始化与跨模块绑定读回

| 调用方 → 接口 | 输入 / 前提 | 作用与输出 / 副作用 |
| --- | --- | --- |
| GameMode → `Slot::InitializeForPawnData(Data)` | Authority、非空 Data，既有 PawnData 尚未设置 | 固定一次角色定义，安装 ASC 组规则/Tag 关系并执行 AbilitySet 授予循环；void，重复设置拒绝，不重授予。基础属性已由宿主默认子对象提供。 |
| GameMode 准备 / Squad 新接收 → `Slot::IsPawnDataInitializationComplete()` | C++ 服务器原初始化事实查询 | 仅返回 `PawnData != nullptr && bAbilitiesGranted`。GameMode 在原初始化外调后读回，Squad 保持唯一新成员准入规则。空 AbilitySets 循环结束也可 true；不新增状态/反射/复制，不保证所有 GA/GE 配置成功或客户端 GameplayReady。 |
| GameMode → `PawnExtension::SetPawnData(Data)` | Authority、原 Pawn 的有效原 Extension、非空原角色配置 | 准备 helper 外调后重取原 Pawn/Extension，验证同一 Extension、Owner 与原 PawnData；缺组件或读回失配返回 false 并保留原产物。供 Pawn InitState 使用，不再次授予 Slot 的能力。 |
| GameMode → `Slot::AttachAvatar(Pawn)` | 原 Context/Slot/Pawn 准备资格仍匹配 | 继承 CombatantState 唯一绑定入口：释放旧 Avatar、`InitAbilityActorInfo`、复制 Avatar，由 Extension 广播 Ready；GameMode 不消费返回的 `EGGYGOAvatarBindResult`，调用不证明绑定成功。外调后 Creator 重检原资格，再由 `RegisterCreatedSlot` 执行唯一接收/绑定验证；不在 Creator 复制绑定规则或清理。 |
| Squad → `Slot::GetGGYGOAbilitySystemComponent()` / `GetAvatarPawn()` / `GetPawnData()` | 只读 | 获取持久 ASC、当前 Avatar 和配置；再对照 ASC Owner/Avatar 与 PawnExtension 的 ASC/PawnData，避免重复写绑定。 |

### 登记上下文与新成员准入

两个接收入口先拒绝已终止、无效或正在销毁的组件，再读回实际 `AGGYGOPlayerState::GetSquadComponent()==this`，要求 PlayerState/Controller 有效且不在销毁、Authority、同 World，并要求 `PlayerState.GetOwner()` 为该 Controller、`Controller.GetPlayerState<AGGYGOPlayerState>()` 指回同一宿主。动态添加的第二 Squad 即便挂在 PlayerState 上也不能替代唯一队伍。

合法重复在上述权限/唯一宿主检查之后、容量与新成员绑定检查之前处理。新成员才需要 Slot 有效且不在销毁、Authority/同 World/Owner 为该 Controller，05a1 查询完成；ASC 有效且不在销毁，OwnerActor 为 Slot；Avatar 是有效且不在销毁的 `AGGYGOCharacterBase`、Authority/同 World，Controller 为空或同 Controller；ASC AvatarActor 等于 Slot Avatar；PawnExtension 有效且不在销毁，其真实 Ready getter 返回 Slot ASC，PawnData 与 Slot PawnData 相同。不额外要求尚未 Possess 的 Pawn 已达到全部 InitState GameplayReady；死亡是否可出战由切人准入决定。Slot.Owner 必须保持原 Controller；Pawn.Owner 是原生控制状态，`APawn::UnPossessed` 合法清空它，不能把它作为待命成员的持久归属条件。

## 两个接收入口与原始创建责任

| 接口 | 输入 / 权限 | 输出与责任 |
| --- | --- | --- |
| `bool RegisterSlot(Slot)` | public BlueprintCallable；上述权威上下文，新成员通过绑定与容量验证 | 只接收借用成员关系。新增成员进入 Slots，默认待命；尚无出战位时尝试原 `SwitchToSlot(0)`。true 表示关系已接收，不保证自动激活/Possess。 |
| `bool RegisterCreatedSlot(Slot, OriginalCreatedPawn)` | private、非 UFUNCTION，仅 friend `AGGYGOGameMode` 的 C++ 创建交付；新请求显式原 Pawn 必须是当前已验证 Avatar | 同时提交 Slots 与原始创建责任，早于表现/自动激活回调。真实 GameMode 已调用并先消费 bool：true 退休 Creator 责任，即使回调已终止；false 不接收，Creator 请求销毁未交付原对。Squad 三终止入口唯一消费已交付原 Actor；不以自动激活/Possess 成功决定归属。 |

| 重复 / 失败路径 | 当前契约 |
| --- | --- |
| 普通重复（含已创建登记的成员） | 权限有效时 true，不重放待命/激活，不新增、升级或降级创建责任；已满也不误拒绝。 |
| 已借用成员再走创建入口 | false，不能通过一次补调用接管其 Slot/Pawn 的清理。 |
| 同 Slot、同原始 Pawn 创建重复 | 按原始弱对象 index+serial 身份 true，即使当前 Avatar 已替换；不要求当前绑定仍是原 Pawn。 |
| 同 Slot、不同原始 Pawn，或原 Pawn 已在另一创建记录 | false，旧责任不变；不让两个记录共同接收同一原 Pawn。 |
| 创建记录存在但 Slots 缺失 | false，不覆盖原记录或降级成借用。 |
| 新请求权限/初始化/容量/绑定失败 | false，提交前无名单、创建记录、待命或附身副作用。 |
| 提交后表现、自动 Switch 或 Possess 失败/重入 | 仍 true；名单与责任先于外部回调一起提交，重复不重放。待命外调后组件已终止/销毁时停止旧栈并保持已接收事实；自动激活前再读当前上下文和首位绑定，失配则跳过尝试，不交回责任。 |

弱身份使用 `HasSameIndexAndSerialNumber`，不通过两个失效 `Get()==nullptr` 推断同对象；原始记录不随 `GetAvatarPawn()` 替换而迁移。重复 true 只确认已接收身份，不证明当前可出战；后续上下文失效返回 false 也不会撤销先前责任。创建者须保留已成功交付事实，不能按一次重试结果或当前 Avatar 推断是否可回滚。

## GameMode 创建准备、交付与未交付责任（创建者 A）

| 接口 / 数据 | 输入与输出 | 责任与清理 |
| --- | --- | --- |
| `void SpawnSquadForPlayer(APlayerController* NewPlayer)` | 原 GameMode/World/GF Session/Controller/PlayerState/唯一 Squad/Experience；选定 PawnData 的本次弱身份快照 | 复用既有 GF 门禁及 Squad 只读登记上下文；同 Controller 同步重入拒绝。原栈退出清理请求保护，不另存成员/Ready 事实；存在该 Controller 的存活拒绝残留时拒绝新生成。 |
| `bool SpawnSquadSlot(const FSquadCreationContext& Context, const UGGYGOPawnData* PawnData, FUntransferredSquadActors& OutActors)` | native 准备结果；OutActors 记录实际原 Slot | `CustomPreSpawnInitialization` 仅捕获实际原 Actor，先于全局 pre-spawn/项目回调；即使 Spawn 返回空也保留已捕获身份。初始化后重取原对象、Context、Owner/World/Authority、原 PawnData 与完成查询。false 不清原产物，不表示交付。 |
| `bool SpawnSquadMember(const FSquadCreationContext& Context, const UGGYGOPawnData* PawnData, const FTransform& SpawnTransform, FUntransferredSquadActors& OutActors)` | native 准备结果；OutActors 在原 Slot 之外记录实际原 Pawn | 同样在原生 pre-spawn 捕获；PawnClass 必须是 CharacterBase 子类，原 Extension 必须有效；SetPawnData 后重检原对象/Extension/配置。失败诊断并返回 false，不返回替代 Pawn，不把缺组件当作成功。 |
| `FUntransferredSquadActors` / `UntransferredSquadActors` | 原 Controller/PawnData/Slot/Pawn 弱身份及定位路径 | 准备/交付中的原产物仅归本次同步栈；GameMode 数组只保留原生拒绝且仍活的未交付字段。已交付身份仅归 Squad 的 CreatedSlotResources；不保存当前 Avatar、绑定状态、名单或完成状态。 |

1. 全部 Slot 准备在 Pawn 阶段之前完成；每次外调后只重取原弱身份并重检资格。选定名单先检查原始容量，再复制为本次 PawnData 弱快照。ChoosePlayerStart 后保存原 Actor/Root 弱身份，拒绝 null、失效、销毁中、错 World、缺 Root 或 Root 替换；真实 Root 世界 Transform 在快照前后复核原 Context/身份，并用 `IsValid()` 拒绝非法值。真实有效世界原点 Identity 合法，不能以缺依赖代入 Identity。
2. 原 Slot/Pawn 准备有效才调用 `Slot::AttachAvatar(Member)`。调用 private `RegisterCreatedSlot(Slot, Member)` **之前**将原对移出 Creator 可清理集合；交付期间只有原同步栈等待返回，Creator 重入关闭不消费这一对。
3. 返回后先处理真实 bool，再检查当前资格。true 是已接收历史，立即退休 Creator 责任；false 由 Creator 回收原对。不按成员数、存活、Owner 或当前 Avatar 反推责任，不降级借用、不反交，不因回调失效或自动激活失败回滚已交付成员。
4. `RequestUntransferredSquadActorDestruction` 是未交付原资源唯一 Actor.Destroy 请求实现，按原 Slot→原 Pawn。接受、失效或已销毁中逐字段退休请求义务；Authority/World 无效或原生拒绝且仍活时保留精确原字段与定位诊断。当前请求遇存活拒绝停止；后续同 Controller 请求拒绝新生成，无 Tick 或自动重试。
5. stack 收尾调用 `FinishUntransferredSquadActors`；bool 只说明本批请求义务是否退休，不证明物理清理。GameMode 原 Controller Logout 与整体关闭均复用同一 Creator 消费者，具体筛选、钩子、重入与单次整体关闭见 [[Teams/结构#原 Controller Logout 与 Creator 留存收尾|退出契约]]。创建栈自身及交付期间原对不被生命周期消费者接管；拒绝原物在来源可用时只追加留账，最终无法留存明确 Error。
6. 已交付原资源只能由 Squad 的终止消费者请求销毁。原 Slot 真正发生原生生命周期时由 Host 关闭自己的绑定；GameMode 不调用 Detach/Clear 或 GA 取消。

创建准备/交付与原 Controller 收尾的验收记录见 [[计划_队伍与装配#9.0 当前实施状态与后续门禁（2026-09-30）|计划与证据]]；当前整队成功政策、完整幂等及物理完成边界保持开放。

## 原 Controller Logout 与 Creator 留存收尾

| 真实接口 / 模式 | 原输入与输出 | 唯一责任 |
| --- | --- | --- |
| public `void Logout(AController* Exiting)` | 外调前固定原 GameMode/PC 弱身份；随后原 PS/World/唯一 Squad 来源校验 | 退出清理允许仍有效但正在销毁的 PC，不用 `GetRegistrationController` 或新工作准入阻断清理。每次调用 `Super::Logout(Exiting)` 恰好一次，Teams 清理校验失败也保留原生通知；外调后不取得后继 PS/Squad。 |
| private `ConsumeUntransferredSquadActors(bool bFinalDestruction, const TWeakObjectPtr<APlayerController>* OriginalController, TFunctionRef<void()> BeforeActorDestroy)` | 退出：false + 原 PC selector + `CloseOriginalSquad` 钩子；整体关闭：true + nullptr + 显式空操作钩子 | 原 GameMode 的一个 `UntransferredSquadActors` 主账本；回调同步且不存储。无效模式或显式空 PC selector 明确拒绝，不改成整体消费。 |
| `RequestUntransferredSquadActorDestruction` / `FinishUntransferredSquadActors` | 局部原批次、原 Creator 弱身份/路径；Finish 的 bool 只表请求义务 | 既有唯一原 Slot→原 Pawn Destroy 请求实现；接受/失效/销毁中退休字段，拒绝存活原物只追加回原 Creator 主账本。 |
| `Destroyed / EndPlay` | 原 GameMode 整体终止 | 先 GF Close，原 Creator 仍可用时调用整体模式，再 Super；首次整体关闭取主账本剩余条目，后续终止入口不自动再次扫描拒绝项。 |

1. 原 PC 筛选用 `HasSameIndexAndSerialNumber`，即使弱对象后来失效仍区分原身份；不能用两个 `Get()==nullptr` 把不同失效 Controller 混为同一来源。只把匹配的**既有留存条目**移入本次局部批次并从主账本移除，其他 Controller 条目保留，早于任何 Squad/Actor 清理外调。
2. `BeforeActorDestroy` 调用现有 `CloseOriginalSquad`：捕获原 PS/World/Squad、验证权威与原归属，再调用 `Squad::DestroySquad()`。Squad 先关闭登记、移出自己的已交付台账，再控制/广播/Destroy；原创建 Context 随之拒绝继续移交。已提交的 Created true 仍是历史接收，责任不反交。
3. 钩子之后 Creator 仅将自己的已抽出批次交给原 Finish/Request。创建中的原产物仍归原同步栈；已交付原物仍归 Squad。回调新留存条目不被旧清理 Reset，也不自动扫描重试。
4. 嵌套 Controller 退出只能取得主账本中尚未移出的匹配条目。首次整体关闭可在消费护栏中接管主账本剩余条目，不能取得外层已移出的批次；后继整体关闭即使护栏已释放也不重扫。只有取得护栏的原外层在原 Creator 可用时释放该护栏；没有新计时器、队列、账本或 Destroy 执行器。
5. 单次整体关闭是 **GameMode Creator** 的合同；Squad 后续显式/真实终止入口仍沿其既有消费协议。原生接受 Destroy 不是物理清理、Host Clear 或能力退出完成。原生拒绝且 Creator 尚可用时保留原字段并诊断；最终来源已不可用时明确无法留存，不制造成功。

原生断线顺序为 PC 的 PawnLeavingGame/UnPossess → Controller 调用 GameMode Logout → CleanupPlayerState/OnDeactivated → Squad 组件生命周期；普通断线本已有后续 Squad 清理。新增同步关闭发生在原生公开 Logout 通知前，避免依赖后续 PS 销毁才关闭原队伍；不改变持久存档或切人玩法。Host 仍独占原 Slot 实际生命周期的绑定清理，Teams 的终止消费者不直接解绑，不新增 GA/ASC 绑定清理链；普通换人见 [[Teams/结构#换人：留场、退场与进场|换人]]。

## 原始创建资源的唯一终止链（08-05b）

| 入口 / 消费者 | 输入与生命周期 | 当前行为与责任 |
| --- | --- | --- |
| `void DestroySquad()` | public native、非 UFUNCTION；显式终止队伍 | 调用同一 private `ConsumeCreatedSlotResources(false)`；不返回整体成功，也不重新开放队伍。 |
| `EndPlay(Reason)` | 组件真实 EndPlay | Super 前调用同一消费者，`false`；不复制清理链。 |
| `OnComponentDestroyed(bDestroyingHierarchy)` | 组件最终销毁 | Super 前调用同一消费者，`true`；最终销毁意图先于重入检查记录，剩余存活原资源必须明确诊断。 |

1. 在任何外部调用前关闭准入，移出原 `CreatedSlotResources` 到唯一局部消费栈，清空 Roster/Slots 并将 ActiveSlotIndex 置 INDEX_NONE。重入由外层栈继续，不再次派发；BeginPlay 不重开这次终止。
2. 首次仅在原 PlayerState→唯一 Squad、Controller↔PlayerState、原活动 Slot→Pawn、Controller↔Pawn 及 Owner/World/Authority 均仍匹配时 `UnPossess`。控制连接缺失或变化只跳过该操作，不跳过原创建责任；组件仍可用时仅首次广播空活动角色。
3. 只消费已显式交付的原 Slot 和 `OriginalCreatedPawn`，每条记录先请求原 Slot `Destroy()`，再请求原 Pawn。当前 Avatar/Owner 不能推导或迁移创建责任；后来接管的实体不因此被销毁。借用成员只退出自己的名单/控制关系，不 Destroy、不直接释放 Host 绑定，也不补隐藏/碰撞操作。
4. 原弱对象已失效或已在销毁中不重复请求；原生接受（含延迟 Destroy）只退休该字段的请求义务，不等于物理清理已完成。Authority 丢失或 Destroy 拒绝且原对象仍存活时明确记录模块/组件/原资源和原因，未退休字段保留回同一个台账；已接受字段不会因另一字段失败重复销毁。外调后只重检原弱身份，组件最终销毁仍有存活未处理对象时逐项 Error。
5. 不创建 Tick、自动重试队列或第二执行器；后续显式入口/真实生命周期可再次处理原台账残留。绑定退出由原 Slot 实际发生的原生生命周期经 Host 的 `CloseAvatarBinding` 完成；该终止消费者不调用 `DetachAvatar / ClearActorInfo`，也不直接取消 GA 或释放 Hero/Input。
6. 登记、Switch/Next/Previous、显隐/碰撞/移动外调及 OnRep 均在组件终止或原对象失配时停止旧栈。已经接收的登记仍 true，不把责任反交创建者；普通换人的流程见下文「换人：留场、退场与进场」；这不证明 Created 终止全链已运行通过。

Host 关闭见 [[Combatants/结构#绑定与释放顺序|Host 绑定与释放]]；原生 Destroy 接受不等于绑定物理清理完成。静态及运行记录见 [[计划_队伍与装配#9.0 当前实施状态与后续门禁（2026-09-30）|计划与证据]]。

## 当前装配与换人链

1. GameMode 的原 GF Session 资格成功就绪后，从实际 PlayerState 取得 Squad 并选择名单；资格失败拒绝装配，原插件请求结束本身不代表成功，见 [[GameFeature/结构|原会话装配门禁]]。
2. native `SpawnSquadSlot(Context, Data, OutActors)` 先准备全部 Slot，Owner 为原 Controller；原生 pre-spawn 捕获产物，`InitializeForPawnData` 后读回原配置/完成事实。false 仍保留原身份并进入 Creator 收尾。
3. native `SpawnSquadMember(Context, Data, Transform, OutActors)` 再准备每个原 Pawn，Owner 同原 Controller；捕获原产物并严格验证原 Extension/PawnData。资格或准备失败消费未交付原对，存活拒绝停止请求。
4. `Slot::AttachAvatar(Member)` 后重检原资格，移出原对并调用 private `RegisterCreatedSlot(Slot, Member)`。先消费 bool：true 只归 Squad，false 由 Creator 请求销毁原 Slot→原 Pawn；再重检当前 Context。详细类型/输出和失败责任见上述创建者 A 契约。
5. 登记只尝试首位出战，真实接收 true 不因自动切人失败反交创建责任。后续换人走 `SwitchToSlot(Index)`，流程见下节。Slot/ASC/Avatar 关系不重建，待命 GE/CD/属性由原 Slot 保有；原生 Controller 变更通过现有 Character→PawnExtension 链合法 Refresh ActorInfo。

## 换人：留场、退场与进场

### 队员状态（服务器）

| 状态 | 表现 | 进入 | 离开 |
| --- | --- | --- | --- |
| Benched | 隐藏、无碰撞、`DisableMovement` | 登记；退场完成 | 被切入 → Active（显示、恢复行走、发 SwitchIn） |
| Active | 被玩家控制 | 被切入 | 被换出 → Lingering 或 Exiting |
| Lingering | 可见、有碰撞、`bRunPhysicsWithNoController`；`State.OffField`＋服务器上的 `Gameplay.Damage.Immunity` | 换出时有能力选择 ContinueOnField | 续放全部结束 → Exiting；被切回 → Active（解除 OffField，加 ReturnPending，不播进场） |
| Exiting | 同 Lingering | 发 `Event.Squad.SwitchOut` | 被激活的退场能力全部结束或未激活 → Benched；被切回 → Active（取消退场） |

同一时刻一个 Active，任意数量 Lingering／Exiting。隐藏走引擎复制的 `bHidden`；引擎的整体碰撞开关不复制，Squad 经 `AGGYGOCharacterBase::SetReplicatedActorEnableCollision` 由服务器设置并复制。服务器上待命 Pawn 的 Mesh 置 `bNoSkeletonUpdate`：从未附身的队员没有 Controller，PawnExtension 未完成初始化、CMC 没有 MovementSet，不能求值动画；`ActivateSlot` 在 Possess 之后恢复。不用关组件 Tick，因为开局登记可能早于 BeginPlay，注册会重新打开 Tick。隐藏、无碰撞且不属于观察者的待命 Pawn 按引擎相关性规则不复制给该客户端。MeleeTrace 跳过持有 `State.OffField` 的目标（不记入窗口去重），留场队员不产生命中、伤害 GE、Cue 或受击；它自己的能力照常命中结算，见 [[Combat/结构|Combat]]。

### 接口

| 请求者 → 入口 | 输入 → 作用 → 结果 |
| --- | --- |
| 客户端／蓝图 → `ServerRequestSwitchToSlot(Index)` | Reliable、WithValidation 只查序号范围 → 服务器以 PlayerRequest 调 `SwitchToSlot`。开发期控制台 `GGYGOSwitchToSlot N`（PlayerController Exec）走它。 |
| 玩家按键 → PlayerController → `ServerRequestSwitchToAdjacentSlot(Direction)` | Direction 为 -1／1（WithValidation 只收这两个值）→ 服务器从 `ActiveSlotIndex` 循环找相邻、有实体且未死亡的位置，以 PlayerRequest 调一次 `SwitchToSlot`；真实切换失败不换目标重试。`SwitchToNextSlot`／`SwitchToPreviousSlot`（Script 来源）共用同一查找。 |
| `AGGYGOPlayerController` 换人键 | `SquadSwitchInputMapping`（默认 `IMC_Squad`：Z 上一个、C 下一个）与两个 InputAction 配在 `BP_PlayerController`；本地 Controller 建好 InputComponent 后按 Started 绑定并注册 IMC，EndPlay 归还自己那一份。键归 Controller 而不放 Hero 会话：换人会同步退役旧 Pawn 的输入会话。IA 带 PlayerMappable 名 `SwitchCharacterPrevious`／`SwitchCharacterNext`，供以后的改键界面使用。三项都不配表示不提供换人键，只配一部分报 Error。 |
| 服务器 → `bool SwitchToSlot(Index, Source = Script)` | 拒绝并诊断：组件终止、同步重入、越界、目标为当前出战、无 Avatar 或已死亡、绑定无效、原控制不符、Cancel 决定的能力不可取消、退场中切回而退场能力不可取消。true 表示新队员已被控制并广播 `OnActiveCharacterChanged`。外调改变原布局时停止并报 Error，已发生的效果不恢复。 |
| Squad → GA `OnAvatarSwitchOut(Context{TargetSlotIndex, Source})` | 每个活动能力一次 → Cancel 或 ContinueOnField。只做决定：同批有不可取消的 Cancel 时整次拒绝，此前没有切换效果。 |
| Squad → GA `RequestAbilityCancel(Original, true)` | Cancel 决定的原激活 → 取消；回调里结束的续放能力由 OnAbilityEnded 从续放集合移除。 |
| Squad → ASC `ReleaseHeldInputForControlLoss()` | 旧队员仍按住的活动 Spec → 一次 `AbilitySpecInputReleased`（WaitInputRelease 收到）→ 清空输入。 |
| Squad → GA `NotifyOwnerControlLost／Regained()` | 续放能力 → 原生钩子与蓝图事件；依赖 PlayerController 的逻辑在这里收尾。 |
| Squad → 槽位 ASC `HandleGameplayEvent(Event.Squad.SwitchIn／SwitchOut)` | 发事件期间临时订阅 `AbilityActivatedCallbacks`，记录本次同步激活且仍在执行的 Spec；退场时等待它们结束。 |
| 槽位 ASC `OnAbilityEnded` → Squad | Spec 从续放／退场集合移除 → Lingering 续放清空则退场；Exiting 退场清空则隐藏；Active 续放清空则移除 ReturnPending。 |

### 流程

```text
校验目标与原控制 → 同步重入护栏
旧队员：取得全部换出决定 → 有不可取消的 Cancel 则整次拒绝
旧队员：移除自身 ReturnPending → 登记续放 → 取消其余
旧队员：补发按住输入的释放 → 续放能力 OnOwnerControlLost → Hero ReleasePlayerInput → UnPossess
Possess 新队员（镜头随原生 ViewTarget）→ 写 ActiveSlotIndex
新队员 Benched：显示、碰撞、MOVE_Walking → 发 SwitchIn
新队员 Lingering／Exiting：取消退场能力 → 解除 OffField → 仍有续放则加 ReturnPending → OnOwnerControlRegained
旧队员：加 OffField → 有续放则 Lingering，否则发 SwitchOut；无退场能力被激活则立即隐藏
广播 OnActiveCharacterChanged
```

ReturnPending（`State.SwitchReturnPending`，复制给拥有者）只拦输入缓冲发起的新激活和 locomotion 移动；事件触发的能力（受击、死亡）不受影响，已在运行的续放能力照常收到按键。被拦的按下在缓冲窗口内登记重试，标签移除后下一次 `ProcessAbilityInput` 重试一次，见 [[AbilitySystem/结构|AbilitySystem]] 与 [[Input/结构|Input]]。

Next/Previous 只跳过不可出战位；一旦尝试了真实切人，失败立即返回，不换另一目标重复。首位登记时的自动 `SwitchToSlot(0)` 同样向首位发 SwitchIn。实体替换/销毁才走 [[Combatants/结构|Host 绑定]]，普通换人不调用 Detach，不重建或搬运 ASC。
