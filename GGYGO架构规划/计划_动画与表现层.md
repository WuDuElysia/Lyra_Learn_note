## 0. 这次重构解决什么

当前动画代码的局部设计并不差：快照集中读取、过渡判定无副作用、CMC 承担移动权威、
Montage Notify 只发 GameplayEvent。这些原则都保留。

真正需要重构的是两个边界问题：

1. **移动层与表现层形成运行时依赖环。**
   CMC 从当前 AnimInstance 读取 `RootMotion_*` 曲线来决定速度、位移和转身相位；
   AnimInstance 又从 CMC 读取步态、速度与转身相位来选择动画。
2. **C++ 过度映射了 AnimBP 的具体拓扑。**
   `NotMoving_To_Conduit`、`Conduit_To_EnterMove`、`WalkRun_To_TurnBack` 等函数
   与蓝图状态和连线一一对应。蓝图若重排状态机，C++ 也必须跟着改。

这两件事叠加后，表面上文件分得很规整，实际修改一个动画状态会跨
AnimBP、AnimInstance、Decisions、Events、StateMemory、CMC 与曲线采样器多处联动。

本次目标不是把所有动画逻辑移到蓝图，也不是让蓝图接管玩法状态，而是建立稳定界线：

> **C++ 决定“真实发生了什么、允许发生什么”；蓝图决定“这些事实如何被表现”。**

修改频率只是辅助判断。凡是涉及服务器权威、网络预测、伤害、位移、可打断性和跨帧
确定性的规则，即使策划经常调整，也不能因为“经常改”就放进 AnimBP。

## 1. 冻结的职责边界

### 1.1 C++：稳定事实、权威规则与线程边界

C++ 负责：

- CMC 的真实速度、加速度、移动模式、步态与朝向；
- GAS 的攻击、受击、死亡、控制限制和 Ability 激活状态；
- RootMotionSource 的创建、优先级、结束条件、复制与预测；
- 转身/刹停这类会改变碰撞体位置的**权威移动动作**；
- 客户端预测需要进入 `SavedMove` / `NetworkMoveData` 的状态；
- 游戏线程采集后可供动画线程只读的帧快照；
- 通用 Montage AbilityTask、GameplayEvent 和 GameplayCue 路由；
- DataAsset 类型、字段约束、Cook 引用和 `IsDataValid()` 校验；
- 不依赖 UObject 世界状态的纯计算与自动化测试。

C++ **不负责**：

- 知道 AnimBP 中存在多少个状态、Conduit 或过渡线；
- 用函数名逐条镜像 `Idle → Start → Loop → Stop` 的蓝图连线；
- 决定某个角色使用 `WalkStartEnd`、`RunEnd` 还是另一段动画；
- 决定惯性化、Blend Pose、Layered Blend、IK 节点如何排列；
- 保存只服务某个 AnimBP 的 Select 索引。

### 1.2 AnimBP / Linked Anim Layer：表现拓扑

蓝图负责：

- Locomotion 状态机拓扑；
- Idle / Start / Loop / Stop / Turn 的动画选择；
- `Time Remaining`、Relevant Time、同步组与 Marker 等纯动画时序；
- BlendSpace、Blend Pose、Inertialization、Layered Blend、Slot；
- AimOffset、Additive、IK、Foot Placement、Stride Warping；
- 不同武器姿态、不同角色体型和 Boss 形态的表现差异；
- 通过只读字段判断“如何表现”，但不写 CMC、ASC 或战斗状态。

蓝图可以频繁修改状态机和混合方式，只要它仍只消费同一份语义输入，C++ 就不需要变化。

### 1.3 DataAsset：可调配置与资产集合

DataAsset 负责：

- 角色/形态使用哪一套 AnimProfile 或 Linked Anim Layer；
- 通用但需要调参的混合速度、播放速率范围、Stride 比例；
- 权威 MotionProfile 的曲线资产与允许 C++ 读取的参数；
- 动画资产引用和缺失校验。

DataAsset 不写流程逻辑。不能用一组布尔配置在资产里拼出第二套状态机。

### 1.4 Montage Notify：唯一受控的反向通道

AnimNotify / NotifyState 可以向 GA 发 GameplayEvent，例如：

- 命中窗口开始/结束；
- 连段输入窗口；
- 可取消点；
- 纯表现 Cue 时点。

Notify 不能：

- 直接扣血、施加 GE；
- 直接调用 CMC 切步态或改速度；
- 直接切 Boss Phase/Form；
- 缓存并调用某个具体 GA、Controller 或 BossState 类型。

GameplayEvent 只是“动画时间轴到达一个语义点”的报告。是否接受以及如何改变权威状态，
仍由当前 GA/C++ 规则决定。

## 2. 目标依赖方向

### 2.1 最终数据流

```text
输入 / AI / GAS
       │
       ▼
CMC + ASC                         ← 权威层（C++）
       │
       ▼
FGGYGOAnimationStateFrame         ← 一帧只读事实
       │
       ▼
UGGYGOAnimInstanceBase            ← 薄适配层
       │
       ├─ Locomotion Linked Layer
       ├─ FullBody Action Slot
       ├─ Additive / Aim / IK Layer
       └─ Reaction Layer
                                      表现层（AnimBP）
```

依赖只向下。AnimBP 不反向成为 CMC 的数据源。

### 2.2 当前需要消除的环

```text
CMC::TickComponent
  → GetMesh()->GetAnimInstance()->GetCurveValue()
  → 曲线决定 CMC 速度/转身相位
  → AnimInstance Capture 再读 CMC
  → AnimGraph 选动画
  → 下一帧 CMC 再读该动画
```

这个环导致：

- 移动结果依赖 AnimGraph 的更新时间和上一帧播放状态；
- Dedicated Server 不评估动画时没有同一份曲线；
- 客户端预测无法仅靠 CMC 状态完整重演；
- 修改表现蓝图可能改变权威移动；
- 当前只能用 `MaxCurveDrivenSpeed` 放宽校验来兜底，而不是得到完全一致的重演。

## 3. C++ 对动画只发布语义帧

当前已实现的稳定帧包含以下语义（字段以源码为准）：

```cpp
USTRUCT(BlueprintType)
struct FGGYGOAnimationStateFrame
{
    GENERATED_BODY()

    FVector WorldVelocity = FVector::ZeroVector;
    FVector WorldAcceleration = FVector::ZeroVector;
    float HorizontalSpeed = 0.0f;
    FVector WorldVelocityDirection = FVector::ZeroVector;
    float LocalVelocityAngle = 0.0f;
    FVector2D LocalVelocityBlend = FVector2D::ZeroVector;

    EGGYGOGait Gait = EGGYGOGait::None;
    TEnumAsByte<EMovementMode> MovementMode = MOVE_None;
    EGGYGOTurnBackPhase TurnBackPhase = EGGYGOTurnBackPhase::None;

    bool bHasMoveInput = false;
    bool bMovingHorizontally = false;
    bool bGrounded = true;
    bool bMovementBlocked = false;
    bool bTurnBackRunOut = false;

    FGameplayTagContainer OwnedStateTags;
};
```

Anim-A 审计确认 ABP_Pyrios 当时实际消费的是七条 Transition 函数、
`StateMemory.GaitBlendY`、`StateMemory.StopValue`、`GetSeqByKey` 与
`GetBlendSpaceByKey`。Anim-C 已把七条 Transition 改为 `AnimationState.bHasMoveInput`、
`IsAnimationRunGait()`、`IsTurnBackCurveDriven()` 与蓝图布尔节点的组合；后四个
表现/查表入口仍保留。

仍需在后续阶段确认：

- 新角色与 Boss Form 是否需要新增稳定语义字段；
- 当前字段中哪些可以在兼容层移除后由已有字段纯推导；
- 是否需要复制 Tag Container，还是只发布有限的动画语义 Tag/布尔值；
- 是否通过 `FAnimInstanceProxy` 保存线程快照。

原则是：**帧结构只表达事实，不表达蓝图节点。**

因此不会有：

```text
bNotMovingToConduit
bConduitToEnterMove
StopSelectIndex
CurrentBlueprintStateName
```

蓝图自己用 `bHasMoveInput`、`Gait`、`TurnBackPhase` 与动画时间节点组织拓扑。

## 4. AnimInstance 的目标形态

`UZZZAnimInstance` 最终收敛为项目通用的薄基类（具体名称实施时确定）：

```text
UGGYGOAnimInstanceBase
  ├─ 游戏线程：从 CMC / ASC 捕获 AnimationStateFrame
  ├─ 动画线程：只基于快照计算少量通用派生值
  ├─ 向 AnimBP 暴露只读数据
  └─ 不知道蓝图状态机拓扑
```

计划移除或迁移：

| 当前内容 | 目标 |
| --- | --- |
| `FZZZLocomotionDecisions` 七条过渡函数 | 删除；过渡拓扑回到 AnimBP |
| `FZZZLocomotionEvents::StopValue` | 移到 AnimBP 的状态选择，或由强类型表现枚举表达 |
| 起步 0.5 秒早停窗口 | 使用当前动画状态时间/Time Remaining 表达；不在 C++ 复制时钟 |
| `MovingSubState` | 直接消费 `TurnBackPhase`，删除重复投影 |
| `GaitValue` | 直接消费 `EGGYGOGait`，删除 int32 镜像 |
| 未被 AnimGraph 使用的 `ActualVelocity*` / `AnimCurveVelocity*` | 移出公开契约；需要时进入 Debug View |
| `NativeThreadSafeUpdateAnimation()` 空实现 | 明确承担纯表现求值，或删除虚假的线程安全分层 |

`GaitBlendY` 的去向实施时二选一：

1. AnimBP 线程安全 Update 内插值；适合每个表现层独立调节；
2. C++ 输出通用 `GaitAlpha`；适合所有角色都使用同一语义。

无论选哪一种，都不再用 `FZZZLocomotionEvents` 同时维护步态、Stop、TurnBack 与诊断状态。

## 5. 动画资产与 Linked Anim Layer

建议保留一个通用主图，只做层级组合：

```text
Main AnimBP
  ├─ Locomotion Layer
  ├─ FullBody Action Slot
  ├─ UpperBody Slot
  ├─ Reaction/Additive Layer
  ├─ Aim/Look Layer
  └─ IK/PostProcess
```

不同角色或 Boss 形态通过 Linked Anim Layer 提供具体 Locomotion 实现，而不是复制一套
包含所有通用逻辑的完整 AnimBP。

这不是要求每个小状态拆成一个蓝图。拆分单位应当是**能够整体替换的表现域**，例如：

- 一整套 Locomotion；
- 一整套武器姿态；
- 一整套受击/死亡反应；
- 某个 Boss 形态的全身姿态层。

Idle、Start、Loop、Stop 仍应留在同一个 Locomotion Layer 内，避免重新制造碎片化。

## 6. 强类型 AnimProfile

当前 `FZZZAnimSet` 使用 `TMap<FName, UAnimSequence*>` 与
`TMap<FName, UBlendSpace*>`。它允许任意字符串 Key，拼错后静默返回空资产，
也无法在 Cook 前确认某个角色缺了哪些必需项。

目标是强类型 Profile 或由 Linked Anim Layer 直接持有资产。

若使用 Profile，建议只放稳定语义：

```cpp
UCLASS(BlueprintType)
class UGGYGOAnimProfile : public UPrimaryDataAsset
{
    TSoftObjectPtr<UAnimSequence> Idle;
    TSoftObjectPtr<UAnimSequence> Start;
    TSoftObjectPtr<UBlendSpace> Locomotion;
    TSoftObjectPtr<UAnimSequence> WalkStop;
    TSoftObjectPtr<UAnimSequence> RunStop;
    TSoftObjectPtr<UAnimSequence> TurnBack;

    FGGYGOAnimPresentationTuning PresentationTuning;
};
```

要求：

- 必需资产缺失时 `IsDataValid()` 明确报错；
- 资产是表现配置，不作为服务器权威状态；
- Profile 由 PawnData/FormDefinition 选择，不由 C++ 写死角色名；
- 不把 Damage、Cooldown、移动权限等玩法参数放进 AnimProfile。

如果 Linked Anim Layer 已经能自然持有这些资产，则 Profile 可以只保存共享调参，
不必为了“数据化”再复制一份资产表。实施前先用 Pyrios 和一个 Boss 形态验证哪种更简洁。

## 7. 曲线与权威移动的新边界

### 7.1 普通 Locomotion

普通走跑的真实速度由 CMC / MovementSet 决定，动画适配真实速度：

- PlayRate；
- Stride Warping；
- Distance Matching；
- BlendSpace / Sync Marker。

不再让当前 AnimGraph 输出的 `RootMotion_Speed` 成为走跑速度上限的唯一权威。

### 7.2 动画形状必须决定移动的动作

转身、刹停等确实需要保留动画位移节奏的情况，曲线应离线烘焙成 C++ 可独立采样的
`MotionProfile`，或转为 UE 原生 RootMotion / RootMotionSource 输入。

```text
MotionProfile
  ProfileId
  Duration
  Speed(Time)
  Direction(Time)
  Yaw(Time)

CMC
  ActiveProfileId
  PlaybackTime
  EntryTransform
  Phase
```

CMC 自己推进 `PlaybackTime` 并采样，因此：

- Dedicated Server 不需要 AnimInstance；
- 客户端预测可以保存/恢复同一时间；
- AnimBP 改连线不会改变碰撞体移动；
- Animation 只需要播放同语义动作，不再是 CMC 的数据源。

动作攻击位移仍由 GA 启动原生 RootMotion 或 GAS RootMotion AbilityTask，规则见
[[计划_移动与动作位移#13. 动作位移驱动]]。Locomotion MotionProfile 与 Ability 位移
必须使用明确的 RootMotionSource 优先级，不能靠 Tick 顺序争夺。

## 8. 线程与时序

目标时序：

```text
Game Thread
  CMC / ASC 更新权威状态
  → AnimInstance PreUpdate 捕获只读帧

Worker Thread
  → 基于帧快照计算表现参数
  → AnimGraph 求值

Game Thread
  → Montage Notify 发 GameplayEvent
```

约束：

- 动画线程不访问 Actor、Controller、ASC、CMC UObject；
- 线程安全函数只读快照和动画实例自己的表现记忆；
- 游戏线程不会在并行求值期间修改同一份快照；
- 若需要双缓冲或 `FAnimInstanceProxy`，由实现阶段用 UE5.8 的实际调用顺序验证后决定；
- 不新增全局 Tick 管理器，仍使用引擎已有的 CMC、AnimInstance、GAS 生命周期。

| Idle → Walk → Run → Stop | 状态与脚步连续，无一帧反跳 |
| 起步后立刻松手 | 蓝图选择短停表现，不改变 CMC 权威状态 |
| Run 中反向输入 | 客户端、服务器、模拟代理转身一致 |
| 转身中动画被攻击 Montage 覆盖 | CMC 动作有明确取消/收尾规则，不因曲线消失卡相位 |
| Dedicated Server 无动画求值 | 速度、位移、转身仍可完整重演 |
| 低帧率与网络校正 | MotionProfile 时间可恢复，不出现累计曲线跳变 |
| 切换 Boss Form | 新 AnimLayer/Profile 生效，ASC/Phase 与权威移动不重建 |
| 缺少动画资产 | Data Validation 报明确资产名，不静默返回空 Sequence |
| 修改 AnimBP 拓扑 | 不修改 C++ 也能编译运行，权威移动结果不变 |

---

## 12. 非目标

- 不新建统一的全局逐帧调度器；
- 不让 AnimBP 承担伤害、冷却、移动权限或 Boss Phase；
- 不为了“全部数据化”制造可在 DataAsset 里拼流程的通用状态机；
- 不要求所有角色共享骨骼；
- 不在本轮同时引入 Motion Matching、Motion Warping、Foot IK 等所有高级系统；
- 不以重命名和移动文件代替职责重构。

## 13. 审阅冻结项

以下边界已确认，实施按阶段推进：

- [x] 接受“C++ 发布事实，AnimBP 组织表现拓扑，DataAsset 保存配置”的三层边界；
- [x] 接受删除与蓝图连线一一对应的 C++ Transition 函数；
- [x] 接受 Stop 选择、起步早停窗口和混合拓扑回到 AnimBP；
- [x] 接受 CMC 最终不再读取当前 AnimInstance 曲线；
- [x] 接受普通 locomotion 由 CMC 速度驱动，动画负责适配；
- [x] 接受转身/刹停若需动画节奏，改由独立 MotionProfile/原生 RootMotion 提供；
- [x] 接受 AnimInstance 收敛为薄数据适配层；
- [x] 接受角色差异优先用 Linked Anim Layer/强类型 Profile，而不是复制运行时 C++；
- [x] 接受迁移分阶段进行，旧链路在替换完成前保持可运行，不一次性大爆炸重写。
